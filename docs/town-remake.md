# 마을 원화 제작과 실제 화면 비교

최상위 기준은 사용자가 제공한 [예배당·숲길 화면](../assets/source/style/approved-game-reference.jpg)입니다.
[분위기 가이드](reference-look-guide.md)와 [원화 투영 검사](chapel-regeneration.md)를 함께 따릅니다.
생성 컨셉의 유사성과 실제 게임 화면의 유사성은 별개이며, 투영 합격만으로 분위기까지 합격했다고 선언하지 않습니다.
제1장 환경을 다루며 후속 스테이지를 추가하지 않습니다.

## 같은 패밀리의 입력

실제 생성 문구·첨부 순서·입출력 해시는 [생성 기록](../tools/extract/town_remake_generation.json)에 보존합니다.
`assets/source/remake/town-master-scene.png`는 세 번째 비교 수정 후보입니다. 첫 넓고 밝은 마을 시안은 사용자가 거절했으며,
두 번째 후보에서 원본의 가까운 예배당 구도를 복원하고 세 번째 후보에서 노란 석재·강한 줄눈·꽃 채도를 줄였습니다.
이 후보는 재질 보조 자료이고 사용자 승인으로 간주하지 않습니다. 분리 원화를 생성할 때도 사용자 원본을 실제로 첨부합니다.

| 대상 | 현재 생성 원본 / 파생 자료 | 제작 기준 |
| --- | --- | --- |
| 잔디·포장·흙 | `remake/ground.png`·`grass-v2.png` | 그림자 없는 위에서 본 재료를 실제 지면에 투영 |
| 꽃·고사리·풀 | `remake/flora.png` | 투명한 개별 군락, 실제 줄기 접점 |
| 일반 나무 | `remake/trees-v2.png` | 높은 수관·앞뒤 가지 가림, 4종을 원본 해상도로 패킹 |
| 서비스 건물 4종 | `remake/house-{nw,ne,sw,se}.png` | 따뜻한 중성 회색 석회암·참나무·차분한 슬레이트 |
| 예배당 | `remake/chapel-v2.png` | 지면 접근형 본체, 문 앞 작은 계단, 넓은 난간 마당 제거 |
| 성문·성벽 | `remake/gate-a.png`, `gate-b-v2.png`, `wall-from-gate.png` | 성문의 실제 날개벽 픽셀에서 반복 벽 추출 |
| 다리 | `remake/bridge.png` | 실제 상판·앞뒤 난간·양 끝·기둥 실측, 기존 건너기 모델 보존 |
| 분수·워프 | `remake/fountain.png`, `portal-v2.png` | 새 돌 본체의 실제 물·포털 내부에서만 애니메이션 |
| 상자·부서진 상자·바위 | `remake/small-props.png`, `props-cells/` | 생성 시트의 정확한 셀을 분리하고 구조물 양면 실측 |
| 강물·물가 돌 | `remake/river-materials.png` | 새 중성 재료, 기존 흐름·물가 경계·일시정지 보존 |

표의 경로는 `assets/source/` 아래입니다. 소스 PNG는 `.gdignore`로 웹 PCK에서 제외합니다.
탈락본은 비교 근거와 다음 생성의 입력을 보존하기 위한 자료이며 런타임 기준으로 사용하지 않습니다.
캐릭터·NPC·몬스터·기존 필드 랜드마크·동굴·HUD 원화는 이 환경 패밀리 재제작 범위와 구별합니다.

## 실제 그림 전체의 투영

수평 조적·처마·띠장·창틀·난간·기단은 양쪽 면의 상·중·하단과 마주보는 모서리에서 다시 측정합니다.
실제 원본의 선분 좌표와 기대 축을 기록하며, 충돌 사각형이나 발치만으로 인증하지 않습니다.
`art_projection`은 런타임과 동일한 `native_point`·메시·반사·실제 벽 변환을 사용합니다.
축 오차와 같은 축의 평행선 편차는 각각 2.5° 이내, 각 선 내부 11점의 직진성 편차는 0.75월드 픽셀 미만이어야 합니다.
메시의 모든 삼각형은 방향을 보존해야 하며, 원본과 실제 렌더 아틀라스 해시가 일치해야 합니다.

나무·잎·자연석·수면의 불규칙한 외곽에는 가짜 직선 각도를 붙이지 않습니다.
나무는 수관 윗면·앞뒤 가림·짧게 보이는 줄기·뿌리 깊이로 높은 카메라를 검수하고,
지면 재료는 실제 `Iso.ground_transform()`으로 ±30° 축을 만듭니다. 지붕 경사는 지면 축과 구별합니다.

## 화면 비교에서 발견한 차이와 수정

첫 실제 세로 화면은 석재·슬레이트가 가까워졌지만 분위기 검수에서 탈락했습니다.
캐릭터가 원본보다 크게 보였고, 넓은 난간 마당·하단의 성문·빈 잔디·직선 포장 경계가 먼저 읽혔습니다.
따라서 예배당을 작은 문앞 계단만 남기도록 재생성하고, 카메라 기준을 1.60으로 맞추며,
실제 건물 배치·전경 나무·지면 꽃군락을 함께 조정합니다. 실제 보행에서 상점과 영웅을 덮던 옛 고정 나무 3그루는 제거하고, 문과 길을 비운 건물 뒤·정원 가장자리 군락을 사용합니다. 줄기만 문을 비우는 것으로 끝내지 않고 실제 수관의 그리기 범위와 깊이 순서로 이웃 건물의 네 서비스 주민까지 가리지 않는지 검사합니다. 지면형 문턱에서 기존 도로로 실제 돌길을 연결하고 동일 생성형 포장 재질·UV를 사용합니다. 길은 지면 기하로 만들며 별도 충돌벽을 추가하지 않고 지도·식생 회피에도 같은 경로를 공유합니다. 캡처에서만 물체를 숨겨 통과시키지 않습니다.
화면 크기를 바꿔도 투영 각도는 유지하고 HUD는 독립된 화면 좌표를 사용합니다.

평지 그늘은 최대 6개 실제 나무의 알파와 접점·변환을 공통 광원 방향으로 투영합니다.
문 뒤 배경 수관은 전경 수관과 구별되는 약한 차가운 그늘색을 적용하며 지면이나 화면 전체에 색 필터를 씌우지 않습니다. 이는 제한된 2D 근사이며 레퍼런스의 완전한 수관 조명이나 나무의 3D 부피를 복원한 결과가 아닙니다.
그림자를 잔디·포장 타일에 반복 무늬로 굽지 않습니다.

## 재현과 검수

모든 패커가 끝난 뒤에만 엔진 임포트를 시작합니다. 측정 자료가 바뀌면 중앙 카탈로그를 직렬로 병합합니다.

```sh
python3 tools/prepare_town_remake.py /path/to/sjrpg
tools/check.sh --export
tools/serve.sh
node tools/screenshot.mjs --scene chapel_reference --class mage --device phone --viewport 714x1280 --dpr 1 --zoom 1 --out /tmp/town-chapel.png
node tools/compare_reference.mjs --actual /tmp/town-chapel.png --out /tmp/town-comparison.png --label '실제 수정본 검수'
node tools/screenshot.mjs --scene town --class mage --device phone-landscape --out /tmp/town-landscape.png
```

비교할 때는 원본과 실제 게임을 나란히 보여줍니다. `compare_reference.mjs`는 원본 비율을 유지해 배치만 하며
원화나 게임 캡처를 다시 칠하거나 생성 컨셉을 실제 플레이 화면처럼 제시하지 않습니다.
기본 세로·가로, 네 성문과 네 코너, 다리 건너기와 앞 난간, 주민 접근·문턱 보행, 분수/워프 애니메이션,
절약 화질과 실제 이동·시전을 확인합니다. 실제로 배우를 가리는 전경과 길 경계를 반드시 포함합니다.
화면 비교 판정과 남은 차이는 투영 수치·자동 검사 결과와 구별해 사용자에게 알립니다.

`chapel_reference`는 문 옆의 실제 보행 가능한 지점을 선택하는 비교 뷰입니다. 원화·나무·성문을 숨기지 않습니다. `chapel` 뷰는 별도로 실제 계단 윗부분을 확인합니다.
