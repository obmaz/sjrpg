# 자연의 수호자 · 아트 기준

전체 화면의 거리·빛·식생과 작은 완성 장면부터 만드는 순서는 [레퍼런스 분위기 제작 가이드](reference-look-guide.md)를 따릅니다. 현재 배포 화면을 최종 분위기 달성의 증거로 삼지 않습니다.

## 기준의 우선순위

1. 사용자가 최종 디자인으로 지정한 [게임 화면 원본](../assets/source/style/approved-game-reference.jpg)이 분위기와 화면 구성의 최상위 기준입니다. 원본 파일을 변형하지 않고 보관합니다.
2. 아래 투영·재질·크기 규격과 [UI 기준](ui-reference.md)을 함께 따릅니다. 그림의 분위기가 좋아도 투영이 틀리면 게임용 원화로 채택하지 않습니다.
3. 같은 종류의 자산은 이미 검수된 **동일 패밀리 원화**를 함께 참조합니다. 성문과 성벽은 [한 세트의 디자인](gate-design.md)을 사용합니다. 새 생성본이 스스로 새로운 기준이 되지 않습니다.
4. 생성 프롬프트·참조 파일·접점·실측 선분·원본 및 런타임 해시를 해당 제작 문서와 측정 파일에 보존합니다. 변경한 기준은 이 문서에서 명시적으로 갱신합니다.

사용자 기준 원본은 첨부 `11165.jpg`이며 SHA-256은 `c81286d93319f3aa34c2e60ff16ad7347585be4e5a9d0e7a03866451dd4bf40a`입니다. 새 생성본으로 이 파일을 덮어쓰지 않습니다.

문서만 반복하거나 매번 새 그림을 기준으로 삼으면 스타일이 조금씩 변합니다. **사용자 원본 + 고정 제작 규격 + 같은 패밀리 원화**를 매번 함께 사용합니다.
통합 생성형 컨셉은 재료와 형태를 맞추는 보조 기준이며, 사용자 원본이나 실제 게임 투영 검사를 대체하지 않습니다.

## 투영과 카메라

- 정통 아이소메트릭의 직교 투영입니다. 원근 소실점, 멀어질수록 작아지는 평행선, 광각·어안·기울어진 수직선을 사용하지 않습니다.
- 지면 직선은 화면에서 **±30°**, 수직 직선은 **90°**입니다. 바닥의 정사각형은 60°/120° 마름모가 됩니다. 흔한 2:1 디메트릭(26.565°) 타일을 섞지 않습니다.
- 카메라 방위는 45°, 고도는 약 35.264°입니다. 생성기에 단순히 ‘isometric’이라고만 쓰지 않습니다.
- `Iso.project()`의 두 지면 방향은 화면 좌표에서 `(cos30°, sin30°)`와 `(-cos30°, sin30°)`입니다. 위로 향하는 수직과 함께 세 기준 축이 각각 120°를 이룹니다.
- 같은 축의 상·중·하 모서리와 반대쪽 모서리가 평행해야 합니다. 지붕의 경사·계단을 오르는 방향은 지면 축과 구분합니다.
- 모든 직선 구조물은 실제 원화 선분을 실측합니다. 렌더 후 각 축 오차와 같은 축 사이 최대 편차 모두 2.5° 이내여야 합니다. 발치 사각형이나 충돌 모델만 맞춘 것은 원화 검증이 아닙니다.
- 나무·꽃·자연석은 가짜 직선 각도로 인증하지 않습니다. 수관 윗면, 뒤쪽의 가림, 줄기·뿌리 접점, 바닥에 놓인 잎의 깊이를 시각 검수합니다.

자세한 실측·보정·해시 절차는 [원화 투영과 재생성](chapel-regeneration.md)을 따릅니다.

## 분위기와 재료

**차분하고 현실적인 숲 판타지.** 오래 사용된 재료의 세부는 보이되 화려한 장식이나 낡은 저해상도 게임 표현으로 만들지 않습니다.

| 요소 | 고정 방향 | 피할 표현 |
| --- | --- | --- |
| 석재 | 중성에 가까운 따뜻한 회색 석회암, 작은 거친 입자, 얕고 불규칙한 풍화, 읽히는 줄눈 | 방향마다 노란 대형 블록과 회색 작은 돌을 혼합, 플라스틱 같은 매끈한 면 |
| 성문·성벽 | 하나의 석재·줄눈 크기·받침띠·흉벽 캡·두께. 두 방향 원화와 모서리까지 같은 구조 | 성문만 다른 건축 양식, 서로 다른 띠장·벽돌 높이·흉벽 비례 |
| 예배당·집 | 절제된 석재 몰딩, 실제 깊이의 창틀·문틀, 청회색 슬레이트와 자연스러운 목재 | 굵은 검은 외곽선, 단순 플랫 면, 과장된 금장·거대한 보석 |
| 목재·금속 | 어두운 참나무 계열 결, 자연스러운 이음, 무광 철·절제된 청동 | 밝은 주황색 플라스틱 목재, 거울 금속, 불필요한 금빛 |
| 지면 | 저채도 올리브·이끼 잔디, 회색 포장석, 자연 흙. 타일 이음이 튀지 않는 세부 밀도 | 노란 볏짚 잔디, 균일한 녹색 단색판, 반복 검은 그림자·고정 햇빛 얼룩 |
| 식생 | 넓은 잎·가느다란 잎의 구분, 크림색 흰꽃·절제된 따뜻한 꽃, 자연스러운 비대칭 | 형광 초록, 완벽한 원형 수관, 정면 나무, 알파 가장자리의 색 테두리 |
| 배우 | 실제 HUD 얼굴과 같은 인물. 가죽·금속의 전사, 남색 긴 외투의 남성 마법사 | 화면마다 성별·머리·의상·비례가 바뀌는 캐릭터 |
| 마법·UI | 청백색 핵·가는 궤적·작은 따뜻한 섬광. 얇은 청동/은색 프레임과 크림색 글자 | 시야를 가리는 상시 발광, 큰 단색 원, 밝은 노란 버튼 |

월드 배치는 영웅 원화 높이 84와 기존 모델의 실제 점유 폭·높이를 기준으로 비교합니다. 포장석 한 변은 대략 영웅 높이의 1/3입니다. 자산별 이미지 크기를 똑같이 맞추는 것으로 실제 크기를 정하지 않습니다.

## 조명과 분리

- 게임용 단일 오브젝트의 재질 기본층은 균일하고 부드러운 중성 확산광으로 제작합니다. 면의 입체감·재질 홈까지 없애는 무음영 표현은 피하고, 최종 장면은 가이드의 따뜻한 주광·차가운 숲 그늘 관계를 별도로 맞춥니다. 다른 방향을 생성하면서 빛 방향·색온도를 새로 바꾸지 않습니다.
- 재료의 홈·틈·겹침에 생기는 자체 음영은 유지합니다. 실제 광원과 오브젝트를 계산할 수 있을 때까지 바닥에 붙은 외부 투영 그림자는 넣지 않습니다.
- 컨셉/타이틀의 숲 햇빛은 분위기 참조입니다. 그 햇빛 얼룩이나 다른 물체의 그림자를 타일·단일 오브젝트에 복사하지 않습니다.
- 지면 타일, 건물/나무, 그림자, 물/워프 애니메이션, 캐릭터, 이펙트, UI는 서로 구별합니다. UI·글자·휴대전화 탐색 막대·로고를 월드 스프라이트에 굽지 않습니다.
- 오브젝트는 투명 PNG 원본을 보존하고 밝고 어두운 단색 배경에서 알파·붙은 바닥판·경계 색 번짐을 확인합니다.

## 제작 순서와 완료 기준

1. [공통 프롬프트](art-prompts.md)를 읽고 사용자 기준 화면과 같은 패밀리 원화를 참조 이미지로 첨부합니다. 목표 크기·카메라·사용 방향·필요한 구조를 먼저 고정합니다.
2. 새 패밀리는 통합 컨셉 한 장으로 재료·비례를 먼저 맞춥니다. 성문·두 방향 성벽·코너처럼 연결되는 물건은 한 세트로 설계합니다.
3. 같은 컨셉으로 게임용 원화를 생성합니다. 연결 부품은 가능한 경우 그 원화의 실제 부품을 추출·반복해 재사용하고, 구조가 필요한 곳만 같은 패밀리 참조로 생성합니다. 방향마다 독립적으로 재해석하지 않습니다.
4. 원본을 보존하고 기존 패킹 도구로 배포 자산을 만듭니다. 접점·충돌·깊이·실측 선분·출처와 해시를 갱신합니다. 프롬프트만 같다는 이유로 이전 측정점을 그대로 쓰지 않습니다.
5. 직선 구조물의 투영 검사와 실제 이동·가림 검사를 통과시킵니다. 장식이 문·계단·상자·주민의 동선을 막지 않아야 합니다.
6. 브라우저의 가로·세로에서 기존 에셋 **옆에** 배치해 돌 크기·색·표면·디테일 밀도·높이를 비교합니다. 성문 4개와 성벽 코너 4개, 상·중·하단을 확인합니다. 해시·헤드리스 검사 통과만으로 시각 검수를 대신하지 않습니다.

동일 프롬프트나 시드가 완전한 동일성을 보장하지는 않습니다. 배포에 사용한 원본과 측정·패킹 결과를 고정하고 재사용하는 것이 재생성보다 안정적입니다.
