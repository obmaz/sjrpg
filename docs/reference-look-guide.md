# 레퍼런스 분위기 제작 가이드

## 목표와 기준 이미지

목표는 **숲속 예배당 곁에서 모험하는 인물이 크게 읽히는, 깊이 있고 차분한 사실적 2.5D 판타지**입니다.
첨부된 [11165.jpg 원본](../assets/source/style/approved-game-reference.jpg)을 생성과 게임 화면 검수에 항상 사용합니다.
원본은 714×1280이며 SHA-256은 `c81286d93319f3aa34c2e60ff16ad7347585be4e5a9d0e7a03866451dd4bf40a`입니다.
이번 첨부와 보관본은 같은 파일입니다. 새 생성본으로 이 기준을 덮어쓰지 않습니다.

이 문서는 앞으로의 제작·검수 목표입니다. 현재 배포 화면이 이 분위기에 도달했다는 완료 기록이 아닙니다.
정확한 투영은 [아트 기준](art-direction.md), 제작 프롬프트는 [공통 프롬프트](art-prompts.md),
HUD의 후속 크기·배치 요청은 [UI 기준](ui-reference.md)을 함께 따릅니다.

원본의 미감과 **정통 아이소메트릭 120°**를 모두 만족해야 합니다.
레퍼런스 이미지 자체를 각도가 검증된 설계도로 간주하지 않습니다. 이미지의 선과 고정 투영이 충돌하면 분위기를 유지하면서 구조를 다시 설계합니다.

## 레퍼런스와 비교할 항목

| 레퍼런스에서 중요한 것 | 실제 화면에서 확인할 위험 | 제작·적용 방향 |
| --- | --- | --- |
| 가까운 인물과 한 채의 예배당이 화면을 채움 | 넓은 지도에 작은 배우·여러 시설이 함께 보여 축소 모형처럼 느껴짐 | 먼저 카메라와 배우의 화면 점유율을 맞춤 |
| 나무 그늘 속 밝은 석재·남색 옷·작은 마법광이 구별됨 | 지면과 물체의 밝기가 비슷해 깊이와 시선 집중이 약함 | 화면 전체의 명암 단계와 일관된 조명을 설계 |
| 세밀한 돌·슬레이트·천과 같은 수준의 배우 표현 | 원화마다 표면 세부·배우 표현의 밀도가 다름 | 건물·지면·배우를 한 장면 안에서 비교하며 같은 표현 수준으로 제작 |
| 흙·풀·꽃이 돌길과 건물 발치에 자연스럽게 이어짐 | 넓은 잔디와 반복 포장, 분리된 장식이 먼저 보임 | 길 가장자리·발치·전경의 식생 군집으로 재료를 연결 |
| 평상시 조용하고 시전 순간 작은 빛이 선명함 | 과한 발광은 몸과 재질을 가리고, 큰 화면 흔들림만으로 분위기는 바뀌지 않음 | 인물 실루엣이 남는 짧은 효과와 명암 대비를 사용 |

여기서의 Game Feel에는 타격 반응뿐 아니라 화면 거리·재질·조명·움직임의 일관성이 포함됩니다.
원화의 형태·재질·자체 음영은 **생성할 때부터** 맞춰야 합니다. 완성된 게임의 분위기는 카메라·배치·조명·애니메이션까지 함께 맞춰야 나옵니다.
기존 그림을 모두 어둡게 하거나 전체 화면에 초록 필터를 씌우는 것으로 완료하지 않습니다.

## 변경하지 않는 투영 규격

| 항목 | 규격 |
| --- | --- |
| 투영 | 직교 투영, 정통 아이소메트릭 2.5D |
| 카메라 | 방위 45°, 고도 약 35.264° |
| 지면의 두 직선 방향 | 화면 수평선에 대해 +30° / -30° |
| 수직 구조 | 화면에서 90°, 높이에 따라 기울지 않음 |
| 세 기준 축 | 오른쪽 아래 `(√3/2, 1/2)`, 왼쪽 아래 `(-√3/2, 1/2)`, 위 `(0, -1)` 사이 각각 120° |
| 금지 | 원근 소실점, 거리별 축소, 광각, 기울어진 수직선, 2:1 디메트릭의 26.565° 축 혼합 |
| 실제 원화 허용 오차 | 렌더 후 축 오차 ≤2.5°, 같은 축 선들 사이 최대 편차 ≤2.5° |

120°는 투영된 세 축 사이의 관계입니다. 카메라를 120° 기울이라는 지시가 아닙니다.

검수는 실제 처마·띠장·기단·난간의 **상·중·하단과 양쪽 면·반대 모서리**에 합니다.
발치의 충돌 사각형만 맞추거나 바닥선 한 개를 재서 통과시키지 않습니다.
지붕 경사, 계단이 올라가는 방향, 임의 방향을 보는 배우는 지면 축과 구분합니다.
나무는 수관 윗면·가지의 앞뒤 가림·줄기와 뿌리 접점으로 높은 카메라를 검수합니다. 자연 실루엣에 직선 각도를 억지로 붙이지 않습니다.

각도는 생성기의 보장 항목이 아닙니다. [실측·보정 절차](chapel-regeneration.md)에 따라 선 내부까지 확인하고,
큰 원근 왜곡이나 형태 손상이 있으면 재생성합니다. 가로/세로 화면 모두 같은 투영을 사용하며 카메라 확대는 축 각도를 바꾸지 않습니다.

## 화면 거리와 비례

다음 값은 원본을 눈으로 비교하기 위한 **근사 제작 목표**이며 자동 실측 완료값이나 현재 런타임 설정이 아닙니다.
OS 탐색 막대·브라우저 크롬을 제외한 게임 화면으로 비교합니다. 긴 폰은 화면 높이보다 짧은 변을 기준으로 배우 크기를 비교합니다.

| 비교 항목 | 시작 목표 |
| --- | --- |
| 실제 배우 실루엣 높이 | 화면 짧은 변의 약 22–26%. 714×1280 원본에서는 약 170–180px로 읽힘 |
| 세로 화면의 발치 | 가로 중앙 근처, 화면 높이 약 58–64% 부근. 얼굴과 공격 전방을 비움 |
| 가까운 주요 건물 | 세로 화면 폭의 약 60–80%를 차지하는 한 채가 주 배경. 건물 일부가 화면 밖으로 이어져도 됨 |
| 포장석의 읽히는 큰 한 변 | 배우 높이의 약 1/4–1/3. 줄눈이 검은 격자처럼 먼저 보이지 않음 |
| 전경·중경·후경 | 가장자리의 잎/풀, 배우와 길, 건물/나무의 세 층이 구별됨 |

현재 `Player`의 `body_height=84`, 짧은 변720 기준 기본 월드 카메라 배율1.60와 발치 약60% 구도는 구현값입니다.
이 값만으로 위 점유율이나 분위기 목표에 도달했다고 판정하지 않습니다. 실제 원화의 투명 여백을 제외한 실루엣과
문·계단의 상대 크기, 전투 시야를 같은 짧은 변에서 비교합니다. `zoom` 디버그 값은 기본1.60에 곱하는 배수이므로
과거의 `--zoom 2.0`을 현재 기본값처럼 사용하지 않습니다. HUD 크기는 월드 카메라 확대와 독립입니다.

배우·문·계단·나무의 월드 비례는 함께 유지합니다. 배우 그림만 두 배 키우거나 건물을 화면에 맞춰 비균일하게 늘리지 않습니다.
가로 화면에서도 배우의 체급을 유지하고 옆 시야를 늘립니다. 이동·조준·공격 예고·접근 대상이 HUD에 가려지지 않는지 함께 확인합니다.
HUD는 월드 확대와 독립적으로 유지하며 이후 사용자가 요청한 크기 조정을 우선합니다.

## 재질·색·식생

- **석재**: 따뜻한 회색 석회암, 얕은 풍화, 미세한 입자, 실제 깊이의 줄눈과 창틀. 모든 면을 같은 평면색으로 채우지 않습니다.
- **지붕**: 청회색 슬레이트의 얇은 겹침과 절제된 색 변화. 과장된 두께·굵은 검정 외곽선을 피합니다.
- **배우**: 남색 마법사 외투의 주름·바느질·가죽 끈과 얼굴이 작은 화면에서도 구별되어야 합니다. 건물은 사실적인데 배우만 단순한 저폴리곤처럼 보이는 조합을 채택하지 않습니다.
- **지면**: 이끼색·올리브색의 잔디, 회색 포장석, 낮은 흙 노출. 넓고 균일한 초록 매트와 반복 타일 경계가 주인공이 되지 않게 합니다.
- **식생**: 건물 발치의 낮은 풀과 흰꽃, 길 가장자리의 작은 따뜻한 꽃, 화면 가장자리의 큰 잎을 군집으로 배치합니다. 긴 풀과 짧은 풀, 빈 곳과 밀집한 곳을 구별합니다.
- **깊이**: 멀리 있는 숲은 낮은 대비로 물러나고, 가까운 인물·돌길의 재질은 읽혀야 합니다. 화면 전체를 똑같이 선명하고 밝게 하지 않습니다.
- **동선**: 문·계단·다리·상자·주민·게이트 앞은 비웁니다. 전경 식생은 적의 예고·전리품·플레이어를 지속해서 가리지 않습니다.

새 자산마다 임의의 색 보정을 하지 않습니다. 같은 석재 조각·지붕·문·배우를 함께 놓고 표면 입자와 줄눈 크기까지 비교합니다.
성문·양 방향 성벽·코너는 하나의 패밀리로 설계하고 실제 같은 부품을 재사용합니다.

## 조명과 그림자의 제작 책임

레퍼런스의 핵심은 **어두운 숲의 깊이, 따뜻하게 빛나는 돌, 차가운 옷과 마법광**의 관계입니다.
밝은 포장면·중간 밝기의 식생·깊은 수관 그늘을 구분하되, 어두운 곳의 배우와 적도 읽혀야 합니다.
주광은 화면 위·왼쪽에서 들어오는 따뜻한 낮빛을 출발점으로 하고, 그늘에는 낮은 채도의 차가운 환경광을 둡니다.
이는 앞으로 맞출 장면 조명 방향이며 현재 모든 원화가 이미 그 조명에 맞는다는 뜻은 아닙니다.

| 제작물 | 포함할 것 | 별도 처리할 것 |
| --- | --- | --- |
| 장면 컨셉 | 최종 명암, 햇빛·수관 그늘, 전체 색 관계, 인물과 건물 비례 | 이동·충돌·게임용 알파·각도 검증 |
| 분리 오브젝트 | 재질, 입체를 읽는 부드러운 면 차이, 홈·겹침의 자체 음영 | 바닥에 떨어지는 그림자, 주변 나무의 그늘, 햇빛 얼룩 |
| 반복 바닥 타일 | 균일한 재료와 작은 표면 변화 | 물체와 관계없는 검은 그림자·스포트라이트 |
| 런타임 장면 | 위치·높이·지형에 연결된 조명과 그림자, 가까운 물체의 접지감 | 화면 전체를 같은 색으로 덮어 깊이를 흉내 내는 처리 |

기존 프롬프트의 ‘부드러운 중성 확산광’은 자산 결합을 위한 기본층입니다. 홈과 면의 입체감까지 없애는 무음영 그림을 뜻하지 않습니다.
장면의 명암은 재질 기본층 위에 일관되게 적용합니다. 서로 다른 자산에 강한 다른 방향의 빛을 구워 넣지 않습니다.
방향을 반사해 재사용하는 부품은 조명 방향까지 뒤집히지 않는지 확인합니다.

참조의 나무 그림자를 그대로 잔디 타일에 복사하지 않습니다. 그림자는 실제 물체 위치·지면 높이·광원과 맞아야 합니다.
2D 라이트 하나를 추가하는 것만으로 쿼터뷰의 높이·계단·다리 그림자가 해결되었다고 간주하지 않습니다.
런타임 조명/가림 정보 또는 지면 좌표와 물체 높이에 연결된 그림자 레이어를 작은 장면에서 먼저 검증합니다.
높낮이까지 맞출 수 없다면 사용자의 기존 요청대로 타일의 외부 그림자는 제거한 상태를 유지합니다.
이 경우 그림자까지 포함한 레퍼런스 분위기 완성을 선언하지 않습니다.

현재 `CanopyShade`는 마을 평지의 실제 나무 알파·발치·변환을 공유 광원 방향으로 투영합니다.
나무와 무관한 타일 무늬는 아니지만 2D 실루엣을 사용하는 근사이며, 높은 지형·다리·계단·건물의 정확한
3D 그림자를 계산하지는 않습니다. 이 적용 범위와 한계를 실제 장면 비교에서 함께 기록합니다.

## 제작 순서: 작은 완성 장면부터

반복 구조물과 여러 방향의 배우는 **같은 3D 모델·재질·고정 직교 카메라에서 렌더한 원화**를 쓰면
각도·광원·비례·프레임 일관성을 더 안정적으로 유지할 수 있습니다. 생성형 이미지는 컨셉과 표면 제작에 활용하고,
Godot에서는 렌더 결과를 기존 2D 스프라이트로 사용할 수 있습니다.
순수 이미지 생성으로 제작할 때도 아래 순서와 실제 픽셀 검수는 동일하며, 생성 결과의 원근 오류를 프롬프트만으로 보증하지 않습니다.

1. 사용자 원본과 이 문서를 읽고, **예배당 한 채 + 짧은 돌길 + 나무 군집 + 배우 한 명 + 작은 마법광**의 목표 장면을 정합니다.
2. 동일한 120° 카메라로 전체 장면 컨셉을 먼저 만듭니다. 화면 거리·재료·빛·식생의 층을 한 장 안에서 맞춥니다.
3. 컨셉에서 사용할 재질·부품을 고정하고, 사용자 원본과 해당 컨셉을 실제 이미지 참조로 넣어 분리 원화를 만듭니다. 새 컨셉은 제작 보조 자료이며 자동 사용자 승인이 아닙니다.
4. 원본·프롬프트·참조 파일·출처·발치·실측 선분·해시를 기록합니다. 새 그림마다 측정하며 이전 측정값을 복사해 인증하지 않습니다.
5. Godot의 작은 실제 플레이 구간에 배치합니다. 같은 카메라에서 배우, 문, 길, 풀의 크기와 가림·이동을 함께 맞춥니다.
6. 정지 화면의 분위기와 5–10초의 실제 이동/시전/명중을 검수합니다. 원화의 전체 해상도보다 최종 모바일 표시 크기에서 판정합니다.
7. 투영과 분위기가 모두 맞은 세트를 숲 1장에 확장합니다. 양 방향·코너·기존 원화와의 접점도 같이 검수합니다.

같은 프롬프트나 시드만 반복해서는 일관성이 보장되지 않습니다.
**사용자 원본 + 고정 카메라·재료 규격 + 같은 패밀리 원본을 실제로 첨부 + 채택한 결과의 재사용**을 기본으로 합니다.
현재 배포 화면을 새 스타일 기준으로 삼아 편차를 누적하지 않습니다.

마을 패밀리의 현재 제작 참조는 `assets/source/remake/town-master-scene.png`의 비교 수정 후보3입니다.
초기 컨셉은 사용자 비교 후 거절되었으며 후보3도 사용자 승인으로 간주하지 않습니다.
각 생성에 실제 첨부한 파일·프롬프트·해시는 `tools/extract/town_remake_generation.json`에 보존합니다.
분리 원본·현재 측정·직렬 통합 절차와 미작성 비교 판정은 [마을 재제작 가이드](town-remake.md)를 따릅니다.

## 움직임·이펙트가 분위기를 유지하는 조건

- 배우·몬스터의 걷기·시전·공격은 모든 방향에서 같은 외형·재료·발치와 조명을 유지합니다. 프레임마다 크기·얼굴·옷이 바뀌거나 발이 미끄러지면 재제작합니다.
- 시전은 손끝의 작은 청백색 핵과 분리된 입자부터 시작합니다. 발사·접촉·잔광을 구별하고 효과 안에서도 손·몸·옷이 읽혀야 합니다.
- 평상시 화면은 조용히 유지하고 접촉 순간에만 빛·짧은 동작 정지·반동·소리를 집중합니다. 상시 과한 블룸·흰 덩어리·큰 흔들림으로 재질과 실루엣을 덮지 않습니다.
- 피해 판정·타격음·접촉 효과의 시점을 맞춥니다. 현재 액션 템포 1.5배와 스킬 쿨타임 표시를 시각 작업 중 임의로 바꾸지 않습니다.
- 장식 64개 한도, 일시정지, 동작 줄이기, UI 입력과 전투 시야를 유지합니다. 정지 이미지의 분위기만으로 타격감이 검증됐다고 보고하지 않습니다.

## 두 가지 완료 판정

| 판정 | 필수 확인 |
| --- | --- |
| 투영·동작 | 실제 원화 상·중·하단/반대 면 ≤2.5°, 평행·선 내부·메시 뒤집힘, 발치·충돌·깊이·가림, 길·문·계단 접근 |
| 레퍼런스 분위기 | 가까운 화면 거리, 배우 체급, 재질 통일, 빛과 그늘의 깊이, 자연스러운 식생 연결, 효과 속 배우 가독성 |

둘 중 하나만 통과하면 완료하지 않습니다. `art_projection` 통과나 해시 일치는 분위기 통과를 뜻하지 않습니다.
같은 화면 비율로 게임 영역을 비교하고 원본을 가로/세로로 늘리지 않습니다. 긴 폰·가로 화면은 짧은 변 기준 비례와 실제 조작 시야를 추가로 봅니다.
나란히 놓은 원본/실제 화면과 이동·공격 결과를 해당 자산 제작 문서에 남깁니다.

현재 기본 카메라로 비교하는 개발용 예시는 다음과 같습니다. 확대 배수를 생략해 기준 화면을 먼저 남깁니다.

```sh
tools/check.sh --export
tools/serve.sh
node tools/screenshot.mjs --scene chapel --class mage --device phone --out /tmp/look-chapel-phone.png
node tools/screenshot.mjs --scene chapel --class mage --device phone-landscape --out /tmp/look-chapel-landscape.png
node tools/screenshot.mjs --scene juice --class mage --device phone --out /tmp/look-combat-phone.png
```
