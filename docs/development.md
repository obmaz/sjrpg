# 개발 구조

저장소 루트는 두 Godot 프로젝트와 버전 선택 웹 화면을 묶습니다. Godot 에디터의 프로젝트 루트는 각각 `sjrpg_2d/`, `sjrpg_3d/`이며 리소스 경로 `res://`도 각 프로젝트 안에서 해석합니다. `.godot-version`은 모두4.7.2를 사용합니다. 기존2D판을 수정해3D 기능을 만드는 대신3D판에서 작업합니다.

## 3D의 책임

`NativeAdventure`가3D판 모험의 진입점입니다. 기존 `Game`·`Player`·`Enemy` 규칙은 UI·진행·AI와의 호환 어댑터로 유지하며, 실제 몸체는 `SpatialWorld3D`의 `CharacterBody3D`입니다. 화면 좌표를 지면 X/Z와 실제 Y높이로 변환하고, 정적 건축·지형·성문·마을 안전 경계·동굴에서3D 충돌을 검사합니다. 2D 좌표 어댑터가 기존 미니맵과 의뢰 데이터를 계속 사용할 수 있게 합니다.

`SpatialCombat3D`는3D 몸체·높이·벽을 기준으로 공격을 제한합니다. 투사체는 발사 높이를 유지하며 실제 이동 구간을 검사합니다. 기존 스킬 수치·재사용·명중 반응·저장 데이터는 재사용합니다.

`NativeCombatFx3D`는 원래 Canvas가 숨겨진3D판에서 일반 화염탄 등 비투척 투사체의 표시를 담당합니다. 실제 `Effect.native_position()`과 소스 수명으로 기존 생성형 원소 이미지를 배치하며 게임 투사체를 삭제하거나 시계를 추가하지 않습니다. `NativeEncounterProps3D`는 비석과 상자의 개별 원화 소유권을 교체하고 실제 충전·피격·소모 상태를 읽습니다. 레벨업 효과도 현재 월드에 속한 소스만 표시해 동굴 방문 중 정지된 숲의 축하가 따라오지 않게 합니다.

`Ortho3DPreview`는 기존 이름을 유지한 공간 표시기입니다. 3D판에서는 마을뿐 아니라 숲과 동굴에서도 켜져 있습니다. 건물·성벽·성문·나무·주민·전사·마법사·몬스터는 입체 모델을 사용합니다. 지면·물·효과·알파 식생의 평면 표시는 실제3D 공간과 함께 유지합니다. 카메라는 직교45°/35.264°를 유지합니다. 기존2D판의3D 비교 표시기·자산·전환 경로는 제거했으며,2D판은 동결합니다.

## 웹과 저장

`tools/export_web.sh`가 두 프로젝트를 따로 빌드하고 `build/web/2d/`, `build/web/3d/`로 합칩니다. 루트 `index.html`은 엔진을 불러오지 않는 버전 선택 화면입니다. 각 게임의 HTML·해시 PCK·WASM·설치 manifest는 자기 경로에 놓이며 상대 URL을 사용합니다. 이전 `2d.html`·`3d.html`은 쿼리와 해시를 유지해 새 경로로 이동합니다.

3D 프로젝트는 네이티브에서 `config/custom_user_dir_name="sjrpg_3d"`를 사용합니다. 웹에서는 `/userfs/sjrpg_3d`만 별도 IDBFS 데이터베이스로 마운트하고 실제 저장·설정도 그 경로에 씁니다. 2D와 전체 `/userfs` 스냅샷을 공유하지 않습니다. 버전 이동은 엔진의 정상 종료·파일시스템 동기화가 끝난 `onExit`에서 실행합니다. 2D의 기존 사용자 디렉터리를 바꾸거나 저장을 자동 변환하지 않습니다. 설정의 버전 선택 화면 복귀는 현재 저장이 성공해야 페이지를 떠납니다. 실행 중 표시 방식 전환이나 다른 버전으로 바로 가는 버튼은 제공하지 않습니다.

## 환경 준비

`tools/setup_env.sh`가 새 클론·클라우드 환경 준비의 단일 출처입니다. `.godot-version`의 Godot를 릴리스의 SHA-512로 검증해 `~/.godot-tools/godot-<버전>`에 설치하고 두 프로젝트의 `.godot` 임포트 캐시를 만듭니다(3D는 `sjrpg_3d/tools/import_project.sh`의 텍스처 정책 경계를 그대로 사용). 설치 위치가 각 프로젝트의 `tools/godot.sh`가 찾는 곳과 같아서, CI가 쓰는 `tools/setup_godot.sh`로 설치한 환경과 서로 호환되고 이미 있으면 다운로드를 건너뜁니다.

웹 빌드(`tools/check.sh --export`)에는 `--templates web`(1.3 GB), 포털·웹 셸 검사에는 `--npm`, APK용 템플릿에는 `--templates android`(필요한 항목만 Range로 수신하고, 실패하면 SHA-512로 검증하는 전체 묶음으로 대체)를 더합니다. 템플릿 다운로드는 간헐적 504로 실패할 수 있어 다시 실행하면 이어서 성공하기도 합니다. JDK·Android SDK는 설치하지 않으며 APK 요청이 있을 때 `sjrpg_3d/tools/setup_android.sh`가 맡습니다. `--check`는 아무것도 설치하지 않고 준비 상태만 보고합니다. 에이전트별 환경 설정에는 이 스크립트를 호출하는 한 줄만 두고 설치 절차를 복사하지 않습니다.

Android 도구 준비는 `sjrpg_3d/tools/setup_android.sh`에서 수행합니다. 공용 시험 키는 `sjrpg_3d/tools/keys/debug-keystore.jks`이며 `obmaz/commuzip`의 키를 그대로 보관합니다. 설정 도구는 키를 생성하지 않고 alias를 확인한 뒤 Godot 에디터 설정에 기록합니다. 출처·지문은 [키 안내](../sjrpg_3d/tools/keys/README.md)에 있습니다.

## 검사

루트 `tools/check.sh`는 두 앱의 기존 검사 도구를 순차 실행합니다. 3D 물리와 투사체의 회귀 검사는3D 프로젝트에 추가하고, 2D의 기존 검사는 계속 실행합니다. `tools/test_portal.mjs`는 모바일·가로 화면의 선택 링크와 이전 주소 이동을 확인합니다. 웹 배포 후 두 직접 경로가 실제 게임까지 열리는지 확인합니다.

`tools/check_native_web.sh`는 조립된 웹 빌드를 실제 Chromium에서 열어 예배당의 일반 화질과 동굴의 절약 화질을 각각 세로→가로→세로로 회전합니다. 네이티브 물리 진행·뷰포트 방향과 WebGL/스크립트 오류를 확인하고 `build/review/`에 실제 화면을 남깁니다. CI도 같은 검사를 수행합니다. 3D판의 원본 Canvas 월드는 처음부터 부모만 숨겨 회전 중 `Polygon2D` 버퍼가 다시 그려지지 않게 하며, 개별 원화의 표시 플래그와 게임 처리는 유지합니다.

웹 Canvas는 고정된 전체 화면 크기로 제한합니다. 가로 렌더 버퍼의 고유 크기가 세로 복귀 후 모바일 레이아웃 폭과 배율을 넓혀 터치 좌표를 어긋나게 하지 않도록, 셸 검사에서 큰 버퍼를 유지한 왕복 회전을 검증합니다. 이동 모터는 충돌 후 실제 XZ의 바닥 지지를 다시 확인하고, 아래로 맞춘 캡슐이 벽과 겹치면 관통 없이 지지되는 경계까지 되돌립니다. `native_threshold_support`는 여러 이동 간격과 문 앞 위치에서 실제 발 높이·캡슐 비관통을 함께 검사합니다.

아트·UI·원본 데이터의 제작 규칙은 각 프로젝트의 `AGENTS.md`와 `docs/`를 따릅니다. 120°는 직교 투영의 세 축 사이 관계이며 카메라를120° 기울이는 뜻이 아닙니다.

고정 Godot4.7.2는 일부 네이티브3D 정상 종료에서 `WorkerThreadPool::Group`의 PagedAllocator 진단을 출력합니다. 장면을 먼저 정리해도 재현되며, 실행 중 스크립트/GL 오류와 구별해 기록합니다. 버전 이동의 성공과 실제 IndexedDB 저장·재접속은 별도로 검증하고, 다른 오류를 허용하는 근거로 사용하지 않습니다.

## 집별 표면과 몬스터 곡면

`sjrpg_3d/tools/preview3d/make_surface_variety.py`는 원본 수식에서 512px 알베도 18종을 재현합니다. 기존 이미지를 재색칠하지 않으며 원본 PNG·고정 시드·런타임 해시는 `assets/source/preview3d/surface-variety/provenance.json`에 보존합니다. 벽/자연물은 2.56m, 지붕은 2.6m의 기존 UV와 실제 기하를 유지합니다. 새 표면은 mode=1 보호 규칙을 적용하며 법선/거칠기 맵으로 가장하지 않습니다. `NativeHouse3D.STYLES`가 집별 벽·지붕·목재를 연결하고, `NativeSceneryProps3D`는 위치에서 공유 바위 재질을 고릅니다. 지면 변형은 지형 역할 번호에 고정되어 로드 순서에 영향받지 않습니다. 원래 풀잎 결은 기본 알베도로 보존하고 새 헤더·이끼 표면을 세부 재질로 혼합해 큰 단색 얼룩을 피합니다.

`NativeEnemyModels._form`은 유기체에 한정해 제한된 단면 보간과 연속 법선을 사용합니다. 바위와 철물의 모서리는 유지하며, 같은 관절별 메시 캐시를 재사용합니다. 몸체·공격·시체·실제 충돌은 기존 규칙을 유지합니다. 회귀 검사는 실제 삼각형 부피·바깥 법선·6천 삼각형 예산·재질 독립성과 공유 메시를 검사합니다.
