# 두 버전의 개발·배포

새 게임은 `flutter_game/`의 Flutter 3.47.8·Bonfire 4 앱이며 `/sjrpg/new/`에 배포합니다. 기존 게임은 루트 `src/`·`index.html`의 Canvas 2D·JavaScript 앱이며 `/sjrpg/legacy/`에 배포합니다. JavaScript 구조·동작 계약은 [Legacy 개발 참고](legacy-development.md), 조작·진행은 [Legacy 안내](legacy-guide.md)를 따릅니다.

Flame·Bonfire의 컴포넌트 수명·카메라·Player/Enemy·충돌 공간 탐색·입력을 사용합니다. 게임 고유의 지형·전투 규칙과 프레임 아틀라스는 위 모델과 렌더러가 담당합니다. 화면 위젯에 별도 전투 공식을 만들지 않습니다.

Dart 파일은 snake_case, 타입은 PascalCase, 멤버는 lowerCamelCase를 따릅니다. `dart format`과 `analysis_options.yaml`의 파일명·import 순서 규칙을 지킵니다. 공유 헬퍼는 실제로 같은 계약을 사용하는 호출부가 있을 때 추출합니다. 수치·상태·렌더링을 불필요한 전달 계층으로 나누거나 사용하지 않는 대체 구현을 남기지 않습니다.

## 전투·시간 계약

`CombatNumbers`는 공격·피해·체력·방어·생명 회복에 `CombatUnit.stat=1000`, 분노·마나의 현재/최대치·장비 옵션·소모·회복에 `CombatUnit.resource=10`을 적용합니다. 내부 시뮬레이션·저장은 기존 기준 단위를 유지하고 공개 숫자 경계에서 한 번 변환합니다. 따라서 체크포인트 버전이나 저장 숫자를 일괄 곱하지 않으며 기존 체력 비율·장비·시전 가능 횟수를 보존합니다. `SkillPreviewValue.unit`을 명시해 수량·레벨·등급·비율·시간·사거리에 배율을 섞지 않습니다. `/초` 값은 실제 시간으로 변환한 뒤 해당 전투 단위를 적용합니다. 마력 방패는 피해 1,000당 마나로 교환 비율을 설명합니다. 피해 숫자는 실제 명중량을 소수 상태로 전달하고 변환 후 반올림하며, 보상 골드·물약 개수는 원래 단위를 유지합니다.

`CombatBalance.gameSpeed=1.2`는 실제 1초당 시뮬레이션 시간입니다. 쿨다운·투사체·상태 이상·리젠·시체 수명은 시뮬레이션 시간으로 계산하며, 설명의 시간·초당 피해는 표시 경계에서 실제 시간으로 변환합니다. 시간 배율을 공격력에 다시 곱하지 않습니다. 부활 보호는 실제 3초입니다.

공격 전에는 생존·일시정지·자원·대상·지형을 확인합니다. 실제로 실행되지 않은 기술은 자원·쿨다운을 쓰지 않습니다. 사망 처치 보상은 적 하나당 한 번이며 같은 프레임의 뒤이은 회복이 사망을 취소하지 않습니다. 적의 광역 피해는 실제 유효 대상 수로 한 명당 피해를 분배하고, 직격 후 같은 대상에 폭발 피해를 중복하지 않습니다. 지형·성역을 통과하는 투사체나 공격을 허용하지 않습니다.

장비 표시·기술 미리 보기·공격 입력은 같은 `Progress` 수치를 사용합니다. 큰 버튼은 별도 주 슬롯(`Progress.primarySlot=4`)으로, 기본 공격·배운 사용 기술·이동 기술 또는 빈 상태를 갖습니다. 기본 공격 선택은 주 슬롯에 다시 장착하며 학습 등급을 지우지 않습니다. 보조 전투 슬롯은 `SkillDef.combatAssignable`로 기본 공격도 허용하며 저장 복원과 상세 배치 버튼이 같은 조건을 사용합니다. 기본 공격의 주·보조 슬롯은 공격 회복 시간을 공유합니다. 주 슬롯의 일반 기술은 기존 `skill(slot: 4)`의 자원·쿨다운·조준·대기 입력 경로를 사용하고, 이동 기술은 공통 이동 실행기로 보냅니다. 일반 공격만 길게 눌러 반복하며 일반 기술은 한 번 누를 때 한 번 시도합니다. 비운 주 슬롯은 공격하지 않고 스킬 창을 엽니다. `primarySkill` 저장 필드의 누락은 기존 기본 공격, null은 명시적 빈 슬롯, `@basic`은 선택한 기본 공격을 뜻합니다. 기술 ID는 배운 기본 공격 또는 비패시브 기술인지 검증하며 초기화로 배움을 잃은 주 기술은 해제합니다. 장비의 원시 공격, 숙련 후 공격, 한 타 피해, 실제 공격 주기와 기대 치명타를 반영한 DPS를 구분합니다. 마법은 무기 공격을 자동으로 상속하지 않으며, 원본 주문 곡선에 공통 피해 배율과 모바일 마법 보정 `1.5`를 한 번 적용한 `sorceressSpell`을 설명과 전투가 공유합니다. 마법사는 공통 주문 평가기에서 1→20등급 피해 효율을 60→100%, 방어·흡수·숙련·상태 지속 효율을 40→100%, 사거리·반경 효율을 75→100%로 보간합니다. 지속 버프의 수명·마나·시전 지연은 유지합니다. 순간이동은 기존 1등급 거리 450의 절반인 225부터 시작하고, 등급별 증가분 150/19를 유지해 20등급 375에 도달합니다. 설명·조준·실제 이동은 같은 주문 수치를 사용합니다. 광역 최대 대상은 3+(등급−1)이며 고유 투사체·연쇄 한도를 넘지 않습니다. 불길도 같은 대상 한도를 적용합니다. 얼음 보주의 실제 파편 수는 1등급 18개에서 20등급 46개까지 증가하며, 이동·종료 파편을 같은 총수에서 배분합니다. 마법사 기본 공격은 배운 화염탄·번개 줄기·얼음살 중 선택하고 마나 부족 시 지팡이 공격으로 바꾸지 않습니다.

주인공과 적의 이동은 전체 충돌 몸체를 검사합니다. `EnemyPower`는 출현 위치와 장을 기준으로 레벨·체력·공격·방어를 고정하며 추적 중 다시 계산하지 않습니다. 1~5장 보스는 장×20레벨, 일반 적은 장×20−19에서 장×20−1까지 마을 거리로 증가합니다. 고대/미래 분기는 같은 장 번호를 공유합니다. 종별 성장 프로필은 체력·공격·방어에 서로 다른 비중을 주며 모든 피해는 공통 명중 경로에서 방어를 적용합니다. 플레이어 레벨을 생성 체력에 다시 곱하지 않습니다. 마을 시작점 반경 4,000 안의 새 무리 수는 절반(올림), 보스 이외 새 적 체력은 절반입니다. 새 저장은 레벨과 능력치 스냅샷을 보존합니다. 구형 지역 강도 저장은 새 기준 체력으로 한 번 옮기면서 부상 비율을 보존합니다. 먼 곳·다음 장·정예/고유 적은 각 배율을 적용합니다. 활성 적 한도와 지역별 유한 출현 횟수를 지킵니다.

`BarbarianUtilities`는 일반 적의 수락된 처치마다 독립 RNG로 시체 확률 10%를 한 번 판정합니다. 실패한 적도 중복 판정하지 않으며 전리품·치명타 RNG 순서를 바꾸지 않습니다. 시체는 최대 32개·시뮬레이션 180초이며 한 기술이 소비하면 다른 조사 기술에서 사용할 수 없습니다. 지형 너머나 범위 밖의 시체는 사용할 수 없습니다. `monster-corpses`의 종별 쿼터뷰 바닥 자세를 원래 가로세로 비율로 그립니다. 서 있는 프레임의 회전·납작한 변형을 사용하지 않습니다. 몸체 표시 폭은 처치 당시 적 표시 높이로 정하고 실제 그림 경계를 화면 가시성 검사에도 사용합니다.

레벨업 요구량은 `ceil(ceil((55 + (level - 1) * 30) * 1.5) / 2)`입니다. 처치·의뢰 XP의 보상 배율과 요구량을 혼동하지 않습니다. `LevelUpEffect`는 생성형 16프레임을 보간해 주인공 뒤에 그리며 처치·의뢰 XP 모두 같은 레벨 변경 알림을 사용합니다. 동시에 여러 레벨을 얻어도 연출을 무제한 쌓지 않습니다.

타격·기술 연출은 피해 판정과 분리합니다. 히트스톱·진동·파편·화면 흔들림 때문에 실제 타격을 다시 실행하지 않습니다. 소용돌이는 주인공 본체 뒤에 연속 붉은 궤적을 그리고, 강타는 단일 대상의 짧은 충격으로 구분합니다. 저체력·중독 경고는 동작 줄이기를 존중합니다. 그림 프레임 수와 엔진의 시뮬레이션 프레임 수는 같은 개념이 아닙니다.

## 지도·의뢰·안전 경계

월드는 34,560×25,920이며 일곱 지도는 고유 의뢰와 시대별 구도를 가집니다. 필수 성소·의뢰·처치·보스 조건을 모두 충족해야 장을 완료합니다. 제2장은 첫 의뢰인의 줄기를 선택하고 다른 줄기를 잠급니다. 고대/미래 제3·4장을 지나 같은 지도·다른 의뢰인의 제5장으로 합류합니다. 사용자에게 사전 분기 선택을 다시 요구하지 않습니다.

`FieldLandmark`는 일곱 지도마다 4개의 대형 쿼터뷰 지형물을 정의합니다. 마을·성소·의뢰·상자·다리·수면·실제 길을 피해 여정 앵커 근처에 결정적으로 배치하며 전투 RNG를 소비하지 않습니다. 밑의 작은 무작위 소품과 그 충돌을 함께 제거하고, 지형물의 발밑을 공통 이동·발사체 충돌 인덱스에 등록합니다. 그림 전체 경계를 소품 검색에 등록해 높은 윗부분도 화면에 진입할 때 표시합니다. 기존 저장의 막힌 위치는 공유 안전 스폰으로 복원합니다. 생성 원본·측정된 개별 실루엣 경계·해시는 `docs/art/field-landmarks/`, 패킹은 `tools/prepare-field-landmarks.py`로 보존합니다. 런타임 2×2 시트는 현재 장 것만 디코딩하며 장당 약 9MiB입니다.

`TerrainMapPlan`은 실제 `FieldLandscape`의 지표 구역과 월드의 숲·공터·모래·강·호수·다리·길·마을 충돌·큰 지형물 발밑을 두 지도에 같은 좌표로 그립니다. 지도에는 평면 색과 최소 윤곽만 사용하고 원근 장면·재질 사진·전투 효과·작은 무작위 소품을 넣지 않습니다. 확대 지도에서만 큰 지형물의 이름을 표시하며 길과 윤곽의 최소 두께는 화면 배율에 맞춥니다.

생성한 마을 장면의 실제 충돌 폴리곤·성벽 안전 윤곽·서비스 위치를 `AuthoredSettlement`에서 함께 정의합니다. 성역의 반경은 탐색용이며 실제 보호 판정은 윤곽을 사용합니다. 주인공 또는 적이 안전 영역에 있거나 공격 선이 안전 영역을 통과하면 공격을 막습니다. 주인공을 감지하지 못한 적은 생성 지점을 중심으로 유효한 필드 위치를 순찰합니다. 종류별 추적 한도를 넘으면 생성 지점으로 복귀하며 이 좌표는 휴면·장 이동·저장에서도 보존합니다. 마을 출입문은 퇴장 후 실제 30초에 해당하는 시뮬레이션 시간 동안 재진입을 막고 양쪽 문짝이 닫히고 열립니다. 일시정지는 이 타이머도 멈춥니다. 지상 이동·구르기·질주는 공간 인덱스의 적 몸체를 연속 검사하며 학습한 도약의 공중 구간만 통과를 허용합니다. 도약의 착지 지형은 시전 전에 확인하며, 착지 시 새로 들어온 적은 지형과 다른 몸체를 검사해 밀어냅니다. 적에게 점유되었다는 이유로 주인공을 출발점으로 되돌리지 않습니다.

길·물·마을 출입구·성소 접근점은 렌더링과 이동 판정이 같은 모델을 사용합니다. 스폰 실패의 `null`을 막힌 후보로 대체하지 않습니다. 적의 경로 탐색은 종료 반경 내에 들어갈 수 있는 전체 몸체 후보를 확인하며 확장 횟수를 제한합니다. 새 몬스터 무리 생성은 발밑 개인 공간의 1.2배를 확보하고, 모든 이동에서 개인 공간 접근을 검사합니다. 주인공 근처의 열린 지형에서는 그림의 깊이를 고려해 개인 공간을 넓히고 근접 적의 공격 거리도 맞춥니다. 좁은 통로에서는 원래 발밑 크기로 지나가며, 복원된 기존 겹침은 더 깊어지지 않으면서 빠져나오게 합니다. 다수의 실제 그림과 주인공의 겹침, 원거리 적 군집·근접 추적·돌진·넉백을 함께 검증합니다. 추적 시야는 0.15초 또는 이동 임계치·상자 지형 변경 시 다시 검사하고 실제 이동 충돌은 매 이동 구간에서 검사합니다. 군집의 국소 우회 탐색은 프레임당 2회로 제한합니다. 마을 충돌 폴리곤은 전체 경계 사전 검사로 먼 필드에서 순회를 생략합니다.

우물 발견과 도착 위치는 공통 안전 접근점을 사용합니다. 방문한 모든 장의 발견한 우물로 이동할 수 있으며, 휴면 적·상자·주차한 탈것·의뢰 상태를 각 지도에 보존합니다. 상호작용은 여러 후보 중 선택할 수 있어야 하고 우물 의뢰가 옆 상자·탈것을 가리지 않아야 합니다. 상자는 몸체를 막는 파괴 가능한 오브젝트입니다. 마을에서도 범위 안 상자가 있으면 공격 기술의 자원·쿨다운을 정상 적용해 실행합니다. 광역·원뿔·빔·지속 지대도 실제 범위·지형·대상 한도 안의 상자를 파괴하며, 보호 구역에서 시작한 주문은 이후 적에게 피해를 주지 않습니다.

미니맵은 주인공을 중심에 고정하고 방향 화살표와 화면 크기에 맞춘 주변 적 표식을 표시하며 서비스·성소는 월드 좌표로 표시합니다. 확대지도는 같은 지형·마을·보호 경계를 사용하며 확대해도 표식 크기를 유지합니다. `MapMarkerLayout`은 완전한 표식 반경과 여백을 지도 안에 두고 겹치는 표식을 개수로 합칩니다. 확대하면 떨어진 표식은 다시 개별로 표시하며, 개수 표식은 주인공 화살표를 피합니다. 표식을 위로 밀어 지도 밖에 쌓지 않습니다. 사막 길은 모래에 묻힌 옅은 흔적으로, 신전 기둥·벽은 실제 받침이 있는 장애물로 표시합니다.

## 그림·캐시·성능

`entry-scene`은 1024×576 가로 로딩 풍경이며 HTML 부트스트랩·EntryLoading에서 cover로 공유합니다. WASM 세션 준비는 LandscapePreparation이 타이틀의 LandscapeEntry 가로 캔버스에서 배경과 패널을 함께 배치합니다. 준비 중에는 타이틀 대신 보관 중인 이미지로 배경을 덮고, 원본·해시는 docs/art/loading-landscape/에 보존합니다. `GameArt.loadMenu`는 메뉴 그림만 준비합니다. 시작·이어하기·장 이동은 필요한 직업·적·장면을 비동기 트랜잭션으로 준비한 뒤 엔진을 만듭니다. 실패·취소 시 기존 페이지와 그림을 보존하고 재시도합니다. 오래 열린 페이지의 배포 파일이 사라져도 방문하지 않은 장을 열 수 있도록 나중에 사용할 압축 원본을 첫 플레이 전에 보관합니다. 이미 사용하지 않는 이전 VFX·마을 조각은 이 사전 다운로드에서 제외합니다. 디코딩·굽기가 끝난 압축 원본은 해제합니다.

`GameArt`가 이미지·재질·아틀라스와 글자 캐시를, `TerrainArt`가 지형 `Picture` 캐시를 소유합니다. 종료 시 각 소유자가 네이티브 자원을 해제합니다. `GameArt.text`는 문자열·크기·색상별 문단을 최대 128개 LRU로 재사용하고 제거 시 dispose합니다. `layoutText`가 반환한 문단은 호출자가 소유하므로 캐시에 넣거나 대신 해제하지 않습니다. 글꼴은 메뉴·게임 표시 전에 준비합니다. 피해 숫자의 자체 문단 캐시와 별개입니다.

지형은 보이는 구역만 그리고 512px 구역 캐시는 최근 사용한 구역부터 최대 24개를 유지합니다. 화면 밖 적·오브젝트·효과는 실제 그림/공격 예고 경계로 그리기만 생략하고 시뮬레이션·보상·충돌을 중단하지 않습니다. 적 깨우기·주변 소품 탐색·경로 탐색은 시간·공간 예산을 두며, 모든 적·모든 지형을 매 프레임 다시 검색하지 않습니다. 잦은 위젯 갱신과 네이티브 글자 레이아웃·이미지 디코딩을 전투 프레임에 넣지 않습니다.

`prepare-new-assets.cjs`는 필요한 공유 그림과 `flutter_game/art/` 및 프레임 메타데이터를 무시된 `flutter_game/assets/`에 준비합니다. 원본으로 덮어쓸 구형 주인공 그림을 먼저 복사하지 않습니다. Flutter에서 사용하지 않는 `actors-vehicles`·`ui-reference`·`popup-frame`·`fx-whirlwind`·`entry-splash` 배포 사본은 제거하며 Legacy 원본과 회귀 비교용 아트는 보존합니다. 다른 준비 파일을 무차별 삭제하지 않습니다.

생성형 원본·출처·해시·측정/패킹 도구는 [콘텐츠 기준](content-reference.md)과 `docs/art/`에 보존합니다. 실제 캐릭터·소품의 투영 방향과 광원, 발 위치·측정 앵커·몸체를 일치시킵니다. 그림에 글자를 굽지 않고 버튼·숫자·접근성 이름은 코드로 표시합니다. 원본을 단순히 확대해 선명도를 주장하지 않습니다. 레벨업 시트는 `tools/prepare-combat-illustrations.py --preset level-up --source <원본>`으로 투명 여백과 함께 패킹합니다.

일반 적의 이동 보간은 양발의 접지와 들림을 번갈아 적용합니다. 보스의 고정 발 자세와 이미지 아래 투명 여백은 이동 보간으로 변형하지 않습니다. 탐색 결과 문구는 160px 문단 안에 결과·물품을 각각 한 줄로 표시하며 실제 한글 글꼴로 줄 수를 검사합니다.

30FPS에 해당하는 33.3ms 프레임 예산이 목표입니다. 네이티브 미세 측정·대체 엔진 테스트·헤드리스 소프트웨어 GPU를 실제 휴대전화 FPS로 보고하지 않습니다. 최적화는 그림·경로·전투 결과의 회귀 검사와 함께 확인합니다.

## UI·저장·플랫폼

팝업은 같은 프레임·머리글·닫기·하단 행동·스크롤 안전 영역을 공유합니다. 공통 프레임은 Material의 둥근 클립 안에서 배경·잉크를 그리고 테두리를 전경에 그립니다. 배낭·상점·강화·설정·알림·확인 창은 가로·세로에서 중앙 정렬하며 수행할 수 없는 행동은 비활성화합니다. 버튼은 짧은 행동명을 쓰고 조건·비용은 설명에서 안내합니다. 배운 기본 공격의 빠른 전환은 장착만 바꾸며 트리의 선택·탭·스크롤을 유지합니다. 스킬 상세는 가로·세로 모두 부모 중앙에 배치하고 Material의 둥근 모양과 클립을 공유해 잉크 효과와 스크롤이 모서리를 침범하지 않게 합니다. 교체 버튼에는 현재 주·보조 슬롯의 스킬 아이콘을 표시하고 빈 슬롯은 +로 표시하며 접근성 값과 툴팁에 현재 스킬 이름을 제공합니다. 전사 기본 공격도 ‘기본·특수’ 트리 노드로 학습·장착할 수 있습니다. 생성 이미지의 버튼 간격을 균등 격자로 가정하지 않습니다. 원본의 개별 알파 경계와 원형 중심을 측정해 `d1-icons-provenance.json`의 `sourceRects`에 기록하고, 규격 셀로 옮긴 뒤 렌더링합니다. 생성된 테두리가 포함된 기술·주 슬롯·회피 그림은 버튼 전체를 채우고, 무기 등 테두리 없는 그림에만 내부 여백을 줍니다. D1 원형 시트는 기존 전사 100–129·마법사 200–229의 효과 ID에 대응하고, 공용 메뉴·이동·상태는 별도 32셀 시트를 사용합니다. 클래스 시트는 해당 직업만 디코딩하며 구형 기술 시트는 원본 비교용으로 보존하고 플레이에서 요청하지 않습니다. `D1IconArt`의 공통 표시 필터가 원소별 색을 유지하면서 채도를 낮춥니다. 강화·약화 상태는 실제 함성/마법/주인공/상태 이상 타이머를 읽으며 일시정지·만료·초기화를 별도로 재계산하지 않습니다. 작은 상태 줄은 한 줄로 크기를 맞춰 물약·미니맵을 가리지 않고 접근성에는 상태명·남은 실제 초를 제공합니다. 스킬 트리는 계열 탭을 쓰며 연결선을 자르거나 가로 스크롤로 숨기지 않습니다. 가방은 목록 안에서 바로 장착·비교합니다. 전투 조작부는 `BattleControlLayout`의 주공격 중심 주위에 보조 기술을 원형 터치 영역의 아치로 배치하며, 전투 버튼은 방향과 관계없이 세로 기준 크기(주 슬롯 84px·보조 52px·구르기 44px)를 유지하고 위치만 화면 높이에 맞춥니다. 공용 메뉴 네 개는 44px 크기를 공유합니다. 충분한 높이의 세로 화면에서도 물약은 전투 버튼 아치 위 오른쪽에 둡니다. 가로 화면의 설정·가방은 미니맵 왼쪽에, 스킬·여정은 미니맵 오른쪽의 세로 열에 둡니다. 물약은 충분한 높이에서 전투 조작부 위에, 세로 메뉴는 하단에 두며 전투 슬롯·구르기와 겹치지 않는 44px 이상 터치 영역을 사용합니다. 장비 아이콘·제목은 위쪽에 맞추며 특수 능력과 추가 능력 수치는 기본 수치 뒤에 펼치지 않아도 표시합니다. 생성된 주 공격·메뉴 버튼은 개별 알파 경계와 원형 중심을 측정한 `reference-battle-buttons` 시트에서 읽습니다. 전투 버튼은 그림과 원형 프레임을 공유하고 HUD의 시간·골드 칩은 숨깁니다. 라벨 없는 원형 버튼은 원 안에서만 터치를 시작합니다. 경험치는 분노·마나 바로 아래에 둡니다. 체력·자원·경험치와 공통 프레임은 같은 원형 초상 경계를 따라 잘라 원의 테두리에 붙입니다. 제목과 숫자는 잘리는 영역 밖에 유지합니다. 레벨·직업 제목 행은 표시하지 않고 체력·자원·경험치를 위쪽으로 올립니다. 체력 18px·경험치 8px의 높이를 유지하고 큰 글씨에서는 자원 라벨에 필요한 높이만 확보합니다. 숫자·경험치 문구는 원형 초상의 금속 테두리 바깥 공간에 정렬합니다. 세 게이지와 공통 프레임은 하나의 전역 사선 좌표를 공유해 중간 직각 돌출부를 만들지 않습니다. 실제 몬스터·주인공 피해는 즉시 적용하고 숫자만 대상별 큐에서 시뮬레이션 0.18초 간격으로 표시합니다. 한 대상은 가로 위치를 공유하는 한 열·최대 5개의 숫자를 유지하고 위로 올라갑니다. 각 숫자의 수명은 0.9초이며 치명타 제목까지 겹치지 않게 세로 간격을 확보합니다. 큐는 대상마다 24개로 제한하고 동작 줄이기에서는 움직임 없이 세로 슬롯을 사용합니다. 피해 숫자는 CombatDamage의 Nanum Gothic ExtraBold(900)를 사용하고 일반 18px·치명타 22px을 상한으로 표시합니다. 글꼴은 Google Fonts의 ofl/nanumgothic/NanumGothic-ExtraBold.ttf 원본이며 기존 assets-fonts/OFL.txt를 따릅니다. 보상과 HUD 글꼴은 Guardian을 유지합니다. 캐시된 숫자와 치명타 제목은 함께 페이드합니다. 모바일 세로·가로, 작은 화면, 글자 배율 1.3 이상에서 44px 터치와 필수 행동을 확인합니다. `CombatDistance`는 월드 40단위를 1걸음으로 표시하며 사거리·반경·이동 속도에 동일하게 적용합니다. 장비 수치와 실제 한 타 피해를 구분하고 DPS는 공유 모델을 사용합니다.

Flutter는 주소창 높이 변화에는 기준 높이를 고정하고 너비 변화 시 새 방향의 높이로 갱신합니다. 전체화면은 동적 높이를 사용하고 종료 시 현재 방향의 기준을 복원합니다. 데스크톱 창 크기 대응은 유지합니다. 다중 터치와 연속 탭이 브라우저 확대를 유발하지 않아야 합니다. 뒤로 가기는 열린 팝업을 먼저 닫고 게임 안의 메뉴/종료 흐름을 따릅니다.

저장은 브라우저에 남으며 5초 간격·중요 변경·백그라운드 전환 시 기록합니다. `GameCheckpoint`는 버전·크기·유효 위치·장비 ID·스킬·쿨다운·의뢰·방문 장을 검사합니다. 현재 체크포인트 `version=1`·`mapVersion=2`·`balance=3`, 직업 트리 버전 1을 사용합니다. 성장 데이터의 `experienceVersion=2`는 이전 누적 XP를 한 번 정규화해 레벨·포인트를 보존하며 체력·자원을 무료 회복시키지 않습니다.

일반 이어하기와 사망 후 부활을 구분합니다. 사망 손실은 한 번 확정해 저장하고 부활 보호·상태 이상 정리는 명시적인 부활 때만 적용합니다. 저장 실패는 성공처럼 덮어쓰지 않으며 기존 모험을 유지하고 오류·재시도를 표시합니다. 타이틀의 이어하기는 누를 때와 앱으로 돌아올 때 저장 유효성을 재확인합니다. 타이틀에서 시작을 누르면 기존 저장의 덮어쓰기를 확인하고 직업 선택으로 이어집니다. 확인 취소·직업 선택 복귀는 저장을 변경하지 않으며, 비동기 준비 중 중복 입력과 확인 창 중복 열기를 막습니다.

`title_screen.dart`는 `art/guardian-title.png` 원본(1672×941, Library `libfile_9e05ed38e2808191868ef90303b5aa33`, 버전 0)을 비율을 유지하며 화면에 꽉 차게 표시합니다. 그림 속 PRESS START 자체에 투명한 시작 터치 영역을 연결하고, 이어하기는 별도 금속 테두리 버튼으로 표시합니다. `landscape_entry.dart`의 1672×941 기준 캔버스에서 그림·선택 테두리·터치 영역을 함께 스케일합니다. 세로 기기에서는 같은 가로 캔버스를 회전하며 별도 세로 배치를 만들지 않습니다. 그림 좌표는 고정하고 터치 영역만 실제 44px 이상으로 확장합니다. 캐릭터 선택은 제공된 ZIP의 카드·패널·버튼을 그대로 쓰며, UI가 제거된 `select-scene.png`에 덧씌웁니다.

설치 요청은 브라우저가 제공한 이벤트를 설정의 사용자 탭 안에서 전달합니다. PWA ID·시작 경로·서비스 워커 범위는 `/sjrpg/new/`로 고정합니다. 진동 API는 지원 여부와 사용자 설정을 존중합니다.

## 검증·배포

Node.js 24 이상에서 루트의 `npm run check`를 실행합니다. Flutter 자산을 준비한 뒤 `flutter_game/`에서 다음을 실행합니다.

```sh
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
flutter build web --wasm --release --base-href /sjrpg/new/ --no-web-resources-cdn
```

같은 작업 공간의 Flutter 검사·테스트·빌드는 직렬로 실행합니다. UI·입력·렌더링 변경은 실제 브라우저에서도 조작합니다. 회귀 시나리오는 유지하되 문서에 오래된 리뷰 완료 기록·테스트 개수를 누적하지 않습니다. 이름에 review가 있는 테스트는 문서 보고서가 아니라 동작 검사이므로 이름만 보고 삭제하지 않습니다.

`npm run prepare:legacy`는 소스와 바이트가 같은 캐시나 공개 Legacy를 검증해 복원하고, 바뀐 경우에만 독립 빌드합니다. `npm run build:new`는 Flutter만 빌드합니다. `npm run build`는 준비된 두 결과를 컴파일 없이 `dist/`에 조립합니다. Flutter 콘텐츠 해시의 `new/releases/<해시>/`와 독립 Legacy 해시를 유지합니다. GitHub Pages에서는 단일 스레드 Skwasm을 사용하고 미지원 브라우저용 JS 결과도 함께 배포합니다.

GitHub Actions **Check and deploy**는 두 게임의 검사·캐시 작업과 조립·Pages 배포를 분리합니다. 완료 보고 전 정확한 커밋의 워크플로 성공, 공개 진입 화면·두 하위 경로, 실제 WASM과 생성 자산의 해시·브라우저 동작을 확인합니다. 한 버전의 수정 때문에 다른 게임을 불필요하게 재컴파일하지 않습니다.

전투 그림은 `docs/art/cinematic/`의 생성 원본·측정 경계·해시와 `tools/prepare-cinematic-art.py`로 재현합니다. 몬스터 21종의 런타임 그림은 `actors-walk-*`의 8방향 × 4개의 독립 보행 자세입니다. 원본·측정 경계·해시와 분리한 시체 17종은 `docs/art/monster-motion/`, 패킹은 `tools/prepare-monster-motion.py`로 재현합니다. 프레임은 실제 이동 거리의 연속 보행 주기로 선택하고 멈춤·피격·공격에서는 보행을 고정합니다. 보스도 같은 네 자세를 사용하며 작은 메시 변형을 함께 적용합니다. 구형 16프레임 런타임 사본은 배포에서 제거하고 생성 원본·픽셀 회귀 자료는 보존합니다. 기준 월드 높이는 유지하고 전투 장면에서는 기존 표시 높이의 0.8배로 그립니다. UI는 `CinematicIconArt`, 공격 궤적은 `IllustratedCombatArt`를 공유합니다. `combat-illustrations`는 완전히 분리된 검격·냉기·번개·화염 생성 원본의 알파 경계를 측정해 2×2 시트로 준비하고, 팽창·잔상·페이드와 기존 궤적·입자를 함께 사용합니다. 원본과 해시는 `docs/art/cinematic-combat-vfx-provenance.json`, 패킹은 `tools/prepare-cinematic-combat-vfx.py`로 재현합니다. 큰 이펙트의 표시 경계는 확대하되 실제 명중 범위와 시간을 바꾸지 않으며 충돌·피해 판정은 기존 월드 모델을 유지합니다. 캐릭터는 `SJRPG_RENDER_CELL=384`로 각 방향과 동작을 다시 렌더링하고 원본 픽셀을 그대로 패킹합니다. 전사와 마법사의 일반·탑승·구르기 그림은 같은 표시 배율을 사용하며, 충돌 몸체와 공격 범위는 바꾸지 않습니다.

탈것은 탑승·주차 화면에서 동일한 표시 크기를 사용하며 더 큰 차체에 맞춰 탑승자의 높이를 조정합니다. 충돌 크기와 이동 판정은 유지합니다. 기관포·질주·물살 버튼은 `mount-skill-icons`의 생성 원본을 사용하고 탄약·말의 피격 횟수는 별도 표시합니다.

이동 기술도 combatAssignable이며 주·보조 슬롯에서 Guardian.useMobility를 호출합니다. 독립 이동 버튼은 만들지 않고 이동의 자원·재사용 대기·장애물 검사는 기존 런타임을 공유합니다. 지도는 mapQuestColor를 퀘스트 점과 선택 범례에 함께 사용하고 완료 뒤에도 지역 색을 유지합니다. 확대 지도 플레이어는 밝은 중심·이중 테두리·방향·내 위치 이름을 마지막에 그립니다.

저체력에서는 PlayerHealthFeedback.warningTintOpacity를 체력바 전체(빈 영역 포함)와 초상화가 공유합니다. 붉은 상태를 유지하면서 같은 시계로 밝기가 변하고 회복·숨김·동작 줄이기를 기존 피드백 수명주기에 맞춥니다. 치명타 제목은 빨간 CRITICAL을 사용합니다.

### 숲의 구성과 NPC 의뢰

숲은 `docs/art/forest-composition/stage-concept.png`의 전체 구성과 실제 지형 앵커를 기준으로 배치합니다. `ForestTreeArt`의 참나무·전나무·버드나무 각 3개 높이는 독립 생성 그림입니다. 물가·길 경계·숲 깊이·마을 거리로 선택하며 충돌 줄기는 유지합니다. 비대칭 원본 발밑 기준을 렌더링·화면 경계 검사에 공유합니다. `QuarterViewBridgeArt`는 측정한 수평 상판을 실제 통행 사각형과 맞추며, `QuarterViewRoadArt`는 실제 길 선 위에 사선 돌과 앞면 깊이를 그립니다. 원본·측정값·패킹은 각 docs/art 폴더와 tools/prepare-*에 보존합니다.

숲의 roots/moon/sun ID는 저장 호환을 유지하며 예배당·오두막·동굴로 표시합니다. `ForestQuestStructureArt`는 발밑 폴리곤·NPC 접근점·그림 경계를 공유합니다. `ForestQuestRuntime`이 NPC 대화와 정화·꾸러미 배달·조사관 보호를 처리하고 우물 워프와 분리합니다. 보호는 명시적 시작/재시도마다 3명의 적만 생성하며 실제 30초와 전원 처치가 모두 필요합니다. 조사관 체력·시도 번호·개별 적 토큰·타이머를 체크포인트와 휴면 저장에서 복원하고, 중복/누락 토큰을 거부합니다. 보상은 완료 보고 때 한 번 지급하며 기존 성소 완료 기록은 이미 보상받은 NPC 의뢰로 이관합니다.

재소환 비석은 36×24 고체 발밑을 공통 충돌 인덱스에 등록합니다. 최초 무리 이후 같은 지역 자동 재생성은 금지하며 공격 성공 때만 충전을 소비합니다. 최대 3회, 실제 300초당 1회를 시뮬레이션 시간으로 계산하고 충전·부분 시간을 저장합니다. 일시정지·오프라인에서는 충전하지 않습니다. 상자는 저장된 캠페인 seed로 10개 묶음 내용을 섞고 장비 RNG를 분리합니다. 구형 seed 누락은 0으로 이관하며 이미 연 상자는 다시 보상하지 않습니다.
