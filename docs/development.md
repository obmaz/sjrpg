## 로딩과 수호자 선택

`web/shell.html`은 엔진 다운로드 전부터 숲 원화와 실제 전송 진행률을 표시합니다. 전체 크기를 모를 때는 불확정 표시를 사용하고, 다운로드 완료와 엔진 준비 단계를 구분합니다. 실패·기능 미지원·엔진 스크립트 실패는 재시도 화면으로 처리합니다.
`web/prepare_art.py`가 기존 `select-scene.png`를 외부 배경으로 패킹하며, `tools/export_web.sh`가 248KB의 `loading-bg.webp`를 배포 폴더에 복사합니다. `web/.gdignore`로 HTML용 파일을 게임 PCK에서 제외합니다.
`node web/check_shell.mjs`로 실제 다운로드 콜백·완료·실패·동작 줄이기·가로/세로 배치를 브라우저에서 검사합니다.

`title_screen.gd`와 `class_select.gd`는 안전 영역과 화면 크기에 따라 다시 배치합니다. 수호자 선택은 두 개의 직업 탭과 단일 큰 원화, 특징·실제 시작 수치, 하단 시작·이어하기 버튼을 사용합니다. 원화는 `assets/source/hero-selection.png`를 `tools/prepare_entry_art.py`로 두 직업의 WebP로 나눕니다. 가로 미리보기는 원화 상단을 기준으로 잘라 얼굴을 보존합니다.
직업 미리보기는 진행을 변경하지 않으며 실제 새 모험·덮어쓰기 확인은 `main.gd`가 담당합니다. `entry_layout`은 회전·작은 화면·실제 저장 보존과 명시적인 시작을 검사합니다.
`tools/screenshot.mjs --scene title|select --class warrior|mage --device phone|phone-landscape`로 확인하고, 선택 화면에서 `--rotate 1`을 주면 같은 선택을 유지한 회전 화면도 저장합니다. 웹 하네스는 실제 버튼 중심을 받아 두 직업 선택 후 시작합니다.

## 좌표와 단위

- 지면 좌표(원본 단위)는 `Iso.project()`로 화면 평면의 월드 픽셀이 됩니다. `Iso.S`는 원본 월드를 이 포트의 화면 비율로 바꾸는 배율입니다.
- 건물 원화는 `IsoSprite`가 실측 바닥 접점(`foot`), 지면 보정(`gvs`/`gvk`), 패킹 배율로 그립니다.
- 지면은 균일하게 밝기를 조정하며, 물체·광원을 계산하지 않는 반복 그늘이나 고정 햇빛 레이어를 얹지 않습니다.
- 배우 이동은 `Game.move_actor()`가 반지름 기준으로 경로를 나눠 검사합니다. 프레임 지연에도 얇은 절벽을 뛰어넘지 않으며, 스폰 목적지 검증은 `resolve_movement()`로 별도 처리합니다.
- 깊이 정렬은 `world`(y 정렬) 안의 노드 위치 y입니다. 높은 지형 윗면의 캐릭터는 `z_index = 1`로 원화 위에 그립니다.

일반 나무는 `assets/source/forest-trees.png`의 참나무 두 크기·전나무·버드나무를 사용합니다.
수관 윗면·뒤쪽 가지의 가림·줄기와 뿌리 접점을 시각 검수하며, 자연형 실루엣에 건물의 직선 모서리 각도 검사를 적용하지 않습니다.
`tools/extract/tree_art_measure.json`에 원화 영역과 줄기-지면 접점 중심을 기록하고,
`python3 tools/prepare_tree_art.py` → `extract_data.py /path/to/sjrpg --only=village`로 재생성합니다.
`tree_art.merge()`가 기존 18개 ID의 높이를 보존해 새 네 그림에 연결합니다. `tree_art` 검사는 리뷰한 원본·아틀라스 해시와 실제 필드의 발치·충돌을 확인합니다.

## Godot판 조정과 개발 순서

원본 추출 데이터는 출처를 보존하고, Godot판 밸런스·규칙은 별도 설정에서 적용합니다.
숲 1장의 저장·재도전, 전투·성장, 의뢰·보스, 탐험, 선택형 동굴, 모바일·웹 마감 순서로 완성합니다.
각 기능은 리뷰·전체 검사·웹 빌드·필요한 브라우저 검증 후 main에 커밋하고 푸시합니다.
배포 워크플로와 공개 페이지를 확인한 뒤 다음 기능으로 진행합니다.

## 데이터 재생성

```sh
python3 tools/extract/extract_data.py /path/to/sjrpg            # skills · gear · village · landmarks
python3 tools/extract/extract_data.py /path/to/sjrpg --only=gear
```

원본 추출 뒤 `town_art.merge()`와 `landmark_art.merge()`로 Godot판 실측값을 합칩니다.
건물 4종·예배당은 `town_art_measure.json`·`chapel_measure.json`, 언덕·정원은 `landmark_art_measure.json`,
성문·성벽은 `gate_measure.json`이 출처입니다. 원화 재패킹·투영 보정·실제 모서리 검증 절차는
[원화 규격과 재생성](chapel-regeneration.md)을 따릅니다. `assets/source/`는 `.gdignore`로 번들에서 제외합니다.
`ArtWarp`의 보정 메시를 그리기와 충돌 좌표에 함께 적용하며, 성벽은 성문 날개벽을 재질 기준으로 만든 석재·거친 표면의 원화를 석재 앞면 표본 색에 맞춰 패킹하며, 비율을 유지하고 끝 반복만 자릅니다.

## 전투 조정

`ForestBalance`에 Godot 숲의 지역 레벨·마을 주변 완화·생성 간격을 둡니다. 추출 데이터는 수정하지 않습니다.
`SkillDefs.cooldown()`이 시전 판정·주/보조 버튼의 남은 시간·스킬 상세의 재사용 시간을 공유합니다.
공격 동작·재사용 대기 중의 반복 입력은 알림 대기열에 추가하지 않습니다. 버튼의 남은 초·원형 가림막으로 준비 상태를 표시하며 자원 부족 안내는 유지합니다.
원본의 양수 쿨타임은 유지하고 마나만 소모하던 주문은 `SPELL_COOLDOWNS`의 1–5초를 적용합니다.
시간은 `Player.cooldowns`에서만 줄이며 일시정지·슬롯 교체에도 같은 주문의 시간을 유지합니다.
`Gear.melee_profile()`의 월드 사거리·반각·공격 간격을 실제 근접 기본 공격과 가방·스킬 설명이 공유합니다.
무기의 공격속도와 일시적인 연격 강화는 공격 간격에 반영합니다. 대장간은 실패 시 비용만 소비합니다.
보호 의뢰의 습격자는 보통 가까운 조사관·영웅을 노리지만, 도발 중에는 살아 있는 영웅을 우선합니다.
도발 만료·영웅 사망 시 조사관을 다시 공격할 수 있으며 기존 공격력 감소도 유지합니다.

명중 시 `ActorSprite`는 접촉 자세만 40–65ms 유지하며 실제 공격·AI·충돌 시간은 멈추지 않습니다.
공격자 자세 유지는 실제 근접 타격 콜백에만 적용해 지속 마법·반격이 다른 공격을 멈추지 않게 합니다.
100ms 재진입 제한으로 연속 피해의 자세 고착을 막고, 새 동작·구르기·사망·부활은 유지 상태를 해제합니다.
적의 그림은 5/8px 이내 감쇠 반동으로 돌아오며 투사체는 진행 방향을 따릅니다. 강한 접촉음도 기존 음성 수·연타 제한을 공유합니다.
동작 줄이기에서는 자세 유지·반동을 억제합니다.


투사체는 수명의 남은 시간만 이동하며 실제 이동 선분과 적의 원형 판정을 연속 검사합니다. 접촉 순으로 처리해 비관통은 첫 접촉에 멈추고, 관통의 같은 대상은 다시 맞지 않습니다. 상자도 같은 구간을 검사합니다.
`Player._cancel_actions()`가 사망·부활에서 예약 콜백·공격·구르기·유지 입력을 해제하고, 행동 번호가 이전 준비광을 무효화합니다. 연쇄 번개는 적을 약한 참조(`WeakRef`)로 보관하고 실행 시 생존·사거리를 다시 확인합니다.
`Enemy.take_damage()`의 `visual_source`는 속성 피격·장식 반동에만 사용합니다. 지속 피해는 기존 `source=null`을 유지해 물리 밀려남·무기 효과를 추가하지 않습니다. 실제 발사광·구르기 잔상은 장식 한도에 포함하며 동작 줄이기를 따릅니다.
카메라는 확인된 명중 즉시 작은 충격을 표시하고 첫 감쇠만 제한합니다. 이후 정상 시간으로 감쇠하므로 느린 프레임에서 첫 표시가 사라지거나 흔들림이 지속되지 않습니다.
임시 기술 등급 강화는 새 모험과 정상 불러오기에서 초기화하고, 불러오기 실패 시 현재 상태는 유지합니다. 읽을 수 없는 저장·백업·임시 파일도 교체 확인을 거칩니다.
검사 도구는 테스트의 실패 수뿐 아니라 엔진 `ERROR` 로그도 실패로 처리합니다.

## HUD 헤더 배치

`Hud.header_geometry(view, safe_margins)`가 안전 영역·초상화·세 막대·숫자 영역·미니맵 배치를 공유합니다.
오른쪽 프레임과 각 막대는 같은 사선과 여백을 사용하고, `HudArt._bar_poly()`가 부분 채움을 사선에 맞춰 자릅니다.
체력 잔상도 같은 채움 다각형을 사용합니다. 채움 비율은 초상화의 테두리·그림자를 제외한 실제 가시 구간에서 계산합니다.
`HudArt.text_in_rect()`는 글꼴의 실제 폭과 수직 치수로 숫자를 중앙에 맞추며, 상태·목표 문구는 폭을 넘기면 줄임표를 사용합니다.
`Minimap.paint_bounds()`는 원 테두리·그림자·나침반의 실제 범위를, `marker_fits()`는 점 전체의 원 내부 배치를 검사합니다.
자세한 좌표 기준과 웹 검수 장면은 [UI 디자인 기준](ui-reference.md)을 참고합니다.

## 분수·게이트와 워프

분수 배율은 `Village._build_plaza()`의 2.4(이전 1.44)이며 석조 기단의 접점 다각형도 같은 투영을 사용합니다.
게이트는 분수·미라와 독립적으로 접근할 수 있도록 배치하고, `Village.portal_points`가 숲 마을·고목·동굴 입구의 공통 기준입니다.
`PlazaWater`는 기존 아틀라스의 물·소용돌이 픽셀만 움직입니다. 석재의 정점·원화 모서리는 유지하고, 별도의 게임 시간으로
위상을 갱신해 일시정지·동작 줄이기 설정을 따릅니다. 공통 가림 처리는 `world_occlusion.gdshaderinc`를 공유하며
`WorldOcclusion`은 애니메이션의 원래 재질을 보존·복원합니다. 보스 진입문·동굴 귀환문도 같은 소용돌이를 사용합니다.
`Exploration`이 목적지 해금·100px 게이트 거리·전투/진행 제한과 안전한 도착점을 검증합니다.
`WarpGatePanel`은 제1장 세 목적지의 현재/발견/미발견 상태를 표시하며, 선택 시에도 이동 조건을 다시 검사합니다.
이동하면 입력·예약 공격·구르기·카메라 충격을 해제하고 회복·저장·효과음·생성형 빛 연출을 적용합니다.
`--scene plaza`는 애니메이션 연속 화면, `--scene warp_trip`은 실제 목적지 버튼을 누른 전후 화면을 캡처합니다.
워프 검증은 방문 코드로 목적지를 발견하고 버튼의 실제 화면 좌표를 읽어 누르며, 이동 결과를 조작하지 않습니다.

`assets/source/corpses.png`는 기존 몬스터 외형을 기준으로 생성한 쓰러진 몸 5종입니다.
`python3 tools/prepare_corpse_art.py`로 투명 여백을 정리하고 `assets/art/actors/corpses.webp`(5×256px)로 패킹합니다.
`CorpseArt`는 원화를 사망 위치의 바닥에 배치하며 기존 코드로 그리던 원·교차선 시체 표시를 대체합니다.
일반 바닥·다리에서는 배우 아래에, 높은 마당·랜드마크에서는 해당 바닥 위에 정렬해 원화에 가려지지 않게 합니다.
처치마다 하나의 레코드가 그림과 사용 판정을 함께 보관합니다. `Game._tick_corpses()`가 숲·동굴에서 활성 맵의 시간을 줄이며,
기존 시체 기술의 활용 시간을 유지하는 30초 수명과 마지막 3초의 페이드를 공유합니다. 일시정지 중에는 수명도 멈춥니다.
기존 30%의 시체 기술 대상 확률은 `searchable`로 유지하고, 그림은 모든 처치에 남깁니다. 최대 32개를 유지하며
소비·만료·오래된 시체 정리·동굴 퇴장 시 레코드를 무효화해 지연된 기술이 같은 시체를 다시 사용하지 못하게 합니다.

## 월드 화질

새 원화는 먼저 [아트 기준](art-direction.md)과 [생성 프롬프트](art-prompts.md)를 읽고 사용자 원본과 같은 패밀리의 검수된 원화를 실제 생성 참조로 사용합니다. 스타일 컨셉과 게임용 투영 검증을 구분합니다.

숲의 [전체 화면 기준](forest-reference.md)은 `ForestArt`의 생성형 지면·식생을 사용합니다. `prepare_forest_art.py`가 원본을 패킹하고 `forest_art.json`이 해시·접점을 고정합니다.
배경 잔디·포장·흙길은 같은 투영을 유지하며 길·건물 가장자리의 낮은 식생만 추가합니다. 별도 장식 난수를 사용하고 충돌은 추가하지 않습니다.
기본 카메라는 짧은 변 720에서 1.0이며 플레이어 원화 높이는 84입니다. 게임 수치와 충돌은 유지하고 두 화질은 같은 시야를 공유합니다.
성공한 원소 시전의 손끝 준비광과 투사체 핵은 기존 생성형 원화를 재사용하며 기존 장식 한도·일시정지·동작 줄이기를 따릅니다.

기본 화질은 기존 주 뷰포트에 월드를 직접 그립니다. 절약 화질에서만 월드·카메라·동굴을 별도 SubViewport로 옮기고
HUD·패널은 주 뷰포트에 유지합니다. `Game.scene_root`/`scene_view`가 현재 월드의 부모와 뷰포트를 가리킵니다.
설정의 절약 화질(`Prefs.low_resolution`, 기본 false)은 월드 렌더링 크기를 가로·세로 절반으로 낮춥니다.
카메라 배율도 함께 조정해 보이는 월드 범위와 조작 좌표를 보존합니다. 기기 설정에 저장하며 진행 저장 형식은 바꾸지 않습니다.
뷰포트 컨테이너는 일시정지 중에도 크기를 갱신하지만 자식 월드의 배우들은 일시정지를 따릅니다.
캡처 시 `node tools/screenshot.mjs --scene town --device phone --quality low`로 선택할 수 있습니다.

`node tools/benchmark.mjs --quality high|low --device desktop|phone|phone-landscape`은 같은 시작 위치에서
실제 월드 그리기·렌더링 크기를 확인하고 6초 준비 후 6초 동안 브라우저 프레임 진행과 95백분위 프레임 간격을 기록합니다. 기본 렌더러는 SwiftShader이며,
실제 기기 성능을 뜻하지 않습니다. `?benchmark=1`에서만 `RenderProbe` 진단을 활성화합니다. 플랫폼 기본 렌더러 비교에는 `--renderer default`를 사용합니다.

## 가림·모바일 표시

승인된 HUD의 비율·재료·자산 제작 기준은 [UI 디자인 기준](ui-reference.md)에 있습니다.
빈 슬롯과 조이스틱은 배경이 비치도록 표시하고 상호작용은 42px 명판으로 줄입니다. 실제 터치 영역은 64px 이상을 유지하며 작은 표시 바깥을 눌러도 동작합니다.

`UiKit.style_button()`은 팝업의 기본·선택·주요 행동·포커스·비활성 상태를 구분합니다.
`UiKit.MetalSkin`이 청동 이중 테두리·미세한 가죽 질감·빛 받는 모서리를 그리며 본문은 크림색으로 표시합니다. HUD 숫자는 Regular 글꼴과 얇은 그림자를 씁니다.
`PanelFrame.set_compact()`는 대화·확인·보스·동굴 안내를 내용 높이에 맞춰 중앙 배치합니다.
가방·설정·스킬은 넓은 틀을 사용하며 회전 시 이전 최소 크기를 지워 새 화면에 맞춥니다.
제목·부제는 10px, 헤더·본문·푸터는 18px, 카드 제목·설명은 8px 간격을 공유합니다.
compact 높이는 실제 헤더·탭·푸터 최소 크기를 측정하며 본문에 최소 96px를 남깁니다.
닫기는 64×64로 유지하고, 행동 버튼의 최소 폭 합이 프레임을 넘으면 세로 배치합니다.

`WorldOcclusion`의 공유 셰이더와 인스턴스 정렬 높이로 주인공 앞 원화의 몸 주변만 투명하게 합니다.
장면의 원화·충돌·깊이 정렬은 유지하며, 높은 지형 윗면에서는 가림 완화를 끕니다.
셰이더 인스턴스는 주인공 몸과 겹치는 앞쪽 원화에만 할당해 모바일 버퍼 한도를 피합니다.
표시 전용 효과는 최대 64개, 시체는 최대 32개로 제한하며 투사체·피해 구역·소환물은 표시 제한으로 제거하지 않습니다.
`Hud.status_geometry()`는 승인된 714×1280 레퍼런스에서 잰 상단 비율을 사용합니다. 터치 조작은 안전 여백을 반영하고 물약·구르기·메뉴도 64px 이상의 터치 영역과 별도 표시 반지름을 사용합니다.
상태 헤더는 화면 배율의 0.82를 따로 적용해 초상화·막대·숫자·목표·강화 효과를 함께 줄입니다. 미니맵과 터치 조작은 화면 배율을 유지합니다. 레벨 메달은 헤더 기준 32px로 초상화 테두리에 겹치고 숫자는 최대 16px에서 실제 폭에 맞춥니다.
초상화 왼쪽 위의 레벨 메달은 원본 `sjrpg/docs/art/level-badge-original.png`를 재사용합니다.
`Hud`가 실제 `GameState.level`을 갱신하고 세 자리 이상도 메달 안에 맞춥니다. `level_badge`는 실제 경험치 레벨업·저장 복원·새 모험과 안전 여백을 검사합니다.
`tools/prepare_ui_art.py`는 `assets/source/`의 새 마법사 초상화·가죽·물약·레벨 메달을 패킹합니다. 메뉴의 검·가방·일지·설정 원형 원화는 원본 `reference-battle-buttons.webp`에서 가져오며 글자 대체 아이콘은 사용하지 않습니다. 설정의 동작 줄이기는 장식 회전과 HUD 맥박을 고정합니다.
패널의 글자 배율은 실제로 열린 패널을 기준으로 복구합니다. 미니맵은 캐시한 도형 경계로 먼 지형의 교차 계산을 생략합니다.

## 바람 동굴

`DungeonLayout`의 투영 다각형을 실제 바닥·이동 충돌·두 지도가 공유합니다. 전투 구역 5개와 두 번의 분기·합류가 있습니다.
`DungeonRuntime`은 숲 루트를 숨기고 처리를 멈춘 뒤 플레이어를 임시 월드로 옮깁니다. 적·상자·시체·지도 상태는
공간별로 분리하고, 퇴장 시 플레이어를 돌려놓은 뒤 동굴 노드를 폐기합니다. 입장 전 미완료 공격도 취소합니다.
적 레벨은 입장 때 고정하며 동굴 처치는 숲 의뢰에 보내지 않습니다. 시체·전리품·경험치는 기존 전투를 재사용합니다.
동굴 적의 `patrol_center`/`patrol_radius`는 대기 중 배회만 방 중심 170px 이내로 제한합니다.
추적·공포 이동은 제한하지 않으며 일반 필드에는 적용하지 않습니다. 방문 전 다른 갈림길로 적이 흩어지는 일을 줄입니다.
`location_mode`만 저장하고 동굴 인스턴스는 저장하지 않습니다. 재접속 시 입구로 복귀하며, 보호 의뢰·보스 도전 중 입장은 막습니다.
`DungeonPanel`은 입장·완료·퇴장을 제공하고 설정에서도 중도 퇴장할 수 있습니다.

동굴의 [완성 디자인과 원화 제작 기준](cave-design.md)은 `assets/source/cave-design.png`가 정본입니다.
`DungeonArt`가 파생한 석재 바닥·높은 암벽·낮은 돌턱·열린 아치·등불 원화를 실제 이동 다각형에 배치합니다.
외곽벽은 방·통로 합집합의 바깥 경계에만 놓고 월드 깊이 정렬·가림 완화를 공유합니다.
등불의 지역 조명은 일시정지와 동작 줄이기를 따릅니다. `cave_art.json`은 원본·배포 원화 해시를 보관하고,
`prepare_cave_art.py`와 `cave_art.merge()`로 원화·외부 입구 데이터를 재생성합니다.
`dungeon_art`는 실제 바닥·지도·벽과 조명·화질 전환·수명을 검사합니다.
`dungeon_preview=entry|room|branch|exit`는 실제 동굴에 입장한 뒤 구도를 고정하며,
`tools/screenshot.mjs --scene cave_entry|cave_room|cave_branch|cave_exit`로 가로·세로를 비교합니다.

## 탐험·지도·안식처

`MapGeometry`가 마을 포장·강·다리·벽·건물 바닥·랜드마크 윗면·물 경계에서 두 지도에 쓸 도형을 만듭니다.
`MapPanel`은 전체 지도와 안식처 이동 탭을 제공하며, 의뢰 상태에 따라 목적지 표식을 갱신합니다.
`Exploration`은 직접 방문한 안식처를 해금하고 `last_sanctuary`에 부활·재접속 위치를 기록합니다.
이동은 안식처 근처에서만 가능하며 주변 적·보호 의뢰·보스 도전 중에는 막습니다. 도착점은 실제 충돌로 검사합니다.
폭포는 기존 `landmarks.json`의 네 번째 측정값을 사용하며 상자 ID 8을 추가합니다(기존 기억 상자 5–7 보존).

## 목표와 근처 상호작용

`Quests.next_quest()`는 보호 진행·보호 완료 보고를 우선하고, 다른 완료 보고·수락·재도전·새 의뢰 순으로 안내합니다.
같은 상태에서는 마을 배달 → 석조 정원 → 조사관 순서이며, 사용자가 다른 의뢰를 먼저 수락하면 그 진행을 존중합니다.
`Game.near_npc()`는 NPC·동굴·안식처 중 가까운 대상을 고릅니다. 분수 부근 안식처가 더 가까운 주민 대화를 가로채지 않습니다.

## 파수꾼 도전

의뢰 3개 완료 시 서쪽 고정 공터에서 `QuestRuntime.start_boss()`로 도전합니다. 별도 처치 수 조건은 없습니다.
사망·1100px 이상 이탈 시 적을 제거하고 재도전을 허용하며, 재접속도 새 도전으로 시작합니다.
보스 예고 타원의 세로 배율과 실제 공격 거리 계산을 일치시킵니다. 고유 보상은 가방이 가득 차면
`boss_heart_pending`으로 저장하고 가방을 비운 뒤 패널을 닫을 때 지급합니다.

## 저장과 재접속

게임은 창·앱의 포커스 이탈과 앱 중단 알림에서 터치·키보드 입력을 해제하고 저장합니다.
열린 패널이 없으면 `Hud.pause_for_background()`로 재개 안내를 열며, 기존 패널은 유지합니다.
포커스 복귀만으로는 재개하지 않습니다. 지연 회전 공격·기억 표시·승리 표시·부활의 SceneTreeTimer도
`process_always=false`로 만들어 일시정지를 따릅니다. `tools/screenshot.mjs --scene background`는 실제 캔버스 blur를 발생시킵니다.

`SaveStore`는 임시 파일에 작성·flush 후 교체하며, 읽을 수 있는 직전 저장만 `.bak`으로 보존합니다.
`GameState.save_game()`은 성공 여부를 반환하고 `save_finished(success, message)`를 알립니다.
HUD는 실패 시 누를 수 있는 재시도 안내를 유지하며 설정의 수동 저장도 실패를 표시합니다.
버전 없는 기존 Godot 저장을 지원하고, 미래 버전과 잘못된 컨테이너는 적용 전에 거부합니다.
중단된 조사관 보호는 습격 노드를 복구하는 대신 수락 상태로 되돌려 재시작합니다.
새 모험 준비·취소는 기존 저장을 지우지 않습니다. 장면 교체 시 이전 장면은 즉시 처리를 중지해 교체 프레임에 진행을 바꾸지 못하게 합니다.
기억 상자 개봉과 일회성 스킬 포인트 보상은 함께 저장하며, 이전 저장에 상자 3개만 기록된 경우 누락 보상을 복구합니다. 테스트 러너는 별도의 `user://tests/` 경로를 사용합니다.

## CI와 배포

`.github/workflows/web.yml`이 모든 푸시에서 `tools/setup_godot.sh` → `tools/check.sh --export`를 실행하고, `main`이면 `build/web`을 Pages에 배포합니다.

## 전투 피드백

`Effect.spawn_impact()`는 실제 피해 확정 뒤에만 생성형 4칸 원화(`assets/source/impact-atlas.png` → `assets/art/effects/impact-atlas.webp`)를 가산광으로 짧게 표시합니다. 기존 장식64개 한도를 공유하며 투사체·피해 영역과 분리합니다. 적의 반동은 스프라이트 위치에만 적용합니다. `Game.combat_feedback()`는 근처 명중에만 최대6px의 감쇠하는 카메라 오프셋을 더하며 시간 배율을 바꾸지 않습니다. 동작 줄이기는 이 움직임을 끕니다.
HUD는 체력·물약 수·쿨다운의 실제 변화를 감지합니다. 사운드의 작은 피치 변화는 별도 난수기를 써 전투 난수에 영향을 주지 않습니다. `juice` 테스트는 실제 피해·무적 중 중복 반응 방지·모션 설정·장식 한도를 검사합니다.
`tools/screenshot.mjs --scene juice --class mage --device phone`은 명시적인 `combat_preview=1` 쿼리로 반복 명중을 재현하고 연속 화면을 저장합니다. 일반 모험에는 이 미리보기를 실행하지 않습니다.

`RewardFx`는 확정된 상자 골드·희귀 장비·처치 XP·레벨업에만 생성형 3칸 원화(`reward-atlas.webp`)를 표시하고 장식64개 한도를 공유합니다. 여러 레벨을 한 번에 올려도 레벨업 효과는 한번입니다. 알림은 HUD의 청동 명판과 최대4개 대기열로 전달하며 중복을 억제하고8초 지난 대기 알림은 버립니다. 패널 일시정지는 알림 수명도 멈춥니다. `rewards` 검사는 중복 보상 방지와 알림 순서·한도를 검증합니다. `tools/screenshot.mjs --scene rewards --device phone`은 명시적인 `reward_preview=1`에서 실제 상자와 레벨업 경로를 재현합니다.

보상 캡처 미리보기는 확정 직후 장면을 멈춰 원화의 위치·크기를 검토합니다. 일반 플레이의 수명·이동·일시정지는 `RewardFx`와 `rewards` 검사로 별도로 확인합니다.
