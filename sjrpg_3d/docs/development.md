# 개발 참고

`web/fullscreen.js`는 웹의 실제 Fullscreen API와 설치 실행 모드를 구별합니다. 설치 실행 여부는 DOM 전체화면 요청 전에 캡처하므로 일반 브라우저의 전체화면을 설치로 오인하지 않습니다. manifest는 `fullscreen`을 기본으로, `standalone`을 대체 모드로 지정합니다. 설치 앱이 `standalone`으로 대체되고 API가 지원되면 첫 신뢰된 터치/키 입력에서 한 번 전환하며 이후 수동 해제를 존중합니다. iOS 등 API 미지원과 앱 manifest 전체화면의 해제 불가 상태는 설정에 그대로 안내합니다. `Prefs`는 웹에서 이 브리지를 동기 호출하고 네이티브에서는 `DisplayServer`를 사용합니다. `SettingsPanel`의 최상단 버튼은 비동기 전환·외부 전체화면 변경을 실제 상태로 갱신합니다. `fullscreen_settings`는 폰 회전/일시정지/미지원 처리를, `node web/check_fullscreen.mjs`는 실제 DOM 전체화면의 입력 진입/해제와 명시적 설치 실행 픽스처를 검사합니다. `check_install.mjs`는 실제 제공 manifest/worker를 확인합니다. 설치 앱을 실제 기기에 설치했다는 검증은 아닙니다. 기존 고정 크기 Canvas CSS와 네 저장 슬롯은 변경하지 않습니다.

성문 개폐와 게임 표시는 `Ortho3DFortification`·`Ortho3DPreview`·`SettingsPanel`이 담당합니다. 성문 두 날개는 각 통로에 가장 가까운 실제 `Village.safe_zone` 경계의 외향 법선으로 회전 방향을 정하므로 네 방향 모두 마을 밖으로 열립니다. 기존 힌지·닫힌 이음새·네이티브 충돌·위협 자동 닫힘·주인공 접근 허용은 유지하고 `TownGateRuntime.progress/closed`만 관찰합니다. `ortho_3d_fortification`은 네 문 × 양 날개의 닫힘/반열림/완전 열림 상태에서 실제 목재·철물 메시의 모든 정점과 고정 힌지·두께 경계를 검사합니다. 게임의 표시 방식 배지는 생성하지 않으며 HUD 확인문은 상태창과 미니맵 사이 여백을 사용합니다. 설정은 모험 저장·선택 화면 복귀 안내만 제공하고 현재 표시 방식 문구는 생략합니다. `native_product_labels`가 숲·동굴·설정·귀환의 실제 보이는 글자를 검사합니다.

엔진 기준은 **Godot 4.7.2 / GL Compatibility**입니다. `.godot-version`을 로컬 실행·설치 도구와 CI가 공유하며,
`tools/setup_godot.sh`는 해당 버전의 실행 파일과 웹 템플릿을 함께 설치합니다. 다른 버전을 명시적으로 검증할 때만 `GODOT_VERSION`을 재정의합니다.

현재판은 `NativeAdventure`를 진입점으로 사용하는 독립3D 프로젝트입니다. `SpatialWorld3D`가 실제 배우 몸체·지형·성문·충돌을, `SpatialCombat3D`가 실제 높이·벽·몸체에 따른 공격 판정을 담당합니다. `Game`과 원본2D 노드는 규칙·UI·개별 원화의 어댑터입니다. 원본 Canvas 부모는 첫 프레임부터 숨기고 다시 표시하지 않습니다. 이동/전투 처리는 계속하며 개별 원화의 로컬 표시 플래그는3D 카드가 사용합니다. 그림용 `Polygon2D`를 회전 중 다시 그리는 Godot4.7.2 WebGL 버퍼 오류를 피합니다.

## 네이티브 주택

`NativeHouse3D`는 `Ortho3DPreview._build_house()`의 비예배당 네 건물을 생성합니다. 기존 기단 위치/폭/깊이와 닫힌 본체 충돌은 유지하며 공통 재질5개에 실제 기하를 합칩니다. 문/창 개구부·지붕창·모서리·미터 경계는 `native_house_family` 검사와 `assets/source/preview3d/houses/provenance.json`에서 확인합니다. 재질·예산 예외와 검수 범위는 [주택 패밀리](native-house-family.md), 전체 규격은 [3D 제작 기준](../../docs/3d-asset-guide.md)을 따릅니다.

## 직교3D 표시

`Ortho3DPreview`라는 기존 이름은 공간 표시기이며 비교 모드가 아닙니다. 마을·숲·기존 동굴 모두3D 물리와 표시를 유지합니다. 설정에는 렌더러 전환이 없고 웹에서 저장 후 루트 버전 선택 화면으로 돌아가는 버튼만 있습니다. 이전 `LaunchMode`와 `Prefs.town_3d`는 제거했습니다.

카메라는 직교 방위45°·고도35.264°이며 햇빛·반사광·접촉광을 실제3D 표면에 적용합니다. `ortho_3d_preview`는 실제 투영·공격 진행·카드 반동·명중광·그림자 구간을, `world_light_feel`은 실제 공간 광원·일시정지·동작 줄이기·영역 전환을 검사합니다. Canvas 조명 셰이더 검사는2D판에 남깁니다. 웹 회전 검사는 루트 `tools/check_native_web.sh`를 사용합니다.

`Ortho3DTrees`는 마을 나무의 실제 투영 크기와 발치를 공유 GLB 두 개로 유지합니다. `Ortho3DFortification`은 성문·벽을 같은 석재와 접점으로 연결하고 실제 `TownGateRuntime.progress`로 문짝 힌지를 갱신합니다. 움직이는 메시는 정적 배칭에서 제외합니다. 생성형 평면 재질·원본 기록은 `assets/source/preview3d/`에 보존합니다. 옛 [비교 장면 문서](orthographic-3d-comparison.md)는 제작 이력이며 현재 구조의 근거는 [루트 개발 안내](../../docs/development.md)와 [3D 에셋 기준](../../docs/3d-asset-guide.md)입니다.

웹 PCK와 다운로드 화면의 배경은 각각 콘텐츠 해시 파일명을 사용합니다. `tools/stamp_web.py`는 배포 폴더의 `loading-bg.webp`를 `loading-bg-<hash>.webp`로 바꾸고 preload/CSS 참조를 함께 갱신합니다. PCK가 그대로여도 배경 바이트가 바뀌면 새 URL을 사용하며, 다시 실행해도 같은 결과를 유지하고 이전의 소유한 해시 파일만 정리합니다. 원본 `web/shell.html`과 셸 모의 검사는 정규 배경 이름을 그대로 사용합니다. 각 앱은 자기 경로의 HTML·엔진·PCK를 열고 저장 마운트도 분리합니다. 루트의 옛 비교 북마크는3D 전용 경로로 연결되며 실행 중 표시 방식을 바꾸지 않습니다.

## 게임패드 입력

자동 로드 `Gamepad`는 Xbox 표준 조이스틱 이벤트와 연결 상태를 읽고, 키보드·터치와 분리된 이동·조준·스킬 유지 상태를 관리합니다. 원형 데드존과 트리거 히스테리시스를 사용하며 연결·포커스·메뉴·사망 전환 뒤에는 중립 입력을 확인합니다. 패드 입력을 키보드의 공격 액션으로 주입하지 않으므로 UI에서 누른 A/B가 공격·구르기로 이어지지 않습니다.

`GamepadNavigation`은 실제 처리 가능한 최상위 패널 또는 타이틀·저장 선택 화면을 포커스 범위로 사용합니다. 로딩 레이어의 `entry_loading` 그룹은 준비 완료와 화면 닫힘 사이에도 전투·메뉴 조작을 막습니다. 선택 가능한 실제 컨트롤만 탐색하고 스크롤 영역 안의 항목을 드러내며, 재구성되는 장비·설정은 의미 있는 키로 포커스를 복구합니다. 스킬 그래프와 장비 칸은 기존 선택 콜백을 사용하는 투명 포커스 버튼을 갖습니다. 오른쪽 스틱은 메뉴에서 조준 대신 스크롤을 담당합니다.

`Player`는 패드의 아날로그 이동을 기존 화면 투영 좌표에 한 번만 적용합니다. 수동 조준 중에는 기존 최근접 적 선택이 스틱 방향을 덮지 않으며, 대상 지정 이동 스킬은 전방에 선택된 대상의 실제 위치를 사용합니다. 기존 피해·쿨타임·충돌·자원 검사는 동일한 스킬 API를 통과합니다. 입력별 버튼 표는 README에 기록합니다.

## 로딩과 수호자 선택

`web/shell.html`은 생성된 어두운 숲 일러스트 위에 실제 다운로드 진행률·한국어 제목·청동 버튼을 표시합니다. 다운로드와 준비 완료는 같은 DOM/배경/제목 배치를 유지하며, 엔진과 `TitleScreen`의 시작 콜백이 모두 준비되어야 버튼을 활성화합니다. 가로 화면은 우측 행동 영역, 세로 화면은 하단 행동 영역으로 재배치합니다. 웹 캔버스는 고정된 전체 화면 크기로 제한해, 가로→세로 회전 후 그리기 버퍼의 고유 폭이 모바일 레이아웃 뷰포트와 터치 좌표를 확대하지 않게 합니다.

`EntryUi`는 `assets/art/entry/`의 배경과 두 투명 캐릭터 일러스트를 읽고, 텍스트·버튼은 실제 컨트롤로 구성합니다. 원본 PNG·정확한 생성 지시·해시는 `assets/source/entry-redesign/`에 보존합니다. `tools/prepare_generated_entry.py`가 형식만 변환하며 `web/prepare_art.py`는 동일한 배경 바이트와 새 전사 그림의 설치 아이콘을 패킹합니다. 원본 이미지의 얼굴·손·발은 자르지 않고 비례를 유지합니다. `web/.gdignore`로 웹 전용 파일을 PCK에서 제외합니다.

`ClassSelect`는 네 저장 슬롯의 `slot_summaries()`만 읽어 미리보기를 만듭니다. 기존 모험은 명시적인 이어 하기에서 `select_slot`/`load_game`을 호출하고, 빈 슬롯의 명시적인 시작만 `create_slot`을 호출합니다. 점유되었거나 읽을 수 없는 슬롯은 새로 덮어쓰지 않으며 슬롯별 삭제 확인을 거칩니다. 저장 시간의 Unix초는 변경하지 않고 `SaveTimeLabel`이 표시할 때만 로컬 오프셋을 더합니다. 웹은 저장 시점의 브라우저 오프셋(DST 포함), 네이티브는 운영체제의 분 단위 timezone bias를 사용합니다. 네 슬롯의 경로·이관·자동 저장 정책은 [저장 슬롯](save-slots.md)을 참고하세요.

`main.gd`의 모험 진입은 `EntryLoading`을 먼저 표시한 뒤 저장 읽기·새 저장 생성·월드 준비를 순서대로 실행합니다. 웹은 두 번의 실제 브라우저 그리기 콜백을 확인한 후 동기 작업에 들어가므로, 월드 생성 중에도 로딩 화면이 먼저 보입니다. 진행률을 측정할 수 없는 작업에는 퍼센트 대신 회전 아이콘과 단계 안내를 사용합니다. 준비 완료는 실제 `simulation.native_ready`와 첫 월드 표시를 기준으로 합니다. 진입 토큰과 입력 차단은 중복 시작을 막고 선택 화면을 떠난 대기 작업을 취소합니다. 저장 실패는 로딩 표시를 정리한 후 기존 선택 화면에 안내합니다. `entry_loading`은 실제 슬롯 파일을 사용해 중복 시작·읽기/생성 실패·취소와 재시도를 검사합니다.

`entry_layout`은 두 방향·작은 창·회전의 실제 컨트롤 경계, 원본 알파·배경 일치, 미리보기의 저장 바이트 보존, 확인/취소, 반복 시작 방지를 검사합니다. `web/check_shell.mjs`는 로딩/준비의 동일 배치와 오류 복구를 검사합니다. `window.__sjrpgClassButtons`는 실제 버튼 중심과 슬롯 요약을 공개하며 기존 `warrior`/`mage`/`start`/`continue`/`back` 외에 `slots`, `slot1`~`slot4`, `delete1`~`delete4`, 모달의 `delete_cancel`/`delete_confirm`을 제공합니다. `slot_labels`는 실제 저장 행 문자열을 제공하며 미리보기 데이터는 바꾸지 않습니다. `TitleReady`/`EntryReady`/`ClassSelectReady` 훅은 유지합니다.

## 좌표와 단위

- 실제 지면은 미터 단위XZ, 높이는Y이며 발치·바닥·충돌은 `SpatialWorld3D`를 기준으로 합니다.
- 기존 UI와 진행 데이터 좌표는 `Iso.project()`/`unproject()` 어댑터로 연결하며 지면65단위가1m입니다. 화면 평면과 실제 수직 높이의 배율은 [3D 기준](../../docs/3d-asset-guide.md)에 구분합니다.
- 네이티브 모델·광원·투사체는 실제 높이를 사용합니다. 원화 카드의 기존 `z_index`로 공간 판정을 대신하지 않습니다.
- 바닥과 경사는 가능한 한 공유 `surface_faces()` 기하를 사용합니다. 큰 프레임 이동도 실제 벽/절벽/성문을 통과하지 않는지 검사합니다.

일반 나무는 `assets/source/remake/trees-v2.png`의 참나무 두 크기·전나무·버드나무를 사용합니다.
수관 윗면·뒤쪽 가지의 가림·줄기와 뿌리 접점을 시각 검수하며, 자연형 실루엣에 건물의 직선 모서리 각도 검사를 적용하지 않습니다.
`tools/extract/tree_art_measure.json`에 원화 영역과 줄기-지면 접점 중심을 기록하고,
`python3 tools/prepare_tree_art.py` → `extract_data.py /path/to/sjrpg --only=village`로 재생성합니다.
`tree_art.merge()`가 기존 나무 ID의 높이를 보존해 새 그림에 연결합니다. `tree_art` 검사는 리뷰한 원본·아틀라스 해시와 실제 필드의 발치·충돌을 확인합니다. 생성 시 기존 나무 그림은 높은 수관과 가림 구조의 참조로만 사용하며 최상위 스타일은 사용자 원본입니다.

## 전투 조정

기술별 발광 원화·접점·생성 기록·기술 연결은 [이펙트 제작 기준](skill-effects-reference.md)을 따릅니다. `ReferenceFxArt`가 6종×4단계 원화를 공유하고 `Effect`의 `skill_fx`는 장식 예산·일시정지·동작 줄이기·첫 느린 프레임 보호를 사용합니다. `Player`는 실제 기술 콜백에서만 생성하며, 유성 충돌은 기존 `zone`의 `impacted` 전환에 연결합니다. `reference_fx`는 원화 해시/여백/잔광과 실제 피해·회전 취소·착지·투사체·유성 지연을 검사합니다. `fx_preview`/스크린샷의 `fx_*` 장면은 기존 기술을 실제 시전한 뒤 검수용으로 일시정지합니다.

`ForestBalance`에 Godot 숲의 지역 레벨·마을 주변 완화·생성 간격을 둡니다. 일반 적은 2초 간격으로 마을 주변 10·먼 숲 16마리까지 보충하며, 비석 무리를 포함한 일반 필드 생존자 상한은 30마리입니다. 추출 데이터는 수정하지 않습니다.
`EncounterRuntime`은 숲 6곳의 첫 무리·충전·휴면·저장과 실제 공격 접촉을 담당합니다. 원본 조사와 이식 규칙·원화 측정은 [재소환 비석](encounter-stones.md)을 따릅니다. `encounters`·`encounter_combat`·`encounter_saving`은 실제 공격, 같은 프레임의 전멸/재소환 방지, 5분 충전, 생존 적 복원을 검사합니다. `--scene stone_cast`는 두 직업의 실제 기본 공격으로 1충전 소비와 소환 결과를 확인합니다.

`GameTempo.RATE=1.5`를 이동 속도·기본 공격·스킬 재사용·몬스터 준비/회복·구르기·투사체에 적용합니다. 투사체의 속도와 수명을 함께 바꿔 사거리를 보존하고, 구르기도 거리는 그대로 두고 시간만 줄입니다. `Engine.time_scale`은 1이며 상태·회복·퀘스트·동굴·비석·UI 시간은 실제 초를 유지합니다. `tempo`는 속도·거리·접촉 정지 중 독립 시계를 검사합니다.
`SkillDefs.cooldown()`이 시전 판정·주/보조 버튼의 남은 시간·스킬 상세의 재사용 시간을 공유합니다.
공격 동작·재사용 대기 중의 반복 입력은 알림 대기열에 추가하지 않습니다. 버튼의 남은 초·원형 가림막으로 준비 상태를 표시하며 자원 부족 안내는 유지합니다.
원본의 양수 쿨타임 또는 마나만 소모하던 주문의 `SPELL_COOLDOWNS` 1–5초를 기준으로 공통 액션 템포를 적용합니다.
시간은 `Player.cooldowns`에서만 줄이며 일시정지·슬롯 교체에도 같은 주문의 시간을 유지합니다.
`Gear.melee_profile()`의 월드 사거리·반각·공격 간격을 실제 근접 기본 공격과 가방·스킬 설명이 공유합니다.
무기의 공격속도와 일시적인 연격 강화는 공격 간격에 반영합니다. 대장간은 실패 시 비용만 소비합니다.
보호 의뢰의 습격자는 보통 가까운 조사관·영웅을 노리지만, 도발 중에는 살아 있는 영웅을 우선합니다.
도발 만료·영웅 사망 시 조사관을 다시 공격할 수 있으며 기존 공격력 감소도 유지합니다.

`Villager.header_layout()`은 보호 체력바를 실제 몸 외곽보다9px 위에 놓고 이름·표식·피해 숫자도 각각 여유를 둡니다. 일반 주민의 기존 헤더는 유지합니다. `QuestRuntime.damage_defender()`는 실제 양수 체력 감소 때만 같은 NPC 원화의 몸 전용 피격 오버레이와 기존 접촉 효과를 표시합니다. 부모 색·이름·체력바·그림자와 카메라를 바꾸지 않으며, 동작 줄이기·일시정지·짧은 수명·연타 한도를 따릅니다. `tools/screenshot.mjs --scene defender --device phone|phone-landscape`는 실제 보호 의뢰와 적의 공격을 실행한 뒤 명시적 검수용으로 일시정지합니다.

명중 시 `ActorSprite`는 접촉 자세를 40–65ms 유지합니다. `GameTempo.ContactStop`은 공격자·피격자의 공격/이동 시간도 35–55ms 멈추되 상태·쿨타임·회복 시계는 진행합니다. 140ms 재진입 제한으로 정지를 무한 연장하지 않습니다.
공격자 자세 유지는 실제 근접 타격 콜백에만 적용해 지속 마법·반격이 다른 공격을 멈추지 않게 합니다.
100ms 재진입 제한으로 연속 피해의 자세 고착을 막고, 새 동작·구르기·사망·부활은 유지 상태를 해제합니다.
적의 그림은 5/8px 이내 감쇠 반동으로 돌아오며 투사체는 진행 방향을 따릅니다. 강한 접촉음도 기존 음성 수·연타 제한을 공유합니다.
동작 줄이기에서는 자세 유지·반동을 억제합니다.

`Effect.place_text()`는 실제 글꼴·외곽선·여러 줄의 범위를 측정합니다. 몬스터 피해는 타깃의 약한 참조를 따라 같은X의 세로 열에 쌓고, 이전 금액은 위로 밀어 새 금액을 발치 쪽에 표시합니다. 240단위 높이를 넘는 오래된 행을 정리하며 대상 제거 뒤에는 마지막 접점을 유지합니다. 경험치·일반 알림은 주변 아홉 위치에서 겹치지 않는 자리를 고릅니다. 금액을 합치거나 지연하지 않으며, 포화 시 새 표시와 겹치는 오래된 글자만 정리합니다. 기존 64개 장식 한도와 수명을 공유하고 동작 줄이기에서는 상승 이동을 멈춥니다. `combat_text`는 실제 지속 피해의 금액·겹침·경험치·일시정지·수명·밀집 한도를 검사합니다.

확인된 `Effect.spawn_impact()`만 `WorldLighting.pulse()`를 호출합니다. 최대 두 접촉광의 갱신은 프레임 끝에 한 번 묶고, 지면 복제 재질은 `configure()`의 별도 수신 목록으로 등록해 자체 낮빛 스위치를 유지합니다. 기본 셰이더는 접촉 계산을 컴파일에서 제외합니다. 접촉이 시작·종료할 때만 미리 준비한 셰이더로 전환하며 같은 재질 인스턴스와 모든 현재 유니폼을 보존합니다. 활성 접촉이 없으면 시계·유니폼 갱신도 생략합니다. CPU 몸 색과 공통 셰이더는 같은 세로/가로0.57735 감쇠·수명·밝기 상한을 사용하며, 레지스트리 초과 재질에는0을 기록해 고정 잔광을 막습니다. `world_light_feel`은 실제 수신값·지면 텍스처·물 위상·성문 진행값의 양 방향 복원과 일시정지·설정·수명·동굴 분리를 검사합니다. GPU의 첫 사용 컴파일 비용은 브라우저에서 별도로 확인합니다.

`Game.break_chests_in_radius/arc()`와 `EncounterRuntime.in_radius()`의 선택적 `melee` 인자는 물리 베기·회전·착지에만 같은 높이·닫힌 성문 도달 검사를 적용합니다. 마법 범위와 투사체의 기존 접촉 규칙은 유지합니다.


투사체는 수명의 남은 시간만 이동하며 실제 이동 선분과 적의 원형 판정을 연속 검사합니다. 접촉 순으로 처리해 비관통은 첫 접촉에 멈추고, 관통의 같은 대상은 다시 맞지 않습니다. 상자도 같은 구간을 검사합니다.
`Player._cancel_actions()`가 사망·부활에서 예약 콜백·공격·구르기·유지 입력을 해제하고, 행동 번호가 이전 준비광을 무효화합니다. 연쇄 번개는 적을 약한 참조(`WeakRef`)로 보관하고 실행 시 생존·사거리를 다시 확인합니다.
`Enemy.take_damage()`의 `visual_source`는 속성 피격·장식 반동에만 사용합니다. 지속 피해는 기존 `source=null`을 유지해 물리 밀려남·무기 효과를 추가하지 않습니다. 실제 발사광·구르기 잔상은 장식 한도에 포함하며 동작 줄이기를 따릅니다.
카메라는 확인된 명중 즉시 작은 충격을 표시하고 첫 감쇠만 제한합니다. 이후 정상 시간으로 감쇠하므로 느린 프레임에서 첫 표시가 사라지거나 흔들림이 지속되지 않습니다.
임시 기술 등급 강화는 새 모험과 정상 불러오기에서 초기화하고, 불러오기 실패 시 현재 상태는 유지합니다. 읽을 수 없는 저장·백업·임시 파일도 점유된 슬롯으로 보존하며 명시적 삭제 확인을 거칩니다.
검사 도구는 테스트의 실패 수뿐 아니라 엔진 `ERROR` 로그도 실패로 처리합니다.

## HUD 헤더 배치

`Hud.header_geometry(view, safe_margins)`가 안전 영역·초상화·세 막대·숫자 영역·미니맵 배치를 공유합니다.
오른쪽 프레임과 각 막대는 같은 사선과 여백을 사용하고, `HudArt._bar_poly()`가 부분 채움을 사선에 맞춰 자릅니다.
체력 잔상도 같은 채움 다각형을 사용합니다. 채움 비율은 초상화의 테두리·그림자를 제외한 실제 가시 구간에서 계산합니다.
`HudArt.text_in_rect()`는 글꼴의 실제 폭과 수직 치수로 숫자를 중앙에 맞추며, 상태·목표 문구는 폭을 넘기면 줄임표를 사용합니다.
`Minimap.paint_bounds()`는 원 테두리·그림자·나침반의 실제 범위를, `marker_fits()`는 점 전체의 원 내부 배치를 검사합니다.
충분히 넓은 가로 화면의 확인 알림은 상태창·미니맵의 실제 그리기 범위 사이 상단 여백에 놓아 중앙 전투와 NPC 체력바를 비웁니다. 세로·좁은 화면과 저장 실패 경고가 보이는 경우에는 기존 아래쪽 배치를 유지합니다.
자세한 좌표 기준과 웹 검수 장면은 [UI 디자인 기준](ui-reference.md)을 참고합니다.

## 분수·게이트와 워프

분수 배율은 `Village._build_plaza()`의 2.4(이전 1.44)이며 석조 기단의 접점 다각형도 같은 투영을 사용합니다.
게이트는 분수·미라와 독립적으로 접근할 수 있도록 배치하고, `Village.portal_points`가 숲 마을·고목·동굴 입구의 공통 기준입니다.
`Village.create_portal()`이 세 이동 게이트·파수꾼 문·동굴 귀환문에 같은 원화 배율·접점·애니메이션을 적용합니다. `_add_warp_portal()`은 세 이동 목적지만 등록하고 마을과 같은 기단 다각형을 사용합니다. 필드 게이트만 작은 별도 높이나 원형 충돌을 사용하지 않습니다. 동굴 귀환문의 기단은 `DungeonLayout.obstacles`에 등록해 숲의 충돌 목록과 분리하며, 실제 이동을 막되 귀환 상호작용의 접근점은 비웁니다. 새 비대칭 기단은 출구 방 안쪽 `DungeonLayout.EXIT + Vector2(50, -110)`의 지면 좌표에 두고, 네 실제 모서리가 벽 안쪽 20단위 여유와 진입 경로를 침범하지 않는지 검사합니다. HUD의 ‘워프 이동’ 명판은 184×56, 터치 영역은 212×76 기준이며 목적지 버튼은 96px 높이입니다. `warp_gates`·`warp_layout`은 실제 원화 배율·기단 충돌·안전한 접근점과 가로/세로의 버튼 범위를 검사합니다.
`PlazaWater`는 기존 아틀라스의 물·소용돌이 픽셀만 움직입니다. 석재의 정점·원화 모서리는 유지하고, 별도의 게임 시간으로
위상을 갱신해 일시정지·동작 줄이기 설정을 따릅니다. 공통 가림 처리는 `world_occlusion.gdshaderinc`를 공유하며
`WorldOcclusion`은 애니메이션의 원래 재질을 보존·복원합니다. 보스 진입문·동굴 귀환문도 같은 소용돌이를 사용합니다.
`Exploration`이 목적지 해금·100px 게이트 거리·전투/진행 제한과 안전한 도착점을 검증합니다.
`WarpGatePanel`은 제1장 세 목적지의 현재/발견/미발견 상태를 표시하며, 선택 시에도 이동 조건을 다시 검사합니다.
이동하면 입력·예약 공격·구르기·카메라 충격을 해제하고 회복·저장·효과음·생성형 빛 연출을 적용합니다.
`--scene plaza`는 애니메이션 연속 화면, `--scene warp_trip`은 실제 목적지 버튼을 누른 전후 화면을 캡처합니다.
워프 검증은 방문 코드로 목적지를 발견하고 버튼의 실제 화면 좌표를 읽어 누르며, 이동 결과를 조작하지 않습니다.

## 시체 원화와 수명

`assets/source/corpses.png`는 기존 몬스터 외형을 기준으로 생성한 쓰러진 몸 5종입니다.
`python3 tools/prepare_corpse_art.py`로 투명 여백을 정리하고 `assets/art/actors/corpses.webp`(5×256px)로 패킹합니다.
`CorpseArt`는 원화를 사망 위치의 바닥에 배치하며 기존 코드로 그리던 원·교차선 시체 표시를 대체합니다.
일반 바닥·다리에서는 배우 아래에, 높은 마당·랜드마크에서는 해당 바닥 위에 정렬해 원화에 가려지지 않게 합니다.
처치마다 하나의 레코드가 그림과 사용 판정을 함께 보관합니다. `Game._tick_corpses()`가 숲·동굴에서 활성 맵의 시간을 줄이며,
기존 시체 기술의 활용 시간을 유지하는 30초 수명과 마지막 3초의 페이드를 공유합니다. 일시정지 중에는 수명도 멈춥니다.
기존 30%의 시체 기술 대상 확률은 `searchable`로 유지하고, 그림은 모든 처치에 남깁니다. 최대 32개를 유지하며
소비·만료·오래된 시체 정리·동굴 퇴장 시 레코드를 무효화해 지연된 기술이 같은 시체를 다시 사용하지 못하게 합니다.

## 월드 화질

새 원화는 먼저 [레퍼런스 분위기 제작 가이드](reference-look-guide.md)·[아트 기준](art-direction.md)·[생성 프롬프트](art-prompts.md)를 읽고 사용자 원본과 같은 패밀리의 검수된 원화를 실제 생성 참조로 사용합니다. 작은 실제 플레이 장면에서 카메라·배우 비례·명암·식생을 먼저 맞추며, 스타일 컨셉과 게임용 투영 검증을 구분합니다. 투영 검사와 분위기 검수를 모두 통과해야 합니다. 가이드의 화면 목표값은 현재 구현값과 구분합니다.

숲의 [전체 화면 기준](forest-reference.md)은 `lighting/ground-materials.png`의 석회암 포장, 기존 `remake/ground.png`의 흙·`grass-v2.png`·`remake/flora.png`와 `ForestArt`의 배치를 사용합니다. `prepare_forest_art.py`가 원본을 패킹하고 `forest_art.json`이 해시·접점을 고정합니다. 새 원화의 프롬프트·실제 참조·채택/탈락 이유는 `tools/extract/ground_light_generation.json`에 보존합니다.
배경 잔디·포장·흙길은 실제 `Iso` 평면에 투영하며 길·건물 가장자리의 낮은 식생은 별도 장식 난수로 배치합니다. 문·주민·상자·게이트·계단 접근을 비우고 식생 자체에 충돌은 추가하지 않습니다.
`Game.CAMERA_WORLD_SCALE`은 1.60을 유지합니다. 설정의 `Prefs.world_zoom`은 표시용 상대 선택 `0.5/1/1.5`이며, `Prefs.WORLD_ZOOM_BASE=0.75`와 `actual_world_zoom()`이 이를 실제 배율 `0.375/0.75/1.125`로 변환합니다. 새 표시 `1×`가 이전 실제 `0.75` 시야입니다. `_update_zoom()`만 이 실제 배율을 한 번 적용하고, `Ortho3DPreview`는 완성된 `game.camera.zoom`에서 직교 카메라 크기를 역산합니다. 짧은 변 720·고화질·표시 1·디버그 1일 때 `Camera2D.zoom`은 `1.60×0.75=1.20`입니다. 기하 문서의 원시 카메라 줌 1과 설정 표시 1을 구별합니다.

기존 저장의 상대 선택 `0.5/1/1.5`는 그대로 읽고 유지하며 저장 스키마 변경이나 강제 마이그레이션은 없습니다. 디버그 URL `zoom`은 그 뒤에 곱하는 독립 승수입니다. `?zoom=1`은 새 기본 시야를 유지하고 `?zoom=0.75`는 새 기본에 추가로 0.75를 곱하므로 새 1로 치환하지 않습니다. 스크린샷 도구의 기존 프리셋도 이 상대 승수 규칙을 따릅니다. 두 화질은 같은 월드 시야를 공유하며, 줌 펀치는 선택된 기준 배율에 상대적으로 적용됩니다. `_camera_focus()`는 발치를 화면 높이 약60%에 유지하고 게임 수치·충돌·HUD·입력 영역은 카메라 때문에 바뀌지 않습니다.

`CanopyShade`는 마을 평지의 실제 나무 아틀라스 알파와 발치·배율·반사·변환을 공유 광원 방향으로 투영합니다. 같은 뷰포트의 지면만 받으며 고정된 타일 그림자가 아닙니다. 변경된 나무/수신면 변환·알파·광원·화질만 갱신하고 그림자는 지면 위·배우와 건물 아래에 둡니다. 2D 나무 실루엣을 쓰는 근사이므로 정확한 3D 수관 체적이나 계단·다리·높은 마당의 그림자까지 재현하지 않습니다. `canopy_shade`는 실제 캐스터 이동·반사·접점·변환·한도·화질과 수명을 검사합니다.

`ForestLighting`·`GroundEdges`·`WorldLighting`은 [장면 가독성 기준](world-readability.md)의 공통 낮빛 모델을 사용합니다. 지면의 재료 전이·나무 밑 흙색은 실제 도로 다각형과 나무 발치에서 만든 캐시 마스크를 사용하며 충돌과 UV를 유지합니다. 건물·성벽·수관·배우 몸과 시체에도 같은 빛/그늘을 적용하고, HUD·표식·확정 타격 섬광은 독립적으로 읽힙니다. `forest_daylight` 부모 아래에만 숲 재질을 부여하므로 동굴 벽·바위·아치·등불은 기존 라이트 수신 재질을 유지합니다. 숲 루트 표시 전환으로 같은 프레임에 조명을 복원하고, 재질 등록은 약한 참조로 정리합니다. 추가 `PointLight2D`·렌더 패스는 없습니다. `--lighting off`는 같은 구도의 전체 적용 전후 비교용이며 정확한 3D 그림자·법선·간접광 복원은 아닙니다.

`TownGateRuntime`은 실제 성벽/문 통로와 적의 거리를 검사하고, 몸 반경을 포함한 몬스터 진입 금지·철문 닫힘/안전 출입을 분리합니다. 닫힌 문은 근접 공격도 통과하지 못합니다. `TerrainLevels`는 실제 지형 면·계단·다리 연결에서 근접 도달 여부를 판정하고, `z_index`나 원거리 마법 규칙을 높이 대신 사용하지 않습니다. `NpcArt`/`Villager`는 새 주민 원화·발치·실제 사람 크기를 사용하며 `town_clearance.json`이 성벽 여백을 정합니다.

[생성형 HUD·원소 표현](presentation-design.md)은 `PresentationArt`가 출처를 고정한 금속 4종과 타격 16프레임을 공유합니다. `prepare_presentation_art.py`로 패킹하며 투명 UI와 순수 검정/ADD 발광 원화를 구별합니다.
시전·발사·투사체·명중·베기·오브·광역 빛은 기존 장식 한도·일시정지·동작 줄이기를 따릅니다.

기본 화질은 기존 주 뷰포트에 월드를 직접 그립니다. 절약 화질에서만 월드·카메라·동굴을 별도 SubViewport로 옮기고
HUD·패널은 주 뷰포트에 유지합니다. `Game.scene_root`/`scene_view`가 현재 월드의 부모와 뷰포트를 가리킵니다.
설정의 절약 화질(`Prefs.low_resolution`, 기본 false)은 월드 렌더링 크기를 가로·세로 절반으로 낮춥니다.
카메라 배율도 함께 조정해 보이는 월드 범위와 조작 좌표를 보존합니다. 기기 설정에 저장하며 진행 저장 형식은 바꾸지 않습니다.
뷰포트 컨테이너는 일시정지 중에도 크기를 갱신하지만 자식 월드의 배우들은 일시정지를 따릅니다.
캡처 시 `node tools/screenshot.mjs --scene town --device phone --quality low`로 선택할 수 있습니다.

`node tools/benchmark.mjs --quality high|low --device desktop|phone|phone-landscape`은 같은 시작 위치에서
실제 월드 그리기·렌더링 크기를 확인하고 6초 준비 후 6초 동안 브라우저 프레임 진행과 95백분위 프레임 간격을 기록합니다. 기본 렌더러는 SwiftShader이며,
실제 기기 성능을 뜻하지 않습니다. `?benchmark=1`에서만 `RenderProbe` 진단을 활성화합니다. 플랫폼 기본 렌더러 비교에는 `--renderer default`를 사용합니다.
`RenderProbe`는 월드와 주 뷰포트의 실제 픽셀 수·별도 렌더 여부를 함께 기록합니다.
루트의 `ViewportTexture.get_size()`는 Window 크기에 stretch 배율을 다시 곱하므로 framebuffer 측정에는 `Window.size`를 사용합니다.
브라우저 측정 결과에는 실제 canvas 속성·CSS 크기·DPR도 함께 기록해 이 값을 대조합니다.
`node tools/screenshot.mjs --scene pc_controls --device desktop --dpr 2`로 높은 픽셀 밀도에서도 클릭 좌표와 시야를 확인합니다.
미니맵은 원점 이동이 지도 1/4px에 못 미치면 원형으로 잘라 둔 지형을 재사용합니다. 지도 교체·크기 변경은 즉시 갱신하고 마커·방향 화살표는 매 프레임 현재 위치를 사용합니다.

## 가림·모바일 표시

승인된 HUD의 비율·재료·자산 제작 기준은 [UI 디자인 기준](ui-reference.md)에 있습니다.
빈 슬롯과 조이스틱은 배경이 비치도록 표시하고 상호작용은 42px 명판으로 줄입니다. 실제 터치 영역은 64px 이상을 유지하며 작은 표시 바깥을 눌러도 동작합니다.

`UiKit.style_button()`은 팝업의 기본·선택·주요 행동·포커스·비활성 상태를 구분합니다.
`UiKit.MetalSkin`이 청동 이중 테두리·미세한 가죽 질감·빛 받는 모서리를 그리며 본문은 크림색으로 표시합니다. HUD 숫자는 Regular 글꼴과 얇은 그림자를 씁니다.
`PanelFrame.set_compact()`는 대화·확인·보스·동굴 안내를 내용 높이에 맞춰 중앙 배치합니다.
가방·설정·스킬은 넓은 틀을 사용하며 회전 시 이전 최소 크기를 지워 새 화면에 맞춥니다.
제목·부제는 10px, 헤더·본문·푸터는 18px, 카드 제목·설명은 8px 간격을 공유합니다.
compact 높이는 실제 헤더·탭·푸터 최소 크기를 측정하며 본문에 최소 96px를 남깁니다.
닫기는 64×64로 유지하고, 행동 버튼의 최소 폭 합이 프레임을 넘으면 세로 배치합니다.

`WorldOcclusion`의 공유 셰이더와 인스턴스 정렬 높이로 주인공 앞 원화의 몸 주변만 투명하게 합니다.
장면의 원화·충돌·깊이 정렬은 유지하며, 높은 지형 윗면에서는 가림 완화를 끕니다.
셰이더 인스턴스는 주인공 몸과 겹치는 앞쪽 원화에만 할당해 모바일 버퍼 한도를 피합니다.
표시 전용 효과는 최대 64개, 시체는 최대 32개로 제한하며 투사체·피해 구역·소환물은 표시 제한으로 제거하지 않습니다.
`Hud.status_geometry()`는 승인된 714×1280 레퍼런스에서 잰 상단 비율을 사용합니다. 터치 조작은 안전 여백을 반영하고 물약·구르기·메뉴도 64px 이상의 터치 영역과 별도 표시 반지름을 사용합니다.
상태 헤더는 화면 배율의 0.902를 따로 적용해 기존 소형 배치(0.82)보다 초상화·막대·숫자·목표·강화 효과를 10% 키웁니다. 공통 금속 띠와 세 막대의 왼쪽 면 모두 초상화 테두리를 따릅니다. 고정된 수직 시작선으로 넓은 검은 쐐기를 남기지 않으며, 원형 테두리가 접점의 외곽선을 맡습니다. 채움과 피해 잔상은 각 높이의 가시 폭에 실제 비율을 적용해 곡선 영역의 면적 비율도 유지합니다. 아바타 문장과 미니맵 테두리의 그리기 범위를 같은 안전 상단 여백(화면 배율 ×16)에 맞추며 화면 높이에 따라 아래로 밀지 않습니다. `Minimap.painted_bounds()`를 배치와 실제 경계 검사에서 함께 사용합니다. 미니맵과 터치 조작은 화면 배율을 유지합니다. 레벨 메달은 헤더 기준 32px로 초상화 테두리에 겹치고 숫자는 최대 16px에서 실제 폭에 맞춥니다.
초상화 왼쪽 위의 레벨 메달은 원본 `sjrpg/docs/art/level-badge-original.png`를 재사용합니다.
`Hud`가 실제 `GameState.level`을 갱신하고 세 자리 이상도 메달 안에 맞춥니다. `level_badge`는 실제 경험치 레벨업·저장 복원·새 모험과 안전 여백을 검사합니다.
`tools/prepare_ui_art.py`는 `assets/source/`의 새 마법사 초상화·가죽·물약·레벨 메달을 패킹합니다. 메뉴의 검·가방·일지·설정 원형 원화는 원본 `reference-battle-buttons.webp`에서 가져오며 글자 대체 아이콘은 사용하지 않습니다. 설정의 동작 줄이기는 장식 회전과 HUD 맥박을 고정합니다.
패널의 글자 배율은 실제로 열린 패널을 기준으로 복구합니다. 미니맵은 캐시한 도형 경계로 먼 지형의 교차 계산을 생략합니다.

## 바람 동굴

`DungeonLayout`의 투영 다각형을 실제 바닥·이동 충돌·두 지도가 공유합니다. 전투 구역 5개와 두 번의 분기·합류가 있습니다.
`DungeonRuntime`은 숲 루트를 숨기고 처리를 멈춘 뒤 플레이어를 임시 월드로 옮깁니다. 적·상자·시체·지도 상태는
공간별로 분리하고, 퇴장 시 플레이어를 돌려놓은 뒤 동굴 노드를 폐기합니다. 입장 전 미완료 공격도 취소합니다.
적 레벨은 입장 때 고정하며 동굴 처치는 숲 의뢰에 보내지 않습니다. 시체·전리품·경험치는 기존 전투를 재사용합니다.
동굴 적의 `patrol_center`/`patrol_radius`는 대기 중 배회만 방 중심 170px 이내로 제한합니다.
추적·공포 이동은 제한하지 않으며 일반 필드에는 적용하지 않습니다. 방문 전 다른 갈림길로 적이 흩어지는 일을 줄입니다.
`location_mode`만 저장하고 동굴 인스턴스는 저장하지 않습니다. 재접속 시 입구로 복귀하며, 보호 의뢰·보스 도전 중 입장은 막습니다.
`DungeonPanel`은 입장·완료·퇴장을 제공하고 설정에서도 중도 퇴장할 수 있습니다.

동굴의 [완성 디자인과 원화 제작 기준](cave-design.md)은 `assets/source/cave-design.png`가 정본입니다.
`DungeonArt`가 파생한 석재 바닥·높은 암벽·낮은 돌턱·열린 아치·등불 원화를 실제 이동 다각형에 배치합니다.
외곽벽은 방·통로 합집합의 바깥 경계에만 놓고 월드 깊이 정렬·가림 완화를 공유합니다.
등불의 지역 조명은 일시정지와 동작 줄이기를 따릅니다. `cave_art.json`은 원본·배포 원화 해시를 보관하고,
`prepare_cave_art.py`와 `cave_art.merge()`로 원화·외부 입구 데이터를 재생성합니다.
`dungeon_art`는 실제 바닥·지도·벽과 조명·화질 전환·수명을 검사합니다.
`dungeon_preview=entry|room|branch|exit`는 실제 동굴에 입장한 뒤 구도를 고정하며,
`tools/screenshot.mjs --scene cave_entry|cave_room|cave_branch|cave_exit`로 가로·세로를 비교합니다.

## 탐험·지도·안식처

`MapGeometry`가 마을 포장·강·다리·벽·건물 바닥·랜드마크 윗면·물 경계에서 두 지도에 쓸 도형을 만듭니다.
`MapPanel`은 전체 지도와 안식처 이동 탭을 제공하며, 의뢰 상태에 따라 목적지 표식을 갱신합니다.
`Exploration`은 직접 방문한 안식처를 해금하고 `last_sanctuary`에 부활·재접속 위치를 기록합니다.
이동은 안식처 근처에서만 가능하며 주변 적·보호 의뢰·보스 도전 중에는 막습니다. 도착점은 실제 충돌로 검사합니다.
폭포는 기존 `landmarks.json`의 네 번째 측정값을 사용하며 상자 ID 8을 추가합니다(기존 기억 상자 5–7 보존).

## 목표와 근처 상호작용

`Quests.next_quest()`는 보호 진행·보호 완료 보고를 우선하고, 다른 완료 보고·수락·재도전·새 의뢰 순으로 안내합니다.
같은 상태에서는 마을 배달 → 석조 정원 → 조사관 순서이며, 사용자가 다른 의뢰를 먼저 수락하면 그 진행을 존중합니다.
`Game.near_npc()`는 NPC·동굴·안식처 중 가까운 대상을 고릅니다. 분수 부근 안식처가 더 가까운 주민 대화를 가로채지 않습니다.

## 파수꾼 도전

의뢰 3개 완료 시 서쪽 고정 공터에서 `QuestRuntime.start_boss()`로 도전합니다. 별도 처치 수 조건은 없습니다.
사망·1100px 이상 이탈 시 적을 제거하고 재도전을 허용하며, 재접속도 새 도전으로 시작합니다.
보스 예고 타원의 세로 배율과 실제 공격 거리 계산을 일치시킵니다. 고유 보상은 가방이 가득 차면
`boss_heart_pending`으로 저장하고 가방을 비운 뒤 패널을 닫을 때 지급합니다.

## 저장과 재접속

설정의 설치 버튼은 `web/install.js`가 보관한 `beforeinstallprompt`를 사용자 버튼 입력 안에서 동기 호출합니다.
설치 수락은 완료로 취급하지 않고 `appinstalled` 또는 실제 standalone 실행에서만 설치됨을 표시합니다.
`web/manifest.webmanifest`와 `install-sw.js`는 `/sjrpg/` 상대 경로를 사용하며, worker는 엔진·PCK를 캐시하지 않습니다.
연결이 끊긴 상태로 실행하면 연결 안내를 표시합니다. `tools/export_web.sh`가 manifest·worker·설치 아이콘을 함께 복사합니다.
`node web/check_install.mjs`는 합성 prompt 이벤트의 상태 처리와 실제 manifest/worker를 검사하며, 기기에서의 실제 설치 검증을 대신하지 않습니다.

PC 월드 좌클릭은 GUI 처리 뒤 `TouchControls.hold_mouse_primary()`를 거쳐 모바일 주 슬롯과 같은 `Player.cast_slot(0)`을 호출합니다.
마우스는 HUD 버튼을 누를 수 있지만 가상 조이스틱을 시작하지 않습니다. 1–4는 보조 슬롯, WASD/방향키는 직접 이동입니다.
우클릭은 `Game.screen_to_world()`로 실제 렌더 뷰포트 크기와 카메라 변환을 역산해 이동 목적지를 정합니다.
절약 화질의 반 해상도 월드에서도 HUD 좌표를 그대로 월드 좌표로 사용하지 않습니다. 이동은 기존 충돌 검사를 통과하며,
목적지 도착·충돌·직접 이동·팝업·포커스 이탈·사망·워프에서 취소합니다. 별도 경로 탐색은 하지 않습니다.
`desktop_input`은 실제 이벤트 전달·주 공격의 재사용/자원 검사·1–4·UI 차단·두 화질의 좌표 변환·충돌 정지를 검사합니다.
`node tools/screenshot.mjs --scene pc_controls --device desktop`으로 실제 브라우저 조작 결과를 함께 확인합니다.

게임은 창·앱의 포커스 이탈과 앱 중단 알림에서 터치·키보드·목적지 이동을 해제하고 저장합니다.
열린 패널이 없으면 `Hud.pause_for_background()`로 재개 안내를 열며, 기존 패널은 유지합니다.
포커스 복귀만으로는 재개하지 않습니다. 지연 회전 공격·기억 표시·승리 표시·부활의 SceneTreeTimer도
`process_always=false`로 만들어 일시정지를 따릅니다. `tools/screenshot.mjs --scene background`는 실제 캔버스 blur를 발생시킵니다.

`SaveStore`는 임시 파일에 작성·flush 후 교체하며, 읽을 수 있는 직전 저장만 `.bak`으로 보존합니다.
`GameState.save_game()`은 성공 여부를 반환하고 `save_finished(success, message)`를 알립니다.
HUD는 실패 시 누를 수 있는 재시도 안내를 유지하며 설정의 수동 저장도 실패를 표시합니다.
버전 없는 기존 Godot 저장을 지원하고, 미래 버전과 잘못된 컨테이너는 적용 전에 거부합니다.
중단된 조사관 보호는 습격 노드를 복구하는 대신 수락 상태로 되돌려 재시작합니다.
새 모험 준비·취소는 기존 저장을 지우지 않습니다. 장면 교체 시 이전 장면은 즉시 처리를 중지해 교체 프레임에 진행을 바꾸지 못하게 합니다.
기억 상자 개봉과 일회성 스킬 포인트 보상은 함께 저장하며, 이전 저장에 상자 3개만 기록된 경우 누락 보상을 복구합니다. 테스트 러너는 별도의 `user://tests/` 경로를 사용합니다.

## 전투 피드백

원소 마법은 짧고 조용한 준비음을 낸 뒤 실제 예약 동작이 실행되는 순간에 발사음을 냅니다.
구르기·사망·시전 취소는 대기 중인 발사음을 버립니다. 명중 플래시는 실제 속성에 따른 따뜻한 금빛·주황·보라·청백색을 사용하고 플레이어 피격은 붉은색으로 구별합니다.
첫 표시의 감쇠만 제한해 느린 프레임에서도 확인할 수 있으며 이후 정상 시간으로 소멸합니다. 피격 색은 원본 프레임 알파를 사용하는 `hit_flash` 오버레이에서 실제 밝은 색으로 표시하며 바닥 그림자는 바꾸지 않습니다.
기존 접촉 자세 유지·반동·발사광·생성형 16프레임 원화·카메라 감쇠·타격음·장식 수 한도는 같은 명중 흐름을 따릅니다.
체력 30% 미만의 경고는 `Hud._critical_warning`의 화면 전체 ColorRect에 표시합니다. 0.9Hz의 옅은 붉은 맥박이며 입력을 막지 않고, 게임 시간과 함께 멈춥니다. 사망·0 체력·30% 이상 회복 시 숨기고 동작 줄이기는 고정된 옅은 색을 사용합니다. 초상화만 붉게 깜빡이던 이전 표시는 제거했습니다. `critical_health`는 임계값·전체 화면 범위·입력 투과·맥박·동작 줄이기·일시정지를 검사합니다. `tools/screenshot.mjs --scene hud_danger --device phone`은 명시적인 검수 모드에서 배우를 고정하고 실제 HUD 경고를 움직이며 두 시점을 캡처합니다.

[몬스터 원화 검수](monster-animation.md)는 다섯 종류의 걷기·공격 640프레임과 해시를 기록합니다.
`monster_motion`은 이 원본 해시·클립 구조와 실제 피해 시점·회복 대기를 검사합니다.
공격 준비의 길이는 진입 시 고정해 둔 타이머를 따릅니다. 공격 후 복귀 원화는 기본 일반 0.28초·보스 0.4초, 회복 대기는 기본 0.7초·1.2초에 각각 공통 액션 템포(÷1.5)를 적용합니다. 복귀 원화가 끝나면 중립 자세를 유지하며 회복 타이머를 기다립니다. 둔화는 이 시간들을 같은 비율로 늘립니다.
보스가 회복에서 이전 공격 자세로 돌아가던 잘못된 분모를 제거했습니다. 체력바는 피해·사망 때, 위험 예고는 준비 중에만 다시 그립니다.

`Effect.spawn_impact()`는 실제 피해 확정 뒤에만 생성형 속성별 4프레임 원화(`assets/source/combat-frames.png` → `assets/art/effects/combat-frames.webp`)를 가산광으로 짧게 표시합니다. 기존 장식64개 한도를 공유하며 투사체·피해 영역과 분리합니다. 적의 반동은 스프라이트 위치에만 적용합니다. `Game.combat_feedback()`는 근처 명중에만 최대7px의 감쇠하는 방향 충격과 짧은 횡방향 반응을 더하며 시간 배율을 바꾸지 않습니다. 동작 줄이기는 이 움직임을 끕니다.
HUD는 체력·물약 수·쿨다운의 실제 변화를 감지합니다. 사운드의 작은 피치 변화는 별도 난수기를 써 전투 난수에 영향을 주지 않습니다. `juice` 테스트는 실제 피해·무적 중 중복 반응 방지·모션 설정·장식 한도를 검사합니다. 피해 단계(`HitTier`)별 숫자·넉백·눌림·소리·처치 연출은 [juice.md](juice.md)에 수치와 튜닝 위치가 정리돼 있고(배경 음악은 [music.md](music.md)) `juice_tier`·`juice_enemy`·`juice_player` 테스트가 검사합니다.
`tools/screenshot.mjs --scene juice --class mage --device phone`은 명시적인 `combat_preview=1` 쿼리로 반복 명중을 재현하고 연속 화면을 저장합니다. 일반 모험에는 이 미리보기를 실행하지 않습니다.

`RewardFx`는 확정된 상자 골드·희귀 장비·처치 XP·레벨업에만 생성형 3칸 원화(`reward-atlas.webp`)를 표시하고 장식64개 한도를 공유합니다. 큰 레벨업 효과는 캐릭터를 따라가며 생성형 빛과 얕은 발밑 광륜을 표시합니다. `LevelUpBanner`는 텍스트 박스 없이 영문 `LEVEL UP`과 실제 `Lv. N`을 1.8초간 표시하며 안전 영역·회전·동작 줄이기·팝업 일시정지를 따릅니다. 여러 레벨을 한 번에 올려도 효과와 배너는 한 번입니다. 레벨업 외의 알림은 HUD의 청동 명판과 최대4개 대기열로 전달하며 중복을 억제하고8초 지난 대기 알림은 버립니다. 패널 일시정지는 알림 수명도 멈춥니다. `rewards` 검사는 중복 보상 방지와 알림 순서·한도를 검증합니다. `tools/screenshot.mjs --scene rewards --device phone`은 명시적인 `reward_preview=1`에서 실제 상자와 레벨업 경로를 재현합니다.

`--scene levelup`은 상자 없이 실제 경험치 레벨업의 영문 배너·캐릭터 주변 효과만 확인합니다. 보상 캡처 미리보기는 확정 직후 장면을 멈춰 원화의 위치·크기를 검토합니다. 일반 플레이의 수명·이동·일시정지는 `RewardFx`와 `rewards` 검사로 별도로 확인합니다.

원본 비교는 `screenshot.mjs --scene chapel_reference --device phone --viewport 714x1280 --dpr 1 --zoom 1`로 실제 보행 지점을 촬영하고 `tools/compare_reference.mjs --actual /tmp/game.png --out /tmp/comparison.png`로 나란히 표시합니다. 비교 도구는 원본 비율을 유지하며 생성 컨셉을 실제 게임 화면으로 대체하지 않습니다. 웹 export는 `tests/*`와 `tools/*`의 제작/검사 자료를 제외하고 런타임이 읽는 `assets/data/`를 배포합니다.

실제 보행 후 화면은 `screenshot.mjs --scene town --walk a:2900,w:300`처럼 키와 유지 시간을 지정해 확인할 수 있습니다. 카메라·물체를 숨기거나 좌표를 조작하지 않고 실제 WASD 입력을 전달합니다.

## 야외 가독성

`WorldLighting`의 기본 그늘광은 `(0.70,0.78,0.84)`, 직사광은 `(0.46,0.32,0.15)`이며 CPU와 GLSL에서 같은 계수를 사용합니다. 그늘을 밝히면서 마을·예배당 개구부의 최대합 `(1.16,1.10,0.99)`은 유지합니다. `ForestArt.GRASS_TINT`는 잔디에만 밝은 황록색 배율을 적용하고 포장석·흙·나뭇잎 원화는 분리합니다. Native3D 잔디도 같은 알베도 배율을 사용합니다. 동굴의 실제 점광원과 접촉광 수명/예산은 이 조정과 별개입니다.

`NativeTownProps3D`는 분수와 숲·동굴의 워프문을 공유 GLB로 배치합니다. 실제 워프 바닥 다각형의 중심·방향을 사용하고 새 콜라이더를 만들지 않습니다. `PlazaWater.phase`가 물·소용돌이·최대 12개 입자의 유일한 시계이며, 환경/상호작용 렌더러는 `owns()`로 중복 카드를 제외합니다. `native_town_props`는 실제 임포트 메시·재질·정지·동작 줄이기·동굴 전환을 검사합니다. 재현 도구는 `tools/preview3d/build_native_town_props.py`, GLB/기하 검사는 `tools/preview3d/test_native_town_props.py`, 해시·재질·충돌 기록은 `assets/source/preview3d/native-town-props/provenance.json`에 있습니다.

## 외곽 숲의 네이티브 나무

`Ortho3DForestTrees`는 `Ortho3DEnvironment._build_forest`에서 외곽의 실제 소유 인스턴스만 교체합니다. `Ortho3DTrees.mesh_library()`는 마을과 외곽의 두 메시/재질을 공유하며 기존 마을 변환을 유지합니다. 16 m 셀별 MultiMesh, 원본 키 기반 고정 변형, 실제 바닥 Y, 전체 수관 AABB와 기존 충돌 계약은 [외곽 숲 나무](native-forest-trees.md)에 기록합니다. `ortho_3d_forest_trees`와 기존 `ortho_3d_trees`·`native_environment`가 해당 통합을 검사합니다.

`NativeCombatFx3D`는 기존 원화 카드 화이트리스트에서 빠졌던 `visual=""` 일반 투사체만 표시합니다. 실제 `Effect.native_position()`·수명·나이를 관찰하여 생성형 원소 아틀라스의 본체와 짧은 꼬리를 최대32개(각2카드)로 표시하며, 피해·충돌·자원·독립 시계를 만들지 않습니다. 기존 `visual="bolt"` 경로는 유지합니다. 범위와 남은 미매핑 효과는 [일반 투사체 표시](native-projectile-fx.md)에 기록합니다.

## 저장 선택 레이아웃 검수

저장 선택과 새 수호자 선택은 [생성형 선택 화면 시안](selection-screen-design.md)의 구성·재질을 따르는 별도 레이아웃을 사용합니다. 인물 일러스트와 숲 배경은 생성 원화이며 제목·직업 탭·능력치·슬롯·삭제·주 행동은 실제 Godot 컨트롤입니다. 클래스 미리보기와 저장 목록의 원화 영역을 목록/상세 영역과 분리해 글자가 그림 위에서 흐려지거나 버튼이 얼굴을 가리지 않게 합니다. 저장 카드는 직업 초상화·번호/직업·레벨/지역·현지 저장 시각을 각각 측정하며 별도 footer를 유지합니다. 웹의 가상 해상도와 CSS 크기를 구분해 슬롯/삭제/주 행동은44CSS px 이상, 주 정보는14CSS px·보조 정보는12CSS px 이상을 유지합니다. 목록의 스크롤과 포커스 가시성을 유지하고 세로·가로에서 실제 렌더와 생성 시안을 비교합니다.

삭제는 선택 슬롯과 별개의 명시적 대상 번호를 유지합니다. 확인 중에는 배경 버튼과 콜백을 모두 막고 취소에 포커스를 둡니다. Tab/Shift-Tab은 확인창 안에서 순환하며 취소/Escape는 해당 삭제 버튼으로, 삭제 완료는 남은 대상 카드로 돌아갑니다. 파일 생성·불러오기·삭제는 기존 GameState 경로만 사용합니다.

전용 하네스는 다음 두 경로를 함께 검사합니다.

- **save_layout**: 실제 빈/혼합/가득/손상/백업 파일과 긴 안내를 여러 raw SubViewport 크기·왕복 회전에서 검사합니다. 레이블 실측·행/삭제/고정 footer 경계, 스크롤/포커스, 저장 bytes와 영웅 미리보기 불변을 확인합니다.
- **node tools/check_save_layout.mjs http://127.0.0.1:8779/ /path/to/review**: 내보낸 실제 main 장면에서 CSS 화면 크기와 포인터/Tab/Shift-Tab/Enter/Escape를 사용합니다. 대표 원본 JPEG는 지정 로그 태그로, 모든 캡처와 JSON은 artifact로 남깁니다. 캡처 기록은 별도 리뷰어의 시각 판정을 대신하지 않습니다.

**?save_layout_review=1**은 새 격리 브라우저 프로필의 검수 전용 진입점입니다. 고유한 user://tests/save-layout-* 경로에서만 정식 create_slot/save_game으로 시나리오를 준비하며 운영 경로의 파일을 고치지 않습니다. 브라우저의 각 시나리오는 새 파일 경로를 사용하며, 이전 시나리오의 파일은 프로필 종료까지 남겨 비동기 IDBFS가 읽는 파일을 다음 시나리오 준비가 삭제하지 않게 합니다. 같은 시나리오 안의 실제 삭제·손상·백업 검사는 그대로 수행합니다. 일반 실행에서는 로드하지 않습니다. 기존 __sjrpgClassButtons 중심 좌표와 slot_labels는 유지하고 실제 rect/visible/font/focus 및 save_layout 읽기 전용 측정값을 추가합니다.

.github/workflows/save-layout-review.yml이 관련 변경의 빠른 검수·캡처를 담당합니다. 명시적인 **[layout-review]** 커밋은 기존 운영 배포를 건너뛰어 검수 중인 UI를 공개하지 않습니다. 소스와 실제 캡처의 독립 리뷰가 끝난 동일 소스 트리의 일반 커밋에서 전체 검사와 Pages 배포를 수행합니다.


## 입체 소유권과 UI 비교 하네스

`NativeResidents3D`·`NativeWarrior3D`·`NativeEnemyModels`는 기존 배우의 실제 발·이동/공격 진행·피격·사망 상태만 관찰합니다. 주민은 정적 배칭 뒤에 생성하고, 교체한 대상은 기존 원화 카드에서 개별 제외합니다. 시체는 원래 수명과 페이드를 공유합니다. 환경의 `remaining_sources`는 아직 원화를 사용하는 실제 원본의 역할·시트·발 위치를 남겨 교체 누락을 숨기지 않습니다.

`?native_style_review=1`은 검수 전용 읽기 전용 상태 측정기를 연결합니다. `tools/check_native_style.mjs`는 새 브라우저 프로필에서 실제 시작·이동·물약/메뉴/스킬트리 입력과 회전·DPR2를 검사합니다. `native-style-review.yml`은 변경 전 커밋의 실제 게임도 따로 내보내 같은 위치의 PNG와 비교 이미지를 남깁니다. 기준본의 작은 입력 영역은 측정하되 새 기준 통과로 표시하지 않습니다. 렌더링 캡처는 별도 리뷰어가 모델 전체 면·재질·모바일 가독성을 판정하는 자료입니다.


## CC0 상인과 공통 주민 factory

`NativeResidents3D.create(identity)`는 실제 마을과 검수 갤러리가 함께 사용하는 factory입니다. 상인만 `assets/art/native_residents/merchant.glb`를 생성하고 나머지 일곱 역할은 기존 절차형 메시를 유지합니다. 주민의 기존 `Villager._time`으로 AnimationPlayer를 수동 샘플링하며 자동 재생·독립 시계·추가 물리 몸체를 만들지 않습니다. 피격 오버레이는 imported root의 모든 자식 메시를 함께 처리하고 이름·의뢰·상점·동굴 범위는 원래 소스가 소유합니다.

`tools/hero_art/fetch_sources.py`는 고정 원본과 실제 CC0 라이선스를 해시로 확인합니다. `export_cc0_merchant.py`는 원본 리그의 기준 자세 차이를 검증하고 대상 뼈 길이를 유지하는 30fps FK retarget과 미터 배율을 구웁니다. `publish_merchant_blobs.py`는 18k 상한·실제 GLB·원문 라이선스를 다시 검증하고 고정 엔진으로 실제 임포트 설정을 만듭니다. 후보 worker는 ref를 이동하지 않고 검수용 blob만 준비합니다. 출처·실제 해시는 `assets/source/native-residents/merchant/`에 보존합니다.

`native_merchant`는 실제 스킨·골격·수동 동작·일시정지·전체 메시 피격·소유권과 기존 발 위치를 검사합니다. `SJRPG_STYLE_MERCHANT_ONLY=1` 브라우저 하네스와 `native-merchant-review.yml`은 변경 전 실제 빌드와 비교해 네 방향·모바일 두 방향·DPR2·실제 상점 버튼·일시정지를 검수합니다. rest AABB와 뼈 원점은 GPU로 변형된 발바닥/보이는 픽셀 경계와 구분합니다. 상점 상호작용 버튼은 다른 HUD와 겹치지 않는 44CSS px 이상 입력 영역을 유지합니다.


## 음악 재생 객체의 소유권

`MusicDirector`는 장면에서 나갈 때 소유한 세 `AudioStreamPlayer`를 정지하고 스트림 참조를 해제합니다. 같은 노드를 다시 붙이면 기존 세 플레이어에 트랙을 다시 연결하고 현재 지역의 페이드를 시작합니다. 앱 포커스로 인한 일시정지 상태는 별도로 유지하며 실제 재생을 시작한 뒤에도 적용합니다. 일시정지된 루프를 새로 시작하지 않도록 재생 객체의 존재는 `has_stream_playback()`으로 판정합니다. 음악 설정을 끄면 일시정지된 재생 객체도 정리됩니다. `music` 검사는 세 트랙의 실제 교차 재생·분리/재부착·포커스·게임 해제와 재생 객체 정리를 검증합니다.

## 헤드리스 종료 진단

3D 회귀 테스트는 Godot의 `--verbose`로 실행해 종료 시 리소스/인스턴스 경로를 추적할 수 있게 합니다. 엔진 종료 코드와 `SCRIPT ERROR`·`ERROR:` 및 전체 `RESULT failed=0` 검사는 그대로 유지하며, 실패 시 마지막 로그도 남깁니다.

헤드리스 테스트 러너는 모든 케이스 해제 후 오디오 드라이버의 새 믹스 완료와 다음 메인 루프 정리를 확인한 뒤 종료합니다. Godot4.7.2의 `stop_playback_stream`은 `FADE_OUT_TO_DELETION`을 요청하며, 믹서가 목록에서 제거한 재생 객체는 `AudioServer.update`에서 해제됩니다. Time/AudioDriver의 공통 OS 시계를 호출 전후로 측정해 실제 새 믹스 경계를 판정합니다. 믹스 확인과 마지막 정리가2초 안에 완료되지 않으면 테스트를 실패시킵니다. 고정 sleep이나 음악 설정 변경, 엔진 오류 무시는 사용하지 않습니다.

이 경계는 테스트 종료 동기화를 위한 것이며 웹 게임의 브라우저 종료 원인과 구분합니다. `.github/workflows/audio-mix-shutdown-diagnostics.yml`은 고정 기준 소스와 같은 작업 환경의 실험 러너를 비교하고 두 strict 결과를 보존합니다. 기준 실행의 실패는 보고서에서 그대로 실패로 남깁니다. 엔진 근거는 Godot4.7.2의 [AudioServer](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/audio/audio_server.cpp), [Dummy 드라이버](https://github.com/godotengine/godot/blob/4.7.2-stable/servers/audio/audio_driver_dummy.cpp), [메인 루프](https://github.com/godotengine/godot/blob/4.7.2-stable/main/main.cpp)에 있습니다.

## 웹 자원과 반복 비용

[웹 성능과 에셋 예산](web-performance.md)은 실제 PCK 분석과 런타임 측정의 단위·경로·한계를 구분합니다. `ActorAtlas.texture_snapshot()`은 메타데이터와 실제 로드 상태를 읽되 텍스처 getter를 호출하지 않습니다. `NativeEnemyModels.cache_stats()`는 최초 SurfaceTool 제작과 반복 레시피 사용을 구분하고, 레시피는 노드를 소유하지 않습니다. `Ortho3DPreview.render_activity()`는 렌더 크기·정지 유지·동기화 횟수를 제공합니다. `ClassSelect.probe_activity()`는 이벤트를 합친 게시 수를 제공하며 일반 유휴 프레임에 JS 레이아웃 게시를 하지 않습니다. 이 관찰 API는 실제 입력과 상태 소유권을 변경하지 않습니다.
