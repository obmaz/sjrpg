# 독립 에셋 제작과 협업

다른 AI나 모델러는 에셋 하나의 폴더를 담당합니다. 공용 표시기·물리·게임 규칙은 통합 담당자가 소유합니다. 한 에셋을 교체하기 위해 전역 목록·대형 JSON·여러 건물 생성기를 동시에 수정하지 않습니다.

## 현재 연결 구조

- `assets/models/architecture/<id>/asset.json`과 `albedo.png`: 건물별 전용 네 면 표면. 현재 ID는 shop, smith, stable, home, chapel, bridge입니다.
- `scripts/native_asset_surface.gd`: 폴더별 설정을 읽는 공용 어댑터. 원화 추가·수정에는 이 파일을 고치지 않습니다.
- `scripts/native_asset_surface.gdshader`: 집과 예배당의 실제 로컬 좌표로 네 방향 벽을 구별하고, 면 전체에 각 원화를 한 번 배치합니다. 창·문·골조와 충돌은 실제 기하가 유지합니다. 다리는 같은 어댑터의 미터 타일 모드를 사용합니다.
- `assets/models/environment/cave_entrance/model.gd`와 `plan.gd`: 동굴 입구만 담당하는 메시 제작기와 표시·충돌의 공통 치수. 동굴 내부 생성·진입 규칙은 이 에셋에 넣지 않습니다.
- `assets/source/architecture/<id>/`: 채택 원본·실제 프롬프트·출처와 해시. 패키지에서는 제외합니다.

`asset.json`은 schemaVersion=1, kind=surface, atlasGrid=[2,2]를 사용합니다. albedo는 같은 폴더의 파일명이며 경로를 벗어날 수 없습니다. mapping은 facade 또는 tile, tileMetres는 미터 단위, roughness는 0~1입니다. 셀 순서는 정면(+Z), 오른쪽(+X), 뒤(-Z), 왼쪽(-X)입니다. 수정자는 다른 에셋의 JSON이나 전역 등록 파일을 함께 고치지 않습니다.

## 외부 모델 제작자에게 전달할 사항

제작 요청에는 에셋 ID, 역할, 승인 스타일 원본, 실제 폭·깊이·높이, 주변 배우와 문 크기, 가로·세로 게임 화면을 포함합니다. 모델은 미터·Y-up·정면+Z, 지상 원점은 바닥 중앙, 배율은 (1,1,1)로 내보냅니다. 필요한 앞/뒤/좌/우 모습과 전체 실루엣을 함께 납품합니다.

GLB/텍스처/라이선스·원본 출처·제작 도구 버전은 같은 에셋 폴더에서 관리합니다. 텍스처는 base-color/normal/roughness의 실제 역할과 색공간을 구별합니다. 알베도에 주변 그림자·햇빛·문 개구부를 구워 넣지 않습니다. 새 이미지는 mode=1·밉맵 보호 대상으로 시작하고 GPU 압축 허용 목록은 통합 검수 후 변경합니다.

일반 소품은 500~2,000삼각형·1~2재질을 출발점으로 사용합니다. 큰 랜드마크·차량은 먼저 화면 점유율·동시 표시 개수·기하/재질 예산을 합의합니다. 크기만 맞춘 저밀도 UV나 불필요한 4K 텍스처를 기본값으로 사용하지 않습니다.

차량을 의뢰할 때는 차체와 회전할 바퀴를 분리하고, 바퀴 원점·회전축·반경·접지 높이, 좌석과 탑승/하차 위치, 문·무기 등 움직이는 부품의 소켓 이름을 지정합니다. 시각 모델 제작에는 이동 코드·운전 규칙·저장·전투 코드를 넣지 않습니다. 현재 게임에 차량 기능이 구현됐다는 뜻은 아닙니다.

충돌은 바닥 윤곽·높이·통과 가능한 구멍·발판을 명시한 별도 단순 형상으로 납품합니다. 정적/동적 여부·충돌 계층·바닥 높이는 통합 어댑터가 적용합니다. 외부 모델이 임의의 게임 콜라이더나 입력 스크립트를 실행하게 하지 않습니다. 기존 동선을 바꾸는 크기 변경은 모델과 실제 물리를 함께 검수합니다.

## 커밋 경계와 검증

한 제작 커밋은 해당 에셋의 모델·표면·설정·원본 출처와 해시를 포함합니다. 공용 어댑터의 API 변경은 별도 커밋으로 검토합니다. 경로를 유지한 모델 교체는 호출부를 수정하지 않으며, 새 종류의 동작이 필요하면 통합 담당자가 어댑터를 먼저 추가합니다. 공용 런타임에 임시 분기·후보 모델·사용하지 않는 로더를 쌓지 않습니다.

표면 패키지 독립 검사는 `python3 sjrpg_3d/tools/check_asset_packages.py --asset shop`으로 실행합니다. 전체 표면은 인자 없이 검사합니다. 이후 관련 Godot 검사·웹 export·실제 모바일 가로/세로에서 앞뒤와 두 측면, 문 접근·동굴 진입·다리 통행을 확인합니다. 물리와 재질이 연결되기 전의 모델 파일만으로 통합 완료를 선언하지 않습니다.

채택하지 않은 후보·일회성 캡처·완료 리뷰는 `build/` 또는 CI 아티팩트에서만 관리합니다. 현재 규격은 이 문서와 에셋별 설정에 유지하며, 채택 원본·라이선스·재생성 입력은 리뷰 기록과 구별해 보존합니다.

동굴 입구의 특수 규격: 원점은 입구 앞 골짜기 바닥 중앙이고+Z가 바깥,+Y가 위입니다. 암반은-Z로 깊어지며 로컬 바닥은0m에서 뒤쪽-1.2m로 내려가고, 입구 폭은3.92m, 홈 깊이는 약3.5m입니다. `plan.gd`의 윤곽·하강 함수·`frame()`과 검수한 `model.res`를 공유합니다. 실제 SOLID는 표시 메시 전체의 삼각형으로 만듭니다. 닫힌 원형 콜라이더나 검은 판을 다시 추가하지 않습니다. 모델 교체 시 같은 원점과 통로를 유지하며 원화는 원형 덩어리보다 비대칭 지층·돌출 암반·흙/풀의 상부를 참고합니다.


야외 웨이포인트는 `assets/models/environment/waypoint/`의 모델·셰이더·생성형 문양만 교체합니다. 상면 반경1.55m, 돌 기단 높이0.10m, 정면+Z, 원점은 주변 지면 중앙입니다. 문양은 기단 상면에 놓고 물리 FLOOR도 같은 높이로 만듭니다. 플레이어가 밟을 수 있어야 하며 수직 문·기둥·SOLID를 추가하지 않습니다. 발견 전은 어두운 회색, 발견 후는 절제된 석재색과 네 모퉁이 불빛을 사용합니다. 첫 활성화 판정·발견 저장은 `Exploration`의 소유입니다.

강둑 원화는 `assets/models/environment/riverbank/albedo.png`의2×2 아틀라스입니다. 좌상 젖은 암석, 우상 뿌리와 흙, 좌하 풀과 자갈, 우하 수중 자갈 바닥이며 실제 타일 밀도는2m입니다. 새 이미지 교체는 이 폴더와 대응 원본 폴더만 수정합니다. 실제 지형 높이·다리 접속은 공용 `NativeGroundRelief`가 담당합니다.


동굴 조형은 같은 폴더의 `sculpt.gd`에서0.30m 밀도장과 통로 차집합으로 만듭니다. 수정 후 저장소 루트에서 `sjrpg_3d/tools/godot.sh --headless res://assets/models/environment/cave_entrance/bake.tscn`으로 `model.res`를 재생성합니다. 런타임 `model.gd`는 저장된 메시만 읽으며 시작할 때 조형 계산을 하지 않습니다. 새 메시·제작기·공유 치수·원화 출처를 한 에셋 커밋에 포함하고 가로·세로 렌더, 실제 하강·천장·측벽 충돌을 함께 확인합니다.

동굴의 로컬 메시와 별개로 `frame()`은 주변 땅보다3.2m 낮고, 지형 통합 어댑터가 외부20m 하강로와 암반 측면을 연결합니다. 모델 교체 시 바깥 지면을0m로 가정해 입구 전체를 다시 올리지 않습니다.

정적 모델의 생성 코드는 에셋 루트에 `NativePlayerOcclusion.mark_object(root)`를 한 번 호출합니다. 벽·지붕·장식·부속 메시를 그 아래에 두면 가릴 때 모델 전체에 같은 투명도가 적용되며, 재질별 정적 배칭 후에도 소속이 유지됩니다. 나무처럼 각 인스턴스가 한 오브젝트인 MultiMesh에는 `occlusion_static_instances=true` 메타데이터를 지정합니다. 플레이어·NPC·몬스터에는 이 표시를 붙이지 않으며, 정적 모델 안의 움직이는 부품은 `occlusion_dynamic=true`로 제외합니다. 연속된 월드 지면·물·길도 등록하지 않습니다.
