# 네 개의 모험 저장

3D판은 최대 네 명의 수호자를 따로 저장합니다. 각 칸은 직업·레벨·장비·스킬·의뢰·상자·안식처·동굴 복귀 정보와 조우 상태를 모두 독립적으로 보관합니다. 빈 칸에서 직업을 골라 시작하고, 기존 칸에서는 이어하기를 누릅니다. 파일을 읽을 수 없는 칸도 사용 중인 칸으로 취급하므로 먼저 삭제를 확인해야 새 수호자를 만들 수 있습니다.

기존3D판의 단일 저장은 첫 번째 칸으로 옮겨집니다. 이전 원본과 백업은 변경하지 않으며, 첫 번째 칸에 이미 파일이 있으면 덮어쓰지 않습니다. 이 과정은2D판의 저장 경로나 파일을 읽지 않습니다.

## 저장 API

`GameState.MAX_SAVE_SLOTS`는3이며 `active_slot`은1부터3까지입니다. 기존4번 슬롯 파일은 자동 삭제하거나 다른 슬롯에 덮어쓰지 않습니다. 인덱스가 범위를 벗어난 요청은 현재 선택과 파일을 변경하지 않고 실패합니다.

| API | 동작 |
| --- | --- |
| `slot_summaries()` | 네 칸의 요약을 반환합니다. 수호자 상태를 불러오거나 자동 저장을 허용하지 않습니다. 최초 호출에서는 필요한 기존 저장 마이그레이션을 완료할 수 있습니다. |
| `select_slot(slot)` | 칸을 선택하고 이전 장면의 저장 권한과 조우 스냅샷 콜백을 해제합니다. |
| `create_slot(slot, cls)` | 빈 칸에 새 수호자를 만들고 저장합니다. 손상되거나 임시 파일만 있는 칸도 덮어쓰지 않습니다. |
| `load_game()` | 선택한 칸의 정상 파일 또는 정상 백업을 불러옵니다. 성공해야 해당 칸의 자동 저장을 허용합니다. |
| `save_game()` | 성공적으로 만들거나 불러온 현재 수호자를 현재 칸에 저장합니다. |
| `delete_slot(slot)` | 해당 칸의 알려진 저장·백업·임시 파일만 삭제합니다. 활성 칸을 삭제하면 늦게 도착한 자동 저장도 거부합니다. |
| `new_game(cls)` / `delete_save()` | 현재 칸에 대한 호환 API입니다. `new_game`도 사용 중인 칸을 덮어쓰지 않으며 성공 여부를 반환합니다. |

요약의 공통 키는 `slot`, `occupied`, `valid`, `class`, `level`, `location`, `sanctuary`, `timestamp`, `backup`입니다. `location`은 기존 저장의 `forest`/`cave`, `sanctuary`는 마지막 안식처ID입니다. `timestamp`는 UTC Unix초이며 날짜가 없던 이전 저장은0입니다. 화면의 날짜/시각만 기기 로컬 시간으로 표시합니다. 브라우저에서는 저장 시점의 시간대 오프셋을 구하므로 DST 전환을 반영하며, 네이티브에서는 Godot가 제공하는 운영체제 timezone bias(분)를 사용합니다. 이 변환은 저장된 timestamp나 진행을 다시 쓰지 않습니다. `backup`이 참이면 해당 칸은 정상 백업을 통해 이어갈 수 있습니다. 요약을 표시하거나 직업을 미리 보는 것만으로 현재 수호자의 진행을 바꾸지 않습니다.

## 파일과 마이그레이션

네이티브 파일은 프로젝트 전용 `user://guardian_save_slot_1.json`부터 `guardian_save_slot_4.json`까지입니다. 웹 파일은 기존의3D 전용 마운트 `/userfs/sjrpg_3d/` 아래에만 저장합니다. 각 칸은 `.bak`, `.tmp`, `.bak.tmp`를 자기 파일명 뒤에 붙입니다. 저장 형식 버전1은 그대로 유지하며 `saved_at`만 선택 필드로 추가합니다. `SaveStore`의 이전 정상본 백업·임시 파일을 통한 교체 규칙은 유지합니다.

이전 `guardian_save.json`과 백업·임시 파일은 첫 번째 칸으로 원문 그대로 복사합니다. `.migration` 영수증의 `pending` 상태는 중단된 복사를 다시 진행하고, `complete`는 다시 가져오지 않음을 뜻합니다. 복사는 `.migration-copy`에 쓴 뒤 이름을 바꾸며, 이미 복사한 목적지의 내용이 다르면 덮어쓰지 않고 중단합니다. 완료 영수증은 주 파일과 백업 모두에 기록합니다. 첫 번째 칸을 삭제하거나 새로 만들 때도 영수증을 남겨 이전 원본이 다음 실행에서 되살아나지 않게 합니다. 삭제는 마이그레이션 영수증과 이전 원본, 다른 칸, 다른 이름의 파일을 제거하지 않습니다.

테스트는 전용 `user://tests/` 경로에서 `save_path`를 바꿀 수 있습니다. 이때 값은 첫 번째 칸의 기준 경로이며 다른 칸은 같은 기준 이름으로 분리됩니다. 게임 UI는 경로를 직접 지정하지 않고 칸 인덱스 API만 사용합니다. `save_slots`는 네 칸의 진행 격리·백업 복구·개수 제한·삭제 후 자동 저장 거부·이전 저장 복사와 중단 후 재개를 검사합니다. 기존 게임 테스트는 새 수호자를 만드는 준비 단계에서 테스트 저장을 명시적으로 삭제합니다.
