# 직교3D 비교 장면

> 독립3D판으로 분리하기 전의 비교 모델 제작 기록입니다. 현재3D판은 숲·동굴에서도3D 공간을 유지합니다. 현재 구조와 제작 기준은 [루트 개발 안내](../../docs/development.md)와 [3D 에셋 제작 기준](../../docs/3d-asset-guide.md)을 따릅니다.

숲1장의 마을만 직교3D로 비교합니다. `3d.html` 전용 주소는 쿼리 없이도 예배당 곁에서3D로 시작하며 마법사 탭을 기본 선택합니다. 이전 `?preview3d=1&at=chapel_reference` 링크도 지원합니다. **설정 → 마을 표시 방식 →2D /3D**에서 위치·직업·체력·공격 시간을 바꾸지 않고 전환하며 일반 진입에는 저장한 기기 설정을 적용합니다. 전용3D 주소는 항상3D로 진입하는 비교용 예외입니다. 마을 밖과 동굴은2D이며 상단의 `3D 마을`/`2D 지역` 표시로 실제 렌더링 범위를 확인합니다. 후속 스테이지나 전체3D 물리 전환은 포함하지 않습니다.

## 실제로 바뀌는 부분

지면·다섯 건물·성벽·성문·분수는 입체 메시이며 실제 `DirectionalLight3D`와 한 장의1024 그림자 지도를 사용합니다. 접촉 때는 기존 `Effect`의 실제 명중을 관찰해 `OmniLight3D` 하나를 짧게 표시합니다. 공간별 면의 법선과 실제 기하가 조명·그림자에 사용되며, 건물 그림 전체를 평면으로 세워3D 건물이라고 표시하지 않습니다. 건물은 재질·투영·광원을 판단하는 기술 비교 모델이며 최종 레퍼런스 수준의 재제작 건축 원화라고 간주하지 않습니다.

예배당은 `Ortho3DChapel`의 실제 아치 개구부·3겹 석재 몰딩·오크 문짝/철물·양쪽 납선 유리창·부벽·슬레이트 처마·계단·개방된 종탑으로 구성합니다. 세부 도형은 공유 재질별 ArrayMesh로 합치며3만 삼각형/8재질 이내를 검사합니다. 문·네 창을 통과하는 광선과 모든 삼각형의 앞뒤 방향·유한한 법선·UV를 검사하며, 창을 막던 종탑 샤프트는 안쪽으로 옮겼습니다. 약한 따뜻한 반사광은 문과 전면 석재를 읽히게 하되 추가 그림자를 만들지 않습니다. 기존 배치와2D 충돌·단차 규칙을 유지합니다. 레퍼런스의 복합 현관 날개와 같은 최종 건축 모델을 완성했다는 뜻은 아닙니다.

마법사는 공식 무료CC0 소스의 실제 스켈레탈 모델과 정지·달리기·시전 동작을 사용합니다. 이 시제품은 검증된 원본 골격 배율을 유지하며 2D 배우/주민에 비해 약13% 크게 보일 수 있습니다. 런타임 축소 때 Compatibility에서 배우가 사라지는 현상이 실제 브라우저에서 재현되어 축소 후보는 제외했습니다. 최종 비례 조정은 골격·메시를 오프라인에서 함께 굽는 별도 작업입니다. `Ortho3DHeroMotion`이 기존2D 게임의 공격 진행도·이동 거리·접촉 자세 유지로 애니메이션을 구동합니다. 수동 seek에 끝나지 않는 크로스페이드를 남기지 않으며 대기를 반복합니다. 실제 이동 중 다리 뼈 회전과 시전·대기 시계, 일시정지/타격 정지를 검사합니다. 전사 모델이 준비되지 않은 경로에서는 원래 전사 스프라이트를 사용하며, 선택한 직업·저장을 마법사로 몰래 바꾸지 않습니다. 실제 공격의 접촉 정지·피격 색상·시각 반동·죽음 페이드는 원래 상태를 그대로 관찰합니다. 주민·몬스터는 기존2D 원화 카드로 남고 그림자를 새로 주장하지 않습니다. 마을 나무는 `Ortho3DTrees`의 실제 줄기·가지와 여러 방향으로 고정된 곡면 잎 묶음으로 교체합니다. 두 공유 GLB를 MultiMesh로 재사용하고 실제 광원·알파 컷아웃 그림자를 받습니다. 카메라를 따라 도는 빌보드는 쓰지 않으며 원래 나무의 발치·화면상 폭·수관 높이를 실제 메시 전체로 맞춥니다. 충돌은 기존 나무가 계속 담당합니다. 워프·상자는 기존 원화의 실제 보정 메시를 카드로 유지하며 상자가 깨지면 원본 상태를 따라 바뀝니다. NPC 이름·의뢰 표식·보호 체력바도 유지합니다. 이 구분은 네이티브3D 비교와 전체 자산 전환 비용을 혼동하지 않기 위한 것입니다.

HUD·설정·입력·전투·퀘스트·저장은 원래 게임을 유지합니다. 이동과 충돌도 기존2D 시뮬레이션이 담당하므로 전체3D 물리·높이 이동·계단 전환을 완료한 것이 아닙니다. 모든 맵을 새 네이티브 자산으로 변환한 상태도 아닙니다. 비교용 별도 렌더 타깃과 원래 시뮬레이션을 함께 실행하므로 이 샘플의 번들·메모리·프레임 비용을 최종3D 제품의 성능이라고 주장하지 않습니다.

기존 생성형 기술 원화는3D 카메라를 향한 발광 카드로 표시합니다. 인접 프레임은 원본과 같은 연속 보간을 하고, 수명·후반 페이드·회전·동작 감소 설정을 공유합니다. 시전 주변의 별도 선분 반짝임과 다른 절차형 보조 효과는 아직 전부 이식하지 않았습니다. 발치 아래에 그려진 서리의 전경 결정·타원을 지면이 잘라 버리지 않도록 효과에만 깊이 검사를 끄며, 주민 카드와 입체 나무의 일반 깊이 검사는 유지합니다. 이것은 기존2D 효과 순서를 보존하는 비교용 절충이며, 입체 얼음 메시나 높이에 따른 효과 차폐가 완료됐다는 뜻이 아닙니다. 반복되는 정적 건축 BoxMesh는 공유 재질별 MultiMesh로 묶습니다. 원래 크기·회전·위치·재질·그림자 설정을 유지하고 여덟 모서리를 검사합니다. 그룹 전체가 함께 컬링되는 절충이 있으며, Dummy 엔진은 인스턴스 변환 getter를 구현하지 않으므로 헤드리스에서는 CPU 계획만 검사합니다. 실제 브라우저의 `batch_corner_error_m`는 설치된 인스턴스 데이터를 다시 읽어 검사합니다. 절약 화질은 절반 해상도와 MSAA 끄기를 함께 사용합니다.

레벨업은 실제 `RewardFx`의 나이·수명을 따라 캐릭터 주변에 생성형 금빛 별과 발밑 고리를 표시합니다. 별도 타이머를 두지 않고 일시정지·동작 줄이기·연속 성장 한도를 따릅니다. 피해 숫자는 몬스터별 같은X의 세로 열로 흐르며 개별 피해량·순서·경험치 분리를 유지합니다. 숫자와 NPC 헤더는 앞쪽 나뭇잎보다 뒤에 덮이지 않는 표시 우선순위를 사용합니다.

네이티브 표시 레이어는 기존 절약 뷰포트보다 위·HUD보다 아래에 놓아 절약 화질에서도 빈2D 화면에 가려지지 않습니다.

Godot4.7.2 Compatibility의 Polygon2D는 hide/show 뒤 같은 형상을 다시 그릴 때 잘못된 index-buffer 갱신을 호출합니다. `Game.set_forest_rendered()`가 저장한 `visibility_layer`와0을 전환해 지형·재질·UV를 유지하고 렌더링만 가립니다. 마을 전환과 동굴 입출구가 같은 경로를 사용하며 낮빛도 실제 마스크/동굴 상태에 맞춰 즉시 끕니다.

## 투영 계약

카메라는 직교 투영이며 방위45°·고도35.2643897°입니다. `Iso.unproject()`의 지면 좌표를65지면 단위/미터로 변환하고, 실제 `Camera2D`의 화면 중심·줌·렌더 뷰포트에서 직교 크기를 구합니다. 세로·가로·절약 화질 모두 같은 투영을 유지하며, 높은3D 지점은 화면에 이미 포함된 높이를 먼저 복원해 접촉광 위치가 두 번 올라가지 않게 합니다.

직교 방향광의 그림자 범위는 `directional_shadow_max_distance`가 아니라 실제 카메라의 앞뒤 클리핑 구간을 사용합니다. 현재 화면의 지면과 최대11.5m 건축 높이를 기준으로 이 구간을 줌마다 맞춰 단일1024 지도의 정밀도를 확보합니다.

광선의 지면 진행 방향은 기존 캐노피의 화면 방향 `(0.72, 0.48)`을 역투영해 유지합니다. 입체 도형의 실제 축은 카메라 수학으로 검사합니다. 기존2D 건물의 실측 통과를 새3D 모델의 미감 완료 인증으로 재사용하지 않습니다.

성벽·날개벽은 `Ortho3DFortification`에서 실제 벽 바닥 폴리곤과 성문의 끝점을 합쳐 연결합니다. 띠장·캡·흉벽은 같은 높이와 재질을 사용하고 네 코너와 여덟 성문 접점을 검사합니다. 성문의 두 문짝은 정적 건축 배칭에서 제외해 실제 힌지 회전을 유지합니다.

## 재질과 출처

`tools/preview3d/prepare_materials.py`는 `assets/source/preview3d/village-materials.png`의 정면 생성형 석재·슬레이트·참나무·수피를 네 영역으로 잘라 WebP로 패킹합니다. 작은 원근 원화 조각을 확대하던 방식을 대신하며, 실제 첨부 참조·프롬프트·원본 해시는 `material-generation.json`, 출력 해시와 영역은 `assets/art/preview3d/materials.json`에 보존합니다. 석재는 세계 좌표 기준 2.56m당 8단을 공유해 성문·양방향 성벽·건물의 돌 크기를 통일합니다. 지붕은 실제 UV의 행을 경사에 가로지르게 맞추고 밉맵·이방성 필터를 사용합니다. 생성된 미세 자체 음영은 남으며 실측 PBR 스캔이나 완벽한 무이음 텍스처 인증은 아닙니다.

나무는 `tools/preview3d/prepare_trees.py`로 생성형 잎·공유 수피를 실제 분기 메시와 고정 곡면 잎 묶음에 연결해 만듭니다. 두 모델의 출처·기하 수·해시는 `town-trees.json`, 실제 생성 프롬프트와 참조 해시는 `assets/source/preview3d/trees/generation.json`에 있습니다.

배우의 공식 CC0 출처·모델 선택·클립·텍스처 해시는 `assets/art/preview3d/mage-manifest.json` 및 기존 영웅 소스 문서에 기록합니다. 작은 비교용 GLB는 512px 생성형 직물 베이스 컬러를 포함하며 미세 범프는 제외합니다. 분수 물의 네이티브 애니메이션은 아직 기술 샘플 수준입니다. 성문은 실제 통로 아치와 문짝·철물을 사용하고 `TownGateRuntime.progress`에 따라 열고 닫습니다. 일시정지와 동작 줄이기 설정을 따르며 독립적인 위협·충돌 규칙을 만들지 않습니다.

유리 원본과 정면 보정 사각형·해시는 `chapel-glass.json`과 `tools/preview3d/prepare_chapel_materials.py`에 기록합니다. 표면의 기존 자체 음영은 남으므로 중성 PBR 스캔이라고 간주하지 않습니다.

## 검수 인터페이스

웹의 `window.__sjrpg3dReady`는 실제 배우와 공간 그리기가 준비된 뒤에만 켜집니다. `window.__sjrpg3dProbe`는 네이티브 뷰포트 크기·화질·공간 그리기 수·프리미티브 수·그림자 프리미티브 수·현재 네이티브 표시 여부와 실제 카메라 각도를 보고합니다. Compatibility에서는 그림자 draw call이 visible에 합산되어 `shadow_draw_calls=0`일 수 있으므로 별도의 `shadow_primitives`와 실제 화면으로 확인합니다. 숨겨진2D 뷰포트의 숫자를3D 성능으로 기록하지 않습니다. 기존 `RenderProbe`와 별도입니다. `animation`은 실제 클립·샘플 시간·다리 뼈 회전을, `level_up_fx`는 실제 캐릭터 성장 효과 수를 보고합니다. `native_trees`와 `gate_progress`는 입체 나무 교체 수와 네 성문의 표시 진행도를 보고합니다.

루트 작업자는 `ortho_3d_preview` 검사와 실제 가로·세로 웹 화면, 첫 이동·시전·명중과 양 화질을 확인해야 합니다. 현재 문서는 검수 방법이며 브라우저 결과를 대신하는 완료 기록이 아닙니다.
