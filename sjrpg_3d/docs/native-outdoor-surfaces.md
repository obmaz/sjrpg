# 야외 잔디와 강물

잔디와 강물은 각각 독립 생성 원화10종을 사용합니다. 원본은1254×1254이며 편집·리사이즈하지 않습니다. 정확한 프롬프트·직접 첨부한 사용자 레퍼런스·파일 해시는 `assets/source/materials/{grass,water}/provenance.json`에 있습니다.

잔디는 짧은 풀·긴 풀·마른 풀·노출된 흙·습한 이끼·낙엽·들꽃·잔돌·밟힌 풀·혼합 식생을 의도한 원화입니다. 각 그림의 식물 모양은 생성 결과에 따르며 완전히 분리된 식생종으로 취급하지 않습니다. `grass_variety.gdshaderinc`가 넓은 서식지 분포와 작은 군락을 섞습니다. 낮은 지면과 높은 흙/돌 지형은 같은 배열과2.56m 배율을 사용하고 높은 지형의 색 대비를 유지합니다. 패치마다 독립된 회전과 네 개의 반 타일 오프셋을 분리 가능한 창으로 혼합합니다. 월드에서 연속적으로 휜 좌표를 사용해 서로 다른 원화의 대비가 직선 격자를 드러내지 않게 합니다. 두 대각 창만 쓸 때 생기던 교차점의 영점과 가장자리 누출을 없애며 가중치 합은 항상1입니다. 한 잔디 층당4회, 인접 서식지 두 층에 총8회 샘플링하며 추가 텍스처·메시·draw call은 만들지 않습니다. 레이어/회전 전환에서 이방성 필터의 샘플 범위가 달라져 단차를 만드는 것을 막으려고 잔디 배열만 명시적 미분과 선형 밉맵 필터를 사용하며, 원본·밉맵·압축은 유지합니다. 모바일에서도 큰 월드 좌표·회전·가중치·미분 계산이 정밀도를 잃지 않도록 해당 경로의 `highp`를 명시합니다. 길·강둑 거리장과 실제 보행 높이를 바꾸지 않습니다.

강물10종은 잔잔한 잔물결·긴 흐름·깊은 물·얕은 물·빠른 포말·소용돌이·바람 물결·흙빛 물·잔광·뒤섞인 흐름을 의도했습니다. `native_river.gdshader`는 고정된 월드 좌표에서 인접한 그림을 부드럽게 혼합하고 원래 두 유속·파도 법선·포말·강둑 알파를 이어받습니다. 프레임마다 메시를 다시 만들지 않으며 일시정지 때 위상을 고정합니다. 실제 수심 시뮬레이션을 추가한 것은 아닙니다.

`assets/models/materials/terrain/surfaces.gd`가 플랫폼에서 가져온 GPU 압축 이미지를 그대로 `Texture2DArray`에 묶고 정적으로 공유합니다. 종류당 한 샘플러를 쓰므로 바닥 셰이더의 기존 포장·강둑 샘플러와 함께 모바일의 샘플러 한도를 유지합니다. 압축 지원 렌더러에서는 `.import`의 실제 플랫폼 경로에서 CTEX v1/raw GPU 블록을 직접 읽습니다. 헤더·미터 패밀리의 크기·DXT1/ETC2 RGB8 형식·밉맵·블록 길이를 검사하며 고정된 Godot4.7.2 규격을 따릅니다. `Texture2D.get_image()`로 GPU를 읽으면 WebGL에서 RGBA로 전개되므로 이 경로를 피합니다. 헤드리스나 압축 미지원 렌더러만 엔진의 원래 변환을 사용합니다.1254픽셀 원본은 압축 블록 정렬 때문에 가져온 GPU 이미지에서1256픽셀이 되며 원본 파일은 바꾸지 않습니다. 압축 포맷·논리 크기·밉맵은 같은 배열 내에서 동일해야 하며 실패를 숨기지 않습니다. Web/S3TC와 Android/ETC2는 같은 원본에서 플랫폼별로 가져옵니다.

`natural_ground`는 실제 바닥/강물에 연결된10개 층과 원본 해시·배율·공유를 확인합니다. 가로/세로 실제 앱 화면에서 초지·길·강둑·다리와 연속 프레임의 강 흐름을 함께 확인합니다. 로컬 브라우저 검증과 실제 Android 기기의 성능 검증은 구분합니다.

실제 GPU 경계 회귀는 Compatibility 렌더러로 실행합니다. `DISPLAY=:0 sjrpg_3d/tools/godot.sh --rendering-method gl_compatibility res://tools/preview3d/check_grass_seams.tscn`은 양 끝의 색이 다른 진단 텍스처를 실제 공유 셰이더에 넣어 음수 좌표·타일 가장자리·반 타일 교차점·서식지 전환의 픽셀 단차를 검사합니다. DISPLAY 값은 실행 환경에 맞춥니다. 음수 좌표와 먼 필드 좌표도 검사하며 `-- --codec=s3tc` 또는 `-- --codec=etc2`를 추가하면 실제 가져온 압축 원화의 패치 경계도 검사합니다. 해당 코덱을 지원하지 않는 PC 드라이버는 Godot가 RGBA로 전개할 수 있으므로 입력 코덱 검수와 실제 휴대폰 GPU 검증을 구별합니다. 헤드리스 더미 렌더러는 이 검사를 대신하지 않습니다.
