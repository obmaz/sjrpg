# 소환 비석과 보물상자의 입체 자산

숲1장의 비석6개와 목재 상자, 기존 선택형 동굴의 쇠·황금 상자를 실제 입체 모델로 표시합니다. 비례·재질은 [3D 제작 기준](../../docs/3d-asset-guide.md), 크기·내구력·보상은 [상자 규격](native-chest-scale.md)을 따릅니다. 2D판은 동결합니다.

## 공유 모델과 재질

`EncounterGeometry3D`가 미터 단위의 닫힌 부피·후면·기단·빈 상자 내부·둥근 덮개·철띠·리벳·힌지를 만듭니다. 비석은0.80×0.4923m 기단과1.58m 높이이며 공유 석재를 씁니다. 상태 tint와 작은 인레이 발광은 원래 비석 상태를 읽습니다.

상자는 같은 몸체·뚜껑·파편 메시를 지역과 종류 사이에 공유합니다. 목재·쇠·황금 모두 `assets/materials/chests/albedo.png`의 평면 생성형 재질을 사용합니다. 앞면·옆면·곡면 뚜껑의 전용 그림을 각 면 전체에 한 번 배치합니다. 펼친 뚜껑 UV는 실제 반원 각도를 따라 이어지고, 정점색은 면 영역과 패널/실제 철물을 구분합니다. 종류별 셰이더를 캐시합니다. 원본·프롬프트·실제 첨부 참조는 `assets/source/materials/chests/`에 있습니다. 그림을 PBR 스캔이라고 간주하거나 별도 법선/거칠기 이미지를 만들어 기록하지 않습니다.

닫힘은2서피스, 열림은3서피스이며 표시기에 충돌체나 보상 시계가 없습니다. 실제3D 충돌은 `SpatialWorld3D`, 개봉·내구력은 `Chest`, 보상은 `Game.on_chest_broken`이 소유합니다.

## 지역과 상태 수명

`EncounterPropRenderer3D`는 개별 소스 ID만 소유합니다. 상자의 파괴가 `body_sprite`를 교체하면 새 ID를 인수하고 이전 fallback을 정리합니다. 재질 패밀리가 없으면 지원하지 않는 소스를 소유하지 않습니다.

비석 표시는 실제 충전·대기·피격 색, 상자 표시는 실제 `dead/hp/variant`를 읽습니다. 현재 지역의 소스만 보이며 동굴 진입 시 숲 모델을 숨겨 보관합니다. 새 동굴 상자를 표시하고 복귀 시 숲 모델의 개봉 상태를 복원합니다. 숨겨진2D 어댑터 조상의 가시성을 입체 모델의 표시 기준으로 사용하지 않습니다. 소스가 삭제되면 표시와 소유권을 정리합니다.

## 검증과 재현

`native_encounter_props`는 유한한 UV/법선·삼각형 감기·바닥·전체 뚜껑 회전·모든 배치의 실제 충돌·접근과 주변 통행·소스 상태·지역 왕복·삭제를 검사합니다. `cave_treasure`는 동굴 상자의 내구력·보상·저장 ID 분리도 확인합니다. 실측과 해시는 다음 명령으로 현재 제작 기록에 반영합니다.

```sh
python3 tools/review/models/record_encounter_props.py --log /path/to/native-encounter-test.log
```

`?loot_review=1`은 격리 브라우저 프로필에서 실제 숲 소스의 닫힘·열림·후면·소환·왕복을 검사하는 명시적 fixture입니다. 실제 모바일 가로/세로와 동굴 화면을 별도로 확인합니다. 검수 자료는 `build/`에 두며 이전 후보의 완료 기록을 현재 검증으로 사용하지 않습니다.
