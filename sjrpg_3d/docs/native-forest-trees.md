# 외곽 숲의 네이티브 나무

`ForestTreeRenderer3D`는 숲 1장의 기존 외곽 나무를 실제 가지·뿌리·입체 잎 메시로 표시합니다. 마을 나무와 같은 참나무2종·전나무·흑송·사이프러스의 공유 메시5개와 생성형 잎·침엽·나무껍질을 사용합니다. 새 원화나 재색칠은 없으며 [기존 제작 출처](../assets/source/vegetation/town_trees/generation.json)와 [기하 기록](../assets/models/vegetation/shared/tree_profiles.json)을 그대로 사용합니다. 2D 프로젝트에는 적용하지 않습니다.

원래 `Village.build_field`의 나무 위치·발치·배율·반사값을 읽고, 별도의 게임 RNG를 소비하지 않습니다. 프레임·발치 위치·반사값의 UTF-8 키를 FNV-1a로 해시해 메시 변형과 회전값을 결정합니다. 자식 순서나 인스턴스 ID가 바뀌어도 배치는 같습니다. 모든 정점을 투영해 원래 그림의 수관 폭과 상단 높이를 맞추며 X/Z는 같은 배율을 사용합니다. Y는 실제 `presenter.surface_height`의 네이티브 바닥 높이입니다. 기존 `village.circles`와 물리 실린더는 수정하지 않습니다.

마을 나무는 정확한 `town_trees` 멤버십으로 제외합니다. 외곽의 성공한 인스턴스 ID만 `EnvironmentRenderer3D`의 원화 카드 배치에서 제외하므로, 지원하지 않는 정의나 누락된 메시까지 무조건 숨기지 않습니다. 나무 루트는 `NativeForest` 소속이며 동굴에서는 같은 부모와 함께 숨겨지고 귀환 시 재사용됩니다.

16 m 지면 셀과 메시 변형별 MultiMesh를 사용합니다. 전체 숲을 하나의 AABB로 묶지 않으며, 각 묶음의 경계는 변환된 **전체 수관·뿌리·높이**를 포함합니다. 동일한 다섯 메시와 세 재질을 마을·외곽·모든 셀에서 공유합니다. 잎은 조명을 받는 양면 alpha-scissor 표면으로 실제 그림자를 드리우며 카메라를 따라 회전하지 않습니다.

[재현 레시피](../assets/data/native_forest_trees.json)는 해시·크기·배치·기하/알파 예산과 한계를 고정합니다. 실행 중 `NativeForestTrees`의 `native_forest_tree_layout` 메타데이터에는 각 나무의 원본 키·좌표·프레임·발치·배율·반사·변형·회전·네이티브 위치·Basis·충돌 반경이 JSON으로 직렬화 가능한 형태로 기록됩니다. `native_forest_tree_report`는 실제 소유 노드·묶음·인덱스·전체 수관 오차를 검수하기 위한 별도 런타임 참조입니다.

원본18프레임은 결정적 배치 키로 다섯 입체 변형에 대응하므로 기존 원화의 수종과 일대일로 같지는 않습니다. 수관의 폭/상단과 발치/충돌은 보존합니다. 활엽수 한 그루는 4,886삼각형이며 그중 잎은 3,016삼각형, 377개 스프레이입니다. 1024² 잎 텍스처의 alpha≥0.42 면적은 약 32.26%입니다. 이는 텍스처 알파 비율이며 실제 화면의 오버드로 비율이 아닙니다. 전체 배치 수만으로 프레임 향상을 주장하지 않습니다.

`ortho_3d_forest_trees`는 외곽 전체 소유권·카드 중복 방지·원래 충돌·결정적 배치·공유 메시·모든 정점의 셀 경계 포함·실제 높은 바닥의 뿌리·동굴 전환을 검사합니다. `ortho_3d_trees`는 기존 마을의 크기와 재질을 검사합니다. [전체 3D 기준](../../docs/3d-asset-guide.md)에 따라 실제 폰 세로/가로·두 방향 회전·그림자·수관 겹침·동일 전투의 프레임을 확인한 뒤 시각 채택을 판단합니다.

엔진 없이 원본 GLB·알파와 크기 피팅을 검사하려면 프로젝트에서 `python3 tools/review/models/audit_forest_trees.py`를 실행합니다. 실제 GLB 해시·삼각형 수·전체 표면 정점과 18개 원본 ID × 16개 회전의 수관 폭/상단을 검사합니다. 이 CPU 검사는 실제 Godot 렌더링·물리 레이·기기 성능을 대신하지 않습니다.
