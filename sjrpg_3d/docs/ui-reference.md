# 게임 UI 디자인 기준

사용자가 승인한 세로 레퍼런스(714×1280)를 최종 구도 기준으로 삼습니다.
HUD는 원화가 보이는 여백을 확보하고, 얇은 청동·은색 테두리와 실제 그림 아이콘을 사용합니다.
큰 단색 원, 한글 한 글자로 대신한 공격 아이콘, 두꺼운 외곽선, 큰 노란 행동 버튼을 사용하지 않습니다.

## 비율과 위치

아래 좌표는 레퍼런스 픽셀입니다. 구현은 안전 영역을 제외한 720×1280 기준으로 환산하며 가로 화면에서 모서리 기준으로 재배치합니다.

| 요소 | 위치·크기 |
| --- | --- |
| 초상화 | 중심 약 (57,126), 반지름 50, 얇은 어두운 청동 메달 |
| 현재 레벨 | 헤더 기준 32×32 메달을 초상화 왼쪽 위 테두리에 겹치고 실제 레벨 숫자 표시 |
| 상태창 | 우측 끝 x≈455, 체력·자원·경험치를 하나의 사선 금속 띠에 결합 |
| 미니맵 | 중심 약 (640,142), 반지름 64, 지역명은 바로 아래 작은 명판 |
| 조이스틱 | 중심 약 (103,922), 반지름 90, 바닥이 비치는 낮은 불투명도 |
| 주 스킬 | 중심 약 (559,948), 반지름 67 |
| 보조 스킬 | (441,947), (474,864), (555,827), (638,864), 기준 반지름 42–44에서 표시만 8% 축소 |
| 구르기 | 주 스킬 바로 오른쪽 (673,948), 표시 반지름 31 |
| 물약 | (596,750), (673,750), 표시 반지름 30, 개수는 아래 오른쪽 |
| 하단 메뉴 | x≈239/318/396/475, y≈1155, 세로 표시 반지름 34.1(10% 확대), 가로 31 유지 |

체력·자원·경험치·물약 숫자는 실제 게임 상태를 사용합니다. 전사는 분노, 마법사는 마나를 표시합니다.
사용자의 추가 크기 요청에 따라 초상화·상태창 묶음은 이전 82%에서 10% 확대해 위 기준의 90.2% 크기를 적용합니다. 레벨 메달은 헤더 기준 32px로 키워 초상화 왼쪽 위 테두리에 겹치고 숫자는 16px에서 맞춥니다. 이 확대는 헤더에만 적용하며 미니맵 배율은 유지합니다.
보조 스킬은 중심·터치 원을 유지하고 그림과 테두리만 8% 작게 표시합니다. 주 스킬 크기는 유지합니다.
폰 세로의 하단 메뉴 네 개는 그림을 10% 키우고 터치 반지름도 35로 넓히며, 기존 79 간격과 상호작용 버튼 사이 여백을 유지합니다. 가로에서는 기존 크기를 유지합니다. 메뉴 원화의 청동 림은 가는 가장자리 하이라이트와 작은 눌림 깊이로만 다듬습니다.
하단 네 개는 후속 요청에 따라 `MobileMenuArt`의 큰 가방·펼친 책·두루마리·여덟 톱니 그림으로 교체합니다. 어두운 올리브 바탕·얇은 청동 림·따뜻한 밝은 실루엣을 공유하고, 미세한 장식·가죽 결·금장·글씨를 넣지 않습니다. 실제 생성 원본/프롬프트/영역/해시는 `mobile_menu_generation.json`·`mobile_menu_measure.json`·`assets/data/mobile_menu.json`에 고정합니다. 48/64px에서 확인하고 기존 버튼 중심·터치 범위·스킬 포인트 표식은 유지합니다.
설정의 화면 확대는 0.5×·1×·1.5× 세 가지이며 월드만 확대합니다. 선택 상태와 저장값을 연결하고 HUD·팝업·버튼 크기는 유지합니다.
워프게이트의 화면 행동은 글자22·표시184×56·터치212×76 기준의 ‘워프 이동’ 명판으로 키우며, 하단 메뉴와 최소10 단위 간격을 둡니다. 목적지 창의 실제 이동 버튼은 높이96·글자26(패널 배율 적용)으로 표시하고 발견한 다른 목적지를 먼저 배치해 가로 화면에서도 첫 이동을 바로 누를 수 있게 합니다.
보조 슬롯이 비어 있으면 낮은 대비의 각인 소켓으로 표시하고 누르면 스킬 화면을 엽니다.
레퍼런스를 흉내 내려 배우지 않은 스킬을 장착하거나 수치·성장 규칙을 바꾸지 않습니다.
원형 버튼의 표시 크기와 터치 영역을 구별하여 물약·구르기·메뉴도 최소 64 단위 터치를 유지합니다.
스킬·물약·구르기의 누름/재사용 표시, 조이스틱+공격 멀티터치, 열려 있는 팝업의 입력 차단은 유지합니다. 체력이 30% 미만이면 화면 전체에 천천히 붉은 경고가 들어오며 장면과 HUD를 읽을 수 있는 낮은 불투명도를 사용합니다. 회복·사망 시 경고를 숨기고, 동작 줄이기는 고정된 옅은 경고색을 사용합니다.

## 재료와 팝업

- HUD 숫자는 NanumGothic Regular와 얇은 그림자를 사용합니다. 원형 스킬은 청백색의 가는 이중 베젤을 사용합니다.
- 팝업은 따뜻한 차콜 가죽 표면·미세한 청동 이중 프레임·크림색 글자로 HUD와 연결합니다.
- 버튼은 어두운 안쪽 면과 빛 받는 금속 테두리로 상태를 구분합니다. 선택·주요 행동·포커스·비활성을 색과 명암으로 구별합니다.
- 큰 패널은 안전 영역 안에서 본문을 스크롤하고, 대화·확인은 내용 높이에 맞춰 중앙에 표시합니다. 닫기는 원형 메달입니다.
- 제목·부제 사이 10px, 헤더·본문·푸터 사이 18px, 카드 제목·설명 사이 8px를 확보합니다. 긴 부제는 줄바꿈하고 닫기 버튼은 64×64를 유지합니다. 좁은 화면의 긴 행동 버튼은 세로로 배치합니다.
- 장비 카드는 재료색을 유지하면서 등급·선택·장착 상태를 구별합니다. 본문과 버튼은 화면 회전 후에도 겹치지 않아야 합니다.

## 자산과 검증

`assets/source/{portrait-mage,panel-leather,potions,level-badge}.png`는 보존하는 원본이며,
`python3 tools/prepare_ui_art.py`로 작은 WebP와 물약 두 칸 시트를 패킹합니다.
`assets/art/hud/reference-buttons.webp`는 원본 저장소의 동일한 원형 메뉴 원화를 사용합니다.
스킬 그림은 원본 스킬 시트와 실제 검·질주 그림을 재사용하고, 스킬·빈 슬롯·미니맵 링과 팝업 모서리는 [같은 생성형 금속 패밀리](presentation-design.md)를 사용합니다. 링 중앙·외부는 실제 투명 알파이며 쿨타임·상태 숫자는 HUD로 표시합니다.
새 UI 이미지는 손실 임포트 모드 1을 사용합니다.

`hud_layout`, `ui_input`, `panel_layout`, `skill_layout` 검사는 배치·화면 회전·충분한 터치 크기·영역 겹침·입력 해제를 확인합니다.
그림을 바꾸면 실제 브라우저의 마법사/전사, 폰 세로/가로, HUD·가방·스킬·설정·대화 화면을 함께 확인합니다.
`tools/screenshot.mjs --scene chapel --class mage --device phone`으로 승인된 구도와 비교할 수 있습니다.

## 헤더의 정밀 배치

- 헤더 배율은 안전 영역을 뺀 짧은 변을 기준으로 계산합니다. 긴 폰에서도 위쪽 기준점은 720×1280 구도와 같게 유지합니다. 아바타 문장과 미니맵 원형 테두리의 그리기 상단을 안전 영역에서 16 화면 단위 아래로 맞춰 이전보다 위쪽에 배치합니다.
- 초상화의 문장·외곽선·그림자를 포함한 실제 그리기 범위를 확보합니다. 금속 띠뿐 아니라 체력·자원·경험치 막대의 왼쪽 면도 초상화 오른쪽 곡선을 따릅니다. 세 막대를 같은 수직선에서 시작해 넓은 검은 틈을 남기지 않습니다. 원형 테두리가 접점을 마감하고 막대의 왼쪽 외곽선을 중복하지 않습니다. 각 높이의 실제 가시 폭에 채움 비율을 적용해 1% 같은 작은 값도 곡선 영역 전체에서 정확히 표시합니다.
- 체력·자원·경험치 바와 바깥 프레임의 오른쪽 사선은 기울기 0.28로 평행하며 금속 여백을 일정하게 유지합니다. 부분 채움과 피해 잔상도 사선 안으로 잘라 그립니다.
- 숫자는 실제 글꼴의 폭·높이·기준선로 행 안에 맞춥니다. 긴 수치·상태·목표 문구도 초상화나 미니맵 쪽으로 넘치지 않습니다.
- 미니맵의 중심·반지름·나침반 구도는 유지하며 그림자와 안티앨리어싱까지 영역 안에 넣습니다. 마커는 점의 전체 반지름이 원 안에 드는 경우에만 표시합니다.

`hud_header`·`minimap_border`는 0%·작은 채움·99%·100%, 긴 숫자, 안전 여백, 작은/큰 배율을 검사합니다.
`--scene hud|hud_low|hud_nearfull|hud_large`는 검수용 실제 수치를 고정한 웹 화면을 캡처합니다.
이 명시적인 미리보기에서만 회복·시간 흐름을 멈추며 일반 모험의 수치·시간은 바꾸지 않습니다. `--scene hud_danger`는 검수용 배우·안식처 회복만 고정하고 실제 HUD 경고 시계는 움직여 두 시점을 비교합니다.
