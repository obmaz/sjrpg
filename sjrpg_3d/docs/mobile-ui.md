# 모바일 UI 배치와 검수

설정·스킬·원정·일지·가방·장비·일시정지와 진입 화면은 실제 글자·조작·스크롤을 기준으로 검수합니다.
생성형 컨셉은 자산 출처이며 화면 크기별 배치의 정답으로 사용하지 않습니다.

## 공용 계약

- `UiMetrics.units_per_display_pixel()`은 웹 CSS px, Android dp를 Godot 논리 좌표로 바꿉니다. Android 창 크기는 물리 픽셀이므로 `screen_get_dpi()/160`을 반영합니다. 접힘 전환 중 크기가 없으면1배로 시작하고 크기 변경 후 다시 맞춥니다.
- `UiKit`은 차콜·숲빛 면, 얇은 청동 테두리와 밝은 본문색을 공유합니다. 큰 모서리 장식이 작은 카드와 버튼의 글자를 덮는9패치 재사용은 하지 않습니다.
- `PanelFrame`은 안전 영역 안의 헤더/닫기, 스크롤 본문, 고정 푸터를 분리합니다. 제목·부제와 본문·조작 사이의 가독 간격을 확보합니다.
- 본문·상태·수치는 가독 고딕과 최소14표시 단위를 사용합니다. 핵심 버튼은 최소44표시 단위의 실제 터치 범위를 유지합니다.
- 긴 제목·상태·가격·실패 이유는 줄바꿈합니다. 고정 행·열 수보다 실제 최소 크기로 열 수와 세로 배치를 결정합니다.
- 버튼 내부 장식도 드래그를 스크롤에 전달합니다. `Range`와 독립 스크롤의 입력 소유권은 유지하며, 스와이프 종료가 선택/삭제/장착/설정 변경으로 실행되지 않아야 합니다.
- 저장 목록이 넘칠 때는 더 볼 내용이 있음을 안내합니다. 네 저장이 모두 들어가는 큰 화면은 남은 높이를 분배하고 카드의 초상·번호·본문을 가운데 정렬합니다.
- 폰트 변경 뒤에는 최소 크기 갱신을 기다려 절대 배치를 정착시킵니다. 같은 값의 폰트/문구를 반복해서 쓰며 무한 재배치를 만들지 않습니다.

## 검수

일반 폰390×844/844×390, 작은 폰320×568/568×320, 외부 화면을 대표하는344×883/883×344,
펼친 비율768×896/896×768과800×800을 확인합니다. 이는 대표 비율 검수이며 특정 Fold 실기기의 측정값을 뜻하지 않습니다.

`panel_layout`, `panel_scroll`, `ui_tone`, `skill_layout`, `bag`, 진입·저장·설정 회귀를 검사합니다.
실제 웹의 `tools/check_mobile_panels.mjs`는 한 번 부팅한 게임에서 실제 입력으로 패널을 열고 글자/조작 크기와 스와이프·끝 내용 접근을 검수합니다.
`tools/check_save_layout.mjs`는 실제 저장 행에서 손가락 드래그를 시작해 오발 없이 목록이 움직이는지 검사합니다.
`tools/check_entry_loading.mjs`는 실제 진입의 페인트 장벽과 로딩 표시를 확인합니다.
검수 probe는 명시적 `inspection=1&ui_layout_review=1`에서만 추가하며 위치나 게임 상태를 바꾸지 않습니다.
일회성 화면·진단은 `build/reports/`에 둡니다.
