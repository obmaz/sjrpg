# 타격감 진단 리포트

"시원한 타격감이 안 난다"는 증상을 [전투 피드백과 타격감](juice.md)의 설계 계약과 실제 구현 값으로 대조한 결과입니다.
결론부터: **시스템은 이미 다 갖춰져 있고, 모든 채널의 상한이 너무 낮게 잡혀 합산 임팩트가 사라진 상태**입니다.
특히 사람이 가장 크게 느끼는 두 채널인 **화면 충격**과 **타격음**이 사실상 0에 가깝습니다.

측정 기준은 720 논리 픽셀(폰), 60fps, 기본 월드 줌(1.05)·`CAMERA_WORLD_SCALE=1.6`입니다.

가장 중요한 관찰: **초반 기본 공격은 이미 대부분 HEAVY로 판정됩니다**(숏소드 15공격력 → 피해 약 9.6, 고블린 최대 체력 22.4의 43%).
즉 단계가 낮아서가 아니라, **가장 강한 단계조차 절대량이 작아서** 손맛이 안 납니다. 값을 키우는 작업이 곧 효과가 있는 작업입니다.

## 우선순위

| 순위 | 원인 | 현재 값 | 증상 |
| --- | --- | --- | --- |
| 1 | 카메라 흔들림이 서브픽셀 | 최대 0.45px → 화면 0.76px | 맞은 느낌이 화면에 전혀 안 옴 |
| 2 | 타격음이 믹스에서 가장 작음 | 명중 -8dB, 악센트 -12dB, 음악 -6dB | 때리는 소리가 배경음에 묻힘 |
| 3 | 히트스톱이 2~4프레임이고 프레임 전체가 멈추지 않음 | 40/55ms, 액터만 정지 | "멈칫"이 아니라 "끊김"으로 읽힘 |
| 4 | 스윙이 1.5배 빨라 준비 동작이 없음 | 전체 0.27~0.34s, 접촉 0.12~0.15s | 휘두르는 무게가 안 실림 |
| 5 | 명중 VFX의 밝은 면적이 작음 | 밝은 코어 16~58px, 가산 합성 | 야외에서 플래시가 사라짐 |
| 6 | 피해 단계가 최대 체력 비율 | 보스 1800HP에서 항상 LIGHT | 중요한 전투가 가장 밋밋함 |
| 7 | 진동·적 반응이 미세함 | 진동 12ms, 리코일 5~14px | 손과 눈에 반응이 안 옴 |

| --- | --- | --- | --- |
| 카메라 이동 | `IMPACT_LIMIT 0.65` × 명중 계수 0.45 | 약 0.76px, 55ms에 소멸 | 사실상 없음 |
| 줌 펀치 | HEAVY 0.1%, KILL 0.15%, 상한 0.2% | 중심 300px 지점 0.3px | 사실상 없음 |
| 히트스톱 | 적 40/55ms, 공격자 35/50ms, 처치 75ms | 60fps에서 2.4~3.3프레임 | 짧고, 액터만 멈춤 |
| 정지 재사용 창 | `recovery = 0.14` | 140ms 안 재타격은 정지 없음 | 연타 시 절반이 무반응 |

| 샘플 원본 | 22.05kHz 모노, 피크 -4.4dBFS, RMS -18~-21dBFS | -8dB 적용 시 RMS 약 -26dBFS | 여유가 아니라 과소 |

| 동시 발음 | 8보이스, 70ms 게이트 | 5명 광역 타격 = 소리 1회 | 다중 타격이 1대로 |
| 명중 카드 | 지름 100/140px, 성장 0.64~1.16배, 0.22/0.28s, 가산 합성 | 화면 107~272px | 아트의 밝은 부분은 셀 면적의 2~9% |
| 명중 파편 | 4/6/8개, 3.5cm × 13~21cm, 2.0~3.35m/s | 0.21s 안에 소멸 | 얇고 적고 몸통에 가림 |
| 킬 링 | 두께 7% 바닥 링, 지름 약 1.7m, 0.3s, 가산 | 링 하나가 0.3s 퍼짐 | 파편·먼지·쓰러짐 없음 |
| 피해 숫자 | 22/26/32/36pt, 0.9s | 화면 약 37~60px(고블린 키의 40~70%) | 무난, 팝은 80ms만 |
| 진동 | hit 12ms, kill 46ms, hurt 90ms | 12ms는 모터 기동 전에 끝남 | hit·kill 무감 |
| 적 반응 | 리코일 5/8/14px, 기울기 0.16~0.38rad, 300ms | 화면 8~24px | 작지만 방향은 맞음 |
| 처치 연출 | 흰 플래시 + 얇은 링 + 0.25s 페이드 후 소멸 | 쓰러지는 동작 없음 | 가장 아쉬운 구간 |

## 원인

### 1. 카메라가 1픽셀도 안 움직인다

```gdscript
# game.gd
const IMPACT_LIMIT := 0.65
_impact_offset = direction * clampf(strength, 0.0, 1.0) * (IMPACT_LIMIT if hurt else 0.45)
```

명중 시 최대 0.45 월드 픽셀이고, 이 값은 `camera.offset`에 들어가 줌(1.68)만큼 곱해져 화면에서 약 0.76px가 됩니다.
720px 화면의 0.1%입니다. 게다가 `exp(-18Δt)`로 감쇠해 55ms면 사라지며, 방향이 한 번만 꺾이고 되돌아오지 않는 **단방향 밀림**이라 진동이 아니라 미세한 드리프트로 보입니다.

줌 펀치도 같은 문제입니다. `ZOOM_PUNCH_LIMIT := 0.002`(0.2%)는 화면 가장자리에서도 1px 미만입니다.
`docs/juice.md`가 "카메라 이동을 절제한다"고 명시한 결과인데, 절제 수준이 **지각 한계 아래**로 내려가 버렸습니다.

- 제안: 명중 3~6px, 강타 6~9px, 처치 10~14px(720 기준). 왕복 2회(예: 12Hz 감쇠 사인)로 바꿔 "밀림"이 아니라 "충격"으로 읽히게 합니다. 줌 펀치는 0.6~1.0%, 90ms로 올려야 지각됩니다. 접근성 설정은 그대로 `reduce_motion`으로 유지합니다.

### 2. 타격음이 음악보다 작다

측정한 샘플은 피크 -4.4dBFS, RMS -18~-21dBFS로 원본 여유가 충분한데, 재생 볼륨이 명중 -8dB·악센트 -12dB입니다.

```gdscript
static func contact_volume_db(name: String) -> float:
	return -8.0 if name.begins_with("impact") else -12.0
```

`playback_volume_db()`는 나머지 효과음에 -4dB를 주고, 음악은 `BASE_DB := -6.0`입니다.
즉 **가장 중요한 소리(명중)가 가장 조용하고, 덜 중요한 소리(피격·경고·루팅)가 더 큽니다.** 여러 겹을 합쳐도 음악보다 4~6dB 아래로 추정됩니다. 게다가 보이스 게이트가 70ms라 5명을 한 번에 베어도 소리는 1회만 납니다.

```gdscript
if not preview and now - int(_last.get(gate, 0)) < 70:
	return
```

- 제안: 명중 -2dB, 악센트 -6dB, `hurt`를 -6dB로 낮춰 명중이 믹스의 최상단에 오게 합니다. 음악에 명중 시 80ms 덕킹(-3dB)을 넣으면 음량을 크게 올리지 않고도 분리됩니다. 게이트는 70ms → 45ms로 줄이고, 광역 타격은 "가장 강한 1회 + 나머지는 60% 음량"으로 남깁니다.
- 기본 파형도 손봐야 합니다. `impact` 계열은 180→48Hz 사인 중심이라 **폰 스피커(300Hz 이하 급감)에서 저역이 거의 안 들립니다.** 300~800Hz 대역의 짧은 크랙 성분을 별도 레이어로 넣고, 살·뼈·암석 샘플(`hit_flesh`/`hit_bone`/`hit_stone`)을 -6dB로 올려 질감을 앞으로 뺍니다.

### 3. 히트스톱이 프레임을 멈추지 않는다

```gdscript
# game_tempo.gd — 액터 로컬 정지
func trigger(seconds: float, limit := 0.055) -> void:
	if Prefs.reduce_motion or remaining > 0.0 or recovery > 0.0:
		return
	remaining = clampf(seconds, 0.0, limit)
	recovery = 0.14
```

문제는 세 가지입니다.

1. 40/55ms는 60fps에서 2.4~3.3프레임입니다. 지각되는 "멈춤"은 보통 60~90ms부터입니다.
2. 정지는 **맞은 적과 공격자만** 받습니다. 카메라와 다른 적, `Effect`(명중 카드·파편·피해 숫자)는 `Engine.time_scale`을 건드리지 않으므로 **정지 중에도 그대로 흐릅니다.** 결과적으로 화면이 멈춘 게 아니라 배우만 끊긴 것처럼 보입니다.
3. `recovery = 0.14` 때문에 140ms 안의 다음 타격은 정지가 아예 없습니다. 기본 공격 간격이 0.27~0.34s라 연타의 상당수가 무반응 구간에 들어갑니다.

- 제안: 일반 60ms, 강타 90ms, 처치 120ms. 정지 중에는 명중 카드·파편의 `_process`도 함께 멈춰 **한 프레임을 통째로 붙잡는** 느낌을 만듭니다(현재 구조는 `Effect`에 시간 배율 인자만 넘기면 됩니다). `recovery`는 90ms로 줄입니다.

### 4. 스윙이 너무 빠르다

```gdscript
const RATE := 1.5          # game_tempo.gd — 모든 동작 1.5배
_attack_duration = GameTempo.duration(0.4 / ...)   # 0.267s
_pending 실행 시점 = CONTACT_PROGRESS 0.45          # 입력 후 약 0.12s
```

무기 tempo는 0.25~0.52s이고, 초반 숏소드는 0.34s, 기본 근접은 `GameTempo.duration(0.4)=0.267s`입니다.
접촉은 그 45% 지점이라 **입력 후 0.11~0.15초 만에 피해가 들어갑니다.** 준비(anticipation) 없이 결과만 나오므로 무게가 실릴 시간이 없습니다.
`weapon_draw`(준비음)는 -13dB라 사실상 들리지 않아서, 귀로도 스윙 시작을 알 수 없습니다.

- 제안: 기본 공격만이라도 전체 0.36~0.42s로 되돌리고, 접촉을 0.55~0.6 지점으로 미룹니다. 준비 구간에 무기를 들어 올리는 프레임과 `weapon_draw`를 -6dB로 올려 "들었다 → 내려친다"의 두 박자를 만듭니다. 연타감은 후속 공격의 팔로스루를 줄이는 방식으로 유지합니다.

### 5. 명중 VFX는 크지만 밝은 부분이 작다

합성 방식 자체는 맞습니다. 명중 카드는 `blend_add, depth_test_disabled`로 그려져 몸통에 잘리지 않고, 파편도 가산 합성입니다.
문제는 **아트의 실제 밝기**입니다. `assets/effects/textures/combat-frames.webp`를 측정하면 4×4 셀 대부분이 검정입니다.

| 물리 타격 프레임 | 밝은 면적(휘도>0.5) | 셀 평균 휘도 |
| --- | --- | --- |
| contact | 2.2% | 0.04 |
| peak | 8.7% | 0.14 |
| fragments | 3.1% | 0.07 |
| tail | 1.1% | 0.03 |

카드는 화면에서 107~272px로 적 키(고블린 약 87px)의 1.2~3배까지 커지지만, 실제로 밝은 부분은 셀 면적의 2~9%(선형 15~30%)뿐이라 **밝은 코어는 16~58px**에 머뭅니다.
여기에 가산 합성이라 **밝은 낮 숲 바닥 위에서는 밝기가 더해져도 대비가 거의 늘지 않습니다.** 어두운 동굴에서는 보이고 야외에서 사라지는 이유입니다.

- 제안: 물리 타격 프레임의 밝은 면적을 2배 이상으로 키우고(코어 확대), 가산 위에 얇은 흰색 코어를 한 장 더 겹칩니다. 야외에서는 가산만으로 부족하므로 `blend_mix` 기반의 짧은 플래시 1프레임(30~40ms)을 추가하는 편이 대비를 만듭니다.
- 파편은 `SPARK_CODE`에 `depth_test_disabled`가 없어 몸 뒤가 가려집니다(의도된 처리지만 체감 크기를 줄입니다). 수를 8/12/16, 길이를 0.2~0.35m로 올리고 몸 바깥으로 더 밀어냅니다.
- 킬 연출은 두께 7%의 바닥 링 하나가 전부입니다. 링 지름은 약 1.7m로 작지 않지만 **파편·먼지·쓰러짐이 없어** "터졌다"는 느낌이 없습니다.

### 6. 보스전은 항상 LIGHT다

```gdscript
# hit_tier.gd — 최대 체력 대비 비율
const MEDIUM_RATIO := 0.10
const HEAVY_RATIO := 0.30
```

일반 몹(고블린 최대 22.4, 해골 41.6)에서는 초반 기본 공격이 MEDIUM~HEAVY에 걸립니다.
문제는 큰 체력 대상입니다. `ForestBalance.BOSS_HP = 1800`인 보스에서는 20데미지도 1.1%라 **영원히 LIGHT**이고, 후반 지역은 `scale_factor = 1 + (level-1)*0.22`로 최대 체력이 커져 같은 피해가 낮은 단계로 떨어집니다.
결과적으로 **가장 긴장되는 전투가 가장 밋밋한 피드백**을 받습니다.

- 제안: `HitTier`를 "비율 + 절대 하한"으로 보정합니다. 예: 비율 판정을 유지하되 `amount >= max_hp * 0.02`이면 최소 MEDIUM, 처치·약점·스킬 피해는 한 단계 승격. 보스에게는 "누적 피해 게이지" 기준으로 강타를 주는 편이 자연스럽습니다.

### 7. 손과 눈에 오는 반응이 너무 작다

- 진동: `{"hit": 12, "kill": 46}`ms. 모터가 돌기 시작하기도 전에 끝나는 길이입니다. **30ms 이상**이어야 지각되고, 명중 30ms·강타 45ms·처치 70ms가 적당합니다. 현재는 피격(`hurt 90ms`)만 손에 느껴져 "맞는 게 더 아프게" 느껴집니다.
- 적 반응: 리코일 5/8/14px(화면 8~24px)에 0.26s, 기울기 0.16~0.38rad. 방향은 맞지만 크기가 작습니다. 8/14/22px, 처치 시 24px + 0.35s로 올립니다.
- 처치 연출: 흰 플래시 후 **0.25초 알파 페이드로 그냥 사라집니다.** 쓰러지는 회전·낙하·먼지가 없어 가장 시원해야 할 순간이 가장 조용합니다. 모델을 25~30° 눕히며 0.35s에 걸쳐 가라앉히고, 발치에 짧은 먼지 카드를 추가하는 것만으로도 차이가 큽니다.

## 권장 적용 순서

한 번에 모두 바꾸면 무엇이 효과가 있었는지 알 수 없습니다. 아래 순서로 나눠 실제 폰 화면·청음으로 비교합니다.

1. **화면(1번)**: 카메라 3~6px 왕복 + 줌 0.6%. 코드 변경량이 가장 적고 체감 차이가 가장 큽니다.
2. **소리(2번)**: 명중 -2dB, 악센트 -6dB, 게이트 45ms, 음악 덕킹. 청음으로 검증합니다.
3. **시간(3·4번)**: 히트스톱 60/90/120ms + VFX 동반 정지, 기본 공격 0.36~0.42s.
4. **VFX(5번)**: 명중 아트 코어 확대, 짧은 불투명 플래시 1프레임, 파편 확대.
5. **반응(7번)**: 진동 길이, 리코일, 처치 연출.
6. **단계(6번)**: 보스·고체력 대상의 최소 단계 보정.

`Prefs.reduce_motion`은 지금처럼 모든 채널을 한 번에 끄는 계약을 유지합니다. 대신 새로 넣는 카메라·진동도 같은 스위치를 통과해야 합니다.

## 주의: 이미 잘 되어 있는 부분

- 피해 단계가 숫자·소리·카메라·피격 반응을 한 곳에서 묶는 구조는 유지할 가치가 큽니다. 값을 키우는 작업은 `hit_tier.gd`와 `game.gd` 상수만 건드리면 됩니다.
- 명중 접촉점을 근접/투사체별로 실제 3D 위치에서 얻는 처리, 파편 풀 재사용, 효과 예산 64, 확정 피해만 표시하는 원칙은 그대로 두는 것이 맞습니다.
- 성능 예산 때문에 상한이 걸린 항목은 카메라(비용 0), 사운드(볼륨만 변경), 히트스톱(로직만 변경)이라 **비용 증가가 거의 없습니다.** 파편 수를 늘릴 때만 `MAX_BURSTS 12`·`SPARKS 8` 예산을 다시 확인합니다.

## 검증 방법

```sh
cd sjrpg_3d
tools/check.sh --only=juice,juice_tier,juice_player,juice_enemy,hit_flash,native_hit_feel
tools/export_web.sh && tools/serve.sh
node tools/screenshot.mjs --scene juice --device phone
node tools/screenshot.mjs --scene damage_stream --device phone
node tools/screenshot.mjs --scene game_feel --device phone
node tools/screenshot.mjs --scene fx_slash --device desktop
```

`native_hit_feel`은 실제 피해 콜백·접촉 자세·숫자 팝·정지·파편 예산을 검사합니다. 수치를 바꾸면 이 테스트의 기대값도 함께 갱신해야 합니다.
카메라·진동은 정적 캡처로 검증되지 않으므로, **Android 실기에서 30초 이상 연속 전투를 청음·진동 확인**하는 절차가 필요합니다. 헤드리스 테스트 통과를 타격감 검증으로 대체하지 않습니다.
