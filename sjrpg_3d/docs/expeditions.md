# 계약 원정 구조

숲 1장은 계약을 고르고 임무 2개와 선택 도전을 거쳐 봉인·보스·귀환으로 끝나는 한 회차입니다. 사용자는 원정 중 기술을 바로 얻고, 지원 룬으로 조합을 바꿉니다. 기존 캐릭터와 원정 진행은 같은 저장 슬롯에 별도 수명으로 보관합니다. 사용자 흐름은 [3D 안내](../README.md#계약-원정과-스킬-조합), 공간 규칙은 [개발 구조](development.md)를 참고하세요.

## 책임과 저장 수명

| 소유자 | 책임 |
| --- | --- |
| `ExpeditionContent` | 챕터·계약·선택지 풀·룬 데이터 읽기 |
| `AbilityLibrary` | 새 기술 폴더 탐색, 행동과 아이콘 별칭 |
| `ExpeditionState` | 단계·목표·저장 데이터 검증 |
| `ExpeditionProfile` | 기존 캐릭터·장비·의뢰·발견 기록의 보관과 복구 |
| `ExpeditionRun` | 선택의 저장 트랜잭션, 숲 의뢰·소환 무리·동굴·보스 콜백 연결 |
| `RunBuild` | 별도 결정적 난수로 3지선다 생성, 룬 호환성과 실제 전투 수정 |
| `ExpeditionPanel`, `RunBuildPanel` | 계약/보상 선택, 배운 기술과 룬의 배치 |

원정 중 상위 `GameState`의 레벨·장비·의뢰는 현재 원정 값이며, 원래 캐릭터는 `expedition.profile`에 있습니다. 출발/결산은 저장에 성공한 뒤에만 월드를 재생성합니다. 재생성 전 기존 월드를 즉시 멈춰 지연된 공격/보상 콜백이 복구된 캐릭터를 변경하지 않게 합니다. 일반 선택도 저장 실패 시 되돌립니다. 기존 네 슬롯, 임시 파일/백업, 예전 저장의 기본값 처리는 유지합니다. 원정 스냅샷 안에 원정이 중첩되는 데이터는 거부합니다.

회차의 기술·룬·장비는 결산 때 사라집니다. `expedition_meta.renown`, `runs`, `clears`는 남습니다. 사망 또는 마을에서의 포기는 명성 없이 종료하고 성공은 실제 촌장 근처에서 한 번만 결산합니다. 경과 시간은 활성 플레이 시간으로, 메뉴/일시정지 시간은 더하지 않습니다. 동굴 중단 시에는 기존 규칙대로 동굴 입구에서 이어 갑니다. 선택 도전 포기는 숲으로 나온 뒤 가능합니다. 선택 정예는 저장 후 재접속하면 다시 도전할 수 있으며, 동굴 내부 상태 자체를 새로 영속화하지 않습니다.

## 챕터 확장

`assets/data/expeditions/chapters/forest_1.json`은 계약, 임무 ID, 필수 임무 수, 봉인 비석 ID, 보스 레벨, 귀환 NPC를 지정합니다. 현재 실제 월드 어댑터는 숲 1장입니다. 후속 챕터는 새 데이터만 추가해 완성되는 것은 아니며 해당 월드의 임무·진입·비석·보스·귀환 배치를 연결하는 어댑터가 필요합니다. 없는 지역을 선택지로 노출하지 않습니다. `QuestRuntime.report()`, `EncounterRuntime._record_wave()/on_killed()`, `DungeonRuntime.complete()`, `Game.on_boss_defeated()`가 각각 실제 성공 시점에 진행을 알립니다.

필수 봉인은 봉인 단계에서 비석을 공격해 소환한 무리의 마지막 적을 처치해야 셉니다. 이전 주변 적이나 다른 무리 처치로 건너뛰지 않습니다. 단계 진입 시 비석 충전은 보충하되 살아 있는 무리는 지우지 않습니다. 지도는 별도 좌표를 복사하지 않고 실제 NPC·비석·정예·보스 노드를 읽습니다.

## 기술 추가

`assets/abilities/<id>/ability.json` 폴더 하나가 새 기술 하나입니다. `id`, `class`(`warrior`/`mage`), `name`, `desc`, `icon_skill`, `cost`, `cooldown`, `unlock_renown`, `behavior`를 둡니다. `icon_skill`은 같은 직업의 기존 그림 ID이며 새 그림을 넣을 때는 해당 자산 경로와 검수를 확장합니다. 새 기술은 명성 조건을 만족하면 자동으로 원정 풀에 합류합니다. 예시는 `emberFan`, `stormLance`, `steelWave`, `breakersCry`입니다.

`behavior`는 기존 `SkillDefs`의 `proj`, `beam`, `nova` 등 지원 행동의 필수 필드를 그대로 따릅니다. 색은 `[r,g,b]`, 피해는 기존 내부 단위/배율입니다. 새 행동 종류를 만들 때는 `Player`의 시전/판정·실제 3D 표시·아이콘·룬 호환 테스트까지 추가해야 합니다. 원본 추출물인 `skills.json`을 손으로 수정하지 않습니다. 지원 룬은 `assets/data/expeditions/runes/<id>.json`의 행동 유형과 modifier로 확장합니다. 룬은 하나씩만 소유하며 기술당 최대 2개, 재배치 시 기존 부착을 검증 후 변경합니다. 원래 기술에 이미 있는 효과라서 개선이 없는 룬은 제시하지 않습니다. 룬 보상에서 호환 룬이 부족하면 새 기술로 선택지를 채워 진행이 막히지 않게 합니다.

주 공격은 시작 선택 기술로 고정하고 비용을 0으로 하므로 첫 원정부터 사용할 수 있습니다. 전사 주 공격의 실제 명중에는 한 시전당 분노 3을 더 줍니다. 흡수 룬도 여러 갈래/폭발로 자원이 중복 생성되지 않도록 시전 ID별 한 번만 적용합니다. 범위 룬은 실제 판정과 조준 범위에, 갈래/관통/폭발은 실제 투사체에 전달합니다.

## 검수

- `tools/check.sh --only=expedition,expedition_integrity,quests,skills`: 실제 임무→소환 무리→보스→귀환, 사망, 저장 실패 복구, 선택지 재개, 지원 룬의 실제 투사체/흡수 검수.
- `tools/export_web.sh`와 로컬 서버를 띄운 뒤 `node tools/check_expedition.mjs --url=http://localhost:8882/index.html`: 세로/가로에서 실제 터치로 계약→월드 재생성→시작 기술→룬→임무 선택. 산출물은 루트 `build/expedition/browser` 또는 `--out`에 둡니다.
- `expedition_review=1&panel=expedition`은 이 검수용 읽기 전용 좌표/상태를 공개하며 게임 상태를 대신 조작하지 않습니다.
- 푸시 전 루트 `tools/ci.sh`를 실행합니다. 로컬 웹 빌드는 공개 배포가 아닙니다.

실제 전체 회차의 소요 시간과 난이도는 자동 상태 검수로 측정하지 않습니다. 10분~2시간 범위의 목표에 맞춘 체감 난이도·선택지 빈도는 실제 플레이를 통해 계속 조정합니다.
